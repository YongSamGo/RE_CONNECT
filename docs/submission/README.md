## 현재 확인한 일정과 범위

KISA 공지의 트랙 A는 자유주제로, 고령자 접근성을 포함한 사회문제 해결을 위한 안전한
소프트웨어 개발을 다룬다. 다시잇다의 트랙 A 선택은 [저장소 소개](../../README.md)에 따른다.
실제 팀의 접수 트랙·접수번호는 별도 증거가 필요하다.

| 항목 | 값 | 판정 |
| --- | --- | --- |
| 개발경연 기간 | 2026-10-06~2026-10-30 | 공개 공지에서 확인 |
| 내부 제출 목표 | 2026-10-29 | 구현 계획의 팀 내부 목표 |
| 최종 제출 마감 날짜·시각·시간대 | 미확인 | 개발경연 종료일만으로 추정하지 않음 |
| 산출물 제출 채널·접근 권한 | 미확인 | 참가 신청 구글폼을 산출물 제출처로 사용하지 않음 |
| 최신 트랙 A 미션·운영요강·양식 버전 | 미확인 | 공지 제목이나 첨부파일 이름만으로 확정하지 않음 |
| 파일명·확장자·분량·용량·영상 길이 | 미확인 | 최신 산출물 안내와 대조 필요 |

## 제출물 6종 준비 목록

아래 6종은 **구현 계획에 있는 내부 목록**이다. 주최 측이 요구하는 최종 목록과
동일하다고 판정하지 않았다. 공식 안내와 대조한 뒤 추가·제외·형식 변경을 기록한다.

| 제출물 | 준비 시 확인할 내용 | 공식 요건 대조 | 최종 파일·버전 |
| --- | --- | --- | --- |
| 시연 영상 | 핵심 여정·실패 처리·보안 통제, 재생·소리·화면 가독성 | 미확인 | 미정 |
| 개발기획서 | 대상 문제·범위·설계·구현 결과·미검증 구분 | 미확인 | 미정 |
| 발표자료 | 같은 릴리스의 기능·시험 근거·남은 한계 | 미확인 | 미정 |
| 개요서 | 공식 양식·필수 항목·분량 | 미확인 | 미정 |
| 소스코드 | 지정 SHA로 재현, 실행 안내, 비밀값·실제 사용자 자료 제외 | 미확인 | 미정 |
| 포스터 | 공식 크기·양식·필수 표기, 본문과 릴리스 일치 | 미확인 | 미정 |

실제 동의 OFF, 카카오 정상 로그인, 승인 공고 20건, EC2/GPU 품질·부하,
실기기·접근성, 운영 백업·복구 등은 별도 검증 대상이다. 문서·화면·자동 시험이
있다는 이유로 해당 운영 검증을 통과로 표현하지 않는다.

## 릴리스·증거 기록 양식

아래 양식을 제출 후보별로 복사한다. 확인되지 않은 값은 `미확인`으로 남긴다.
SHA·파일 해시를 적는 것만으로 인수 시험이나 제출 수신이 완료되는 것은 아니다.

| 항목 | 기록 |
| --- | --- |
| 확인일·확인자 | 미확인 |
| 최종 안내 제목·게시/개정일·원문 위치 | 미확인 |
| 트랙·미션·공식 양식 버전 | 미확인 |
| 공식 마감 시각·시간대 | 미확인 |
| 공식 제출처·제출 방식 | 미확인 |
| 릴리스 식별자·소스 커밋 SHA | 미확인 |
| 배포 이미지 digest·모델 revision | 미확인 |
| 제출물별 파일명·크기·SHA-256·릴리스 표기 | 미확인 |
| 같은 SHA의 CI·보안 검사·여정 시험 근거 | 미확인 |
| 영상과 실제 배포 버전의 일치 근거 | 미확인 |
| 남은 미검증·제출 판단 | 미확인 |
| 실제 업로드·수신·재다운로드/재생 근거 | 미확인 (#109에서 기록) |

수신증·팀원 개인정보·비밀 링크·미조치 취약점 보고서는 공개 문서에 넣지 않는다.
비공개 증거가 필요하면 `security-reports/`에 보관하고 공개 가능한 확인 결과만 남긴다.

위 기한은 팀 내부의 확인 목표이며 대회의 공식 제출 마감을 뜻하지 않는다.
담당자는 최신 운영요강·팀별 안내를 대조하고, 자료로 확정되지 않으면 주최 측에 직접 확인한다.
확인 결과·근거·개정일을 기록하기 전에는 아래 항목을 완료로 바꾸지 않는다.

- [ ] 최신 주최 측 안내에서 트랙 A 미션·양식 버전을 확인한다.
- [ ] 최종 제출 마감의 날짜·시각·시간대와 제출 채널을 확인한다.
- [ ] 공식 제출물 목록·파일 형식·용량·분량을 위 6종과 대조한다.
- [ ] 원문 위치·개정일·확인일을 기록하고 서로 다른 공지는 차이를 해소한다.
- [ ] 팀의 범위·담당·일정 확인(#4)과 제출 계획을 대조한다.

위 항목이 미확인인 동안 #106은 통과로 표시하지 않는다. #107의 제출 문서 작성은
계획에 명시된 선행 작업과 공식 요건을 확인한 뒤 진행한다.
릴리스 고정은 #108, 실제 제출과 수신 확인은 #109에서 별도로 수행한다.
