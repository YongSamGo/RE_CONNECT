# 운영 절차 (#97 W12-08)

배포한 서비스를 되돌리고, 장애·키·권한·비용을 다루고, 다음 담당에게 넘기는 절차다.
배포 자체는 [릴리스와 EC2 배포](../../infra/deploy/README.md), 복원은 [백업·복원](../security/backup-restore.md)이 기준이다.
이 폴더는 그 문서들을 실행 순서로 묶고 빠진 판단 기준을 채운다.

| 문서 | 내용 |
| --- | --- |
| [rollback.md](rollback.md) | 이전 릴리스로 되돌리기. DB downgrade 금지, `rollback-check` 판정, 모델 재준비, 마이그레이션 작성 규칙 |
| [runbook.md](runbook.md) | 장애별 첫 조치, 키·비밀값 교체, 운영자·팀 권한 회수, 비용과 자원 종료 |
| [handover.md](handover.md) | 담당·문의 경로 표(확정 전 빈칸), 공개 정책 점검표, 계획 8장 형식의 인계 기록 |

## 검증 상태 (2026-10-29)

- `rollback-check` 판정 도구는 단위 시험(`infra/release/tests`)만 통과했다.
- 실제 EC2에서 새 환경 실행·복원·롤백을 재현하지 않았다. 아직 릴리스와 운영 이미지가 없다.
  재현과 증거는 #104(장애·배포·롤백 시험)에서 같은 릴리스로 남긴다.
- 담당자·문의처·처리방침의 실제 값은 정해지지 않았다(#9). 정해지기 전에는 공개하지 않는다.

## 기록 규칙

- 운영 중 남기는 증거는 건수·성공 여부·시각·릴리스 태그만 적는다. 식별자·원문·비밀값·AWS 계정 ID는 적지 않는다.
- 공개 저장소다. 조치하지 않은 취약점의 위치·재현 방법은 커밋·이슈·PR에 쓰지 않고 `security-reports/`에만 둔다.
