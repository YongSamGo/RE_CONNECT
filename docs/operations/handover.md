# 담당·공개 정책·인계 (#97 W12-08)

## 1. 담당과 문의 경로

**미정** 칸이 하나라도 있으면 공개 운영을 시작하지 않는다. 사람 이름 대신 역할로 적어도 되지만, 실제로 연락되는 경로여야 한다.
공개 저장소이므로 개인 전화번호·개인 메일 대신 공식 문의 경로를 적는다.

| 역할 | 하는 일 | 담당 | 문의 경로 | 정하는 곳 |
| --- | --- | --- | --- | --- |
| 운영 책임자(운영 주체) | 공개·중단·복원 손실 감수 결정, 이용자 안내 | 미정 | 미정 | #9 |
| 개인정보 보호책임자 | 권리행사 접수, 사고 판단·신고 | 미정 | 미정 | #9 |
| 이용자 문의 접수 | 서비스 문의·신고 응대 | 미정 | 미정 | #9 |
| 비용·자원 종료 담당 | EC2/RDS 중지 확인, RDS 자동 재시작 전 조치, 자원 삭제 | 미정 | — | [AWS 점검표](../progress/aws-launch-20261029.md) |
| 복구 키 보관자(2명 이상) | 암호화 키 분리 사본 보관·꺼낸 기록 | 미정 | — | #25 |
| 인증서·도메인 담당 | 도메인 갱신, 인증서 자동 갱신 확인 | 미정 | — | #91 |
| 릴리스 승인자 | `release` 환경 승인(자기 승인 금지) | 저장소 설정 | — | [deploy README](../../infra/deploy/README.md) 4절 |
| 배포·장애 대응 | [rollback](rollback.md)·[runbook](runbook.md) 실행 | C · 백엔드·보안 | — | 이 문서 |

## 2. 공개 정책 점검표

공개 전에 아래가 모두 실제 값으로 채워져 있어야 한다. 하나라도 없으면 해당 기능을 켜지 않는다.

- [ ] 운영 주체 정식 명칭, 개인정보 보호책임자·접수 부서와 연락처, 시행일 ([처리방침 근거](../privacy-notices-basis.md))
- [ ] 전체 개인정보 처리방침과 이용약관의 공개 위치(서비스 화면에서 찾을 수 있는 경로)
- [ ] AI 처리·저장 안내문 본문 승인과 버전. 승인 전에는 `AI_NOTICE_VERSION`·`STORAGE_NOTICE_VERSION`을 설정하지 않는다.
      미설정이면 동의 수락은 503이고 처리는 403 `CONSENT_REQUIRED`다([동의](../security/consents.md))
- [ ] 처리 리전·위탁·보관기간이 실제 배포 구성과 같은지 확인
- [ ] 카카오 redirect URI와 `PUBLIC_ORIGIN`이 실제 도메인과 같은지 확인
- [ ] 장애·점검 때 이용자에게 보여 줄 안내 문구와 게시 위치
