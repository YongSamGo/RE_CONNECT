# 이용약관·개인정보 안내 검토 초안

기준일: 2026-10-28. 운영 검토용 초안이며 게시·실제 동의 수집에 사용하지 않는다. 법률 자문 또는 적합성 판정이 아니다. 확정되지 않은 항목은 대괄호로 남긴다.

## 근거와 범위

- [개인정보 보호법 (2026-09-11 시행)](https://www.law.go.kr/LSW/lsInfoP.do?efYd=20260911&lsiSeq=283839): 특히 제15조 수집·이용 및 동의 고지, 제22조 동의 방법, 제23조 민감정보, 제30조 처리방침, 제35~37조 정보주체 권리를 실제 처리에 맞춰 검토한다.
- [개인정보보호위원회 2025 개인정보 처리방침 작성지침](https://www.privacy.go.kr/front/bbs/bbsView.do?bbsNo=BBSMSTR_000000000049&bbscttNo=20806). 개인정보 포털에는 2026년 지침도 검색되므로 게시 전 최신 원문을 확보해 재검토한다.
- [약관의 규제에 관한 법률 제3조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029708921): 약관 작성·명시·설명 조건을 서비스 형태에 맞춰 검토한다.
- 이 문서는 약관과 처리방침, 목적별 동의를 분리한다. 개인정보 처리의 법적 근거는 항목과 실제 맥락별로 확인하며 모든 처리가 동의에 근거한다고 가정하지 않는다.

## 현재 코드와 남은 확인

| 구분 | 확인한 구현·화면 | 확정 전 확인 |
| --- | --- | --- |

| 화면 설정 | 큰 글씨 선택만 `reconnect-large-text` 키에 기기별로 저장한다. 입력 내용은 이 키에 넣지 않는다. | 저장 기간·이용자가 지우는 방법과 브라우저 저장 기술 고지 필요성을 확인한다. |
| AI·음성 | 대화·프로필과 전사 등은 체험 서버 경로가 있다. 원본 음성은 서버 처리 중 메모리에서 다루며 전사 결과는 체험 수명에 결합된다고 기록되어 있다. [전사](../data/transcriptions.md) | 실제 입력 항목, AI/STT/TTS 처리 경로·필터 한계, 접속 로그·운영 인프라, 유휴·절대 만료와 백업까지 확인한다. 건강 등 민감정보가 입력될 가능성과 처리 근거·대응을 검토한다. |
| 회원 저장 | 저장 안내와 동의는 AI 동의와 분리되어 있고, 확정 운영 안내가 없으면 새 로그인·동의 진입은 제한된다. [회원 연결](../../frontend/src/features/account/SERVER.md) | 카카오에서 받는 정확한 항목, 목적·보유 기간·거부 시 영향, AWS 위탁/국외 이전 여부와 계약, 운영 삭제·복구 절차를 확인한다. |
| 삭제·철회 | 화면은 저장 철회, AI 철회, 탈퇴를 구분한다. [삭제 설계](../data/member-deletion.md) | 삭제 이력 30일 안내가 실제 운영 백업·복원과 일치하는지, 장애·재시도·법정 보관 예외를 확인한다. |
| 공고 | 공개 검색어는 요청 URL에 포함될 수 있다. [공개 검색](../../frontend/src/features/public-opportunities/README.md) | 프록시·서버 접근 로그에 검색어가 기록되는지 및 외부 공식 사이트로 이동할 때의 처리·고지를 확인한다. |

오래된 [동의 기록](../security/consents.md)에는 회원 인증 미연결로 기술된 부분이 있어 최근 회원 연결 문서·코드와 시점이 다르다. 실제 운영 처리로 단정하지 말고 재대조한다.

## 목적별 동의 안내 — 미게시

운영 담당자가 항목별 법적 근거를 확인한 뒤, 동의가 필요한 경우 별도 화면에 아래를 기재한다. 각 항목의 필수·선택 여부와 거부 시 실제 제한을 확정 전 추측하지 않는다.

- AI 처리: 목적 [ ], 항목 [ ], 보유·이용 기간 [ ], 거부할 권리와 영향 [ ], 철회 방법 [ ], 안내문 버전 [ ]. 음성 처리와 민감정보를 별도로 어떻게 다룰지 확인한다.
- 회원 저장: 목적 [ ], 저장 항목 [ ], 보유·이용 기간 [ ], 거부할 권리와 영향 [ ], 철회·삭제 방법 [ ], 안내문 버전 [ ]. 로그인과 저장은 별도 행동이다.
- 제3자 제공·국외 이전 등 별도 고지 또는 동의가 필요한 처리는 실제 계약·법적 근거가 확인된 뒤 해당 내용과 별도 선택을 설계한다.

## 이용약관 검토 골격 — 미게시

[운영 주체와 연락처], 서비스 제공 범위와 실제 신청처의 역할, 회원과 비회원의 이용 범위, 이용자의 의무, 서비스 변경·중단 및 사전 고지, 계약 종료, 책임과 분쟁 해결, 약관 변경·시행일을 운영 정책과 함께 작성한다. 일방적인 면책·변경 권한이나 이용자 권리 포기를 임의로 넣지 않는다. 약관 동의는 개인정보 목적별 동의와 섞지 않는다.

## 운영 담당자 확인 질문

1. 실제 운영 주체·개인정보 보호책임자와 문의처는 누구인가?
2. 제공 기능별 수집 항목, 법적 근거, 보관 기간과 이용자가 거부했을 때의 실제 제한은 무엇인가?
3. AWS·카카오 등 공급자와의 계약상 역할, 처리 위치, 위탁·국외 이전 여부는 무엇인가?
4. 로그·백업·삭제 이력의 보존과 복구 후 삭제 재적용은 실제 운영에서 어떻게 검증하는가?
5. 민감정보가 포함된 발화·전사·프로필을 어떻게 차단하거나 적법하게 처리할 것인가?
6. 게시 책임자와 법률 검토자, 안내문 버전·변경 고지·동의 증거 관리자는 누구인가?

게시 및 실제 동의 활성화는 위 사실과 동작을 확인하고 운영 책임자와 필요한 법률 검토를 마친 후 수행한다.
