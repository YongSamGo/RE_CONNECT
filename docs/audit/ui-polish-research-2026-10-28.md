# 다시잇다 UI 완성도 개선 조사

조사일: 2026-10-28. 현재 파란색 팔레트의 실행 화면과 소스를 기준으로 조사했다. 아래 내용은 화면 관찰과 공식 디자인 자료를 바탕으로 한 디자인 제안이며, 사용자 검증 결과나 객관적 미감 점수가 아니다.

## 범위와 확인 방법

로컬 Chromium에서 홈의 1440×1000·390×844 화면과 공고 탐색의 1440×1000 초기 상태를 캡처해 관찰했다. 캡처는 `security-reports/ui-research-20261028/`에 보관했다. 실제 회원·운영 성공 상태나 전체 서비스 사용성을 검증하지 않았다. 조사 자체에서는 테스트를 실행하지 않았다. 이후 요청한 지도·서체 수정의 검증은 별도다.

상용 서비스 비교는 토스가 공개한 디자인 시스템과 라이팅 원칙, 에어비앤비 공개 페이지의 정보 구조를 사용했다. IBM 공식 디자인 언어와 중장년 대상 서울시50플러스 일자리몽땅을 보완 자료로 읽었다. 토스 한국 홈·원티드·당근은 접근 또는 렌더링에 실패해 현재 시각 디자인을 평가한 사례에서 제외했다. 텍스트 추출만 가능한 페이지의 픽셀 배치나 모든 인터랙션을 관찰했다고 주장하지 않는다.

## 판단

현재의 간결함과 파란색은 유지할 가치가 있다. 가장 큰 문제는 빈 영상 영역의 비례, 제목과 행동의 거리, 서체 굵기의 불일치, 큰 프레임 안에 떠 있는 작은 검색 폼이다. 여기에 장식을 추가하는 것보다 시선의 순서와 정보의 역할을 명확히 하는 작업이 먼저다.

홈은 영상이 없는데도 16:9 비율의 큰 영역을 유지하며 제목은 왼쪽 위, 행동은 오른쪽 아래에 있다. 영상이 들어오면 빈 공간 문제는 줄겠지만 영상 위 글자와 조작부의 가독성, 버튼을 발견하는 순서는 다시 확인해야 한다. 모바일에서는 짧은 카드 아래에 큰 빈 화면이 남아 정보가 로딩 중인 것처럼 보일 가능성도 있다. 이는 현재 화면을 보고 내린 해석이며 실제 사용자에게 확인할 가설이다.

## 적용 우선순위

### 1. 실제 서체 굵기와 타이포그래피

조사 당시 S-Core Dream은 200·300·400만 등록됐는데 버튼과 제목에는 500~700이 요청돼 있었다. 공급하지 않은 굵기는 브라우저 매칭·합성 결과에 의존할 수 있다. 실제 파일을 등록하고 본문 400, 레이블·보조 행동 500, 제목 600, 주요 행동 600~700의 역할을 검토한다. 이것은 프로젝트용 제안이다.

제작사는 [에스코어 드림을 제목용 글꼴이며 9가지 두께를 제공하는 폰트](https://s-core.co.kr/company/font/)라고 소개한다. 따라서 모든 글자를 매우 얇게 쓰는 방식은 피하고 긴 본문은 실제 화면과 이용자 반응으로 읽기 편한지 확인한다. 글꼴 수를 늘리는 것보다 같은 글꼴 안의 역할을 다듬는 것이 우선이다.

### 2. 홈의 영상·문구·버튼을 하나의 구성으로 완성

영상 중심 방향을 유지하려면 실제 영상과 포스터를 먼저 준비하고 주요 인물·자막·글자·재생 조작·CTA가 부딪히지 않는 안전 영역을 정한다. 영상이 없을 때의 정적 상태도 별도 완성 화면으로 설계한다. 임시 플레이어나 가짜 서비스 결과를 넣지 않는다.

제목과 설명의 왼쪽 정렬, 본문 행간, 버튼 두 개의 같은 글자 크기는 유지한다. 제목과 버튼을 가까이 묶은 안과 현재의 영상 위 배치 안을 비교 시안으로 검토할 수 있다. 지금 레이아웃을 바꾸기로 확정했다는 뜻은 아니다. 삭제한 하단 세 단계 안내는 복원하지 않는다.

### 3. 공고 탐색을 큰 지도와 작은 폼의 나열에서 정리된 작업 화면으로

지도는 강점이다. 지역 선택, 검색 조건, 적용 조건, 결과가 연결돼 보이도록 제목과 정렬선을 맞춘다. 폼의 그림자와 카드 안팎의 모서리를 줄이고 지도와 폼의 비중을 실제 정보량에 맞춘다. 텍스트가 들어갈 공간을 프레임 비율에 맞춰 억지로 압축하지 않는다.

선택한 지역과 검색 결과 범위가 눈에 보이도록 하고, 시각적으로 선택 상태와 현재 보고 있는 지도 탭을 구분한다. 공고 목록은 제목·기관·지역·마감·보수 순서와 값의 시작 위치를 일정하게 맞춘다. 작은 지도 이름을 무조건 키우기보다 위치 조정이나 별도 선택 목록도 필요에 따라 검토한다.

### 4. 버튼·입력·카드의 규칙을 통일

주요 버튼, 보조 버튼, 링크의 색·굵기·테두리 역할을 정한다. 두 홈 버튼의 글자 크기는 같게 유지해도 배경과 테두리로 우선순위를 표현할 수 있다. 모서리와 그림자는 크기·역할별 소수의 값으로 제한하고 공통 토큰으로 관리한다. 예: 입력 8px, 패널 16px, 영상 24px를 출발점으로 시안에서 비교한다. 숫자 자체가 상용 완성도를 보증하지 않는다.

hover·키보드 초점·선택·비활성·요청 중·실패 상태를 함께 디자인한다. 기존 자동 검사로 화면 잘림을 찾되, 가로 넘침 0건을 디자인 완성 판정으로 사용하지 않는다.

### 5. 서비스가 운영되는 방식까지 화면에 드러내기

도움말, 문의, 실제 신청처, 개인정보 처리방침 등의 접근 경로를 검토한다. 운영 주체와 문의처가 미정이면 임의로 꾸며 넣지 않는다. 첫 화면을 정책 문장으로 채우기보다 실제 행동 직전에 필요한 정보를 읽게 한다. 실제 기능의 미연결 상태는 정확히 알린다.

## 다음 작업 단위

1. 현재 파란색·기존 구조·동일한 CTA 글자 크기·글자만 확대하는 모드는 유지한다.
2. 서체·간격·버튼·입력의 작은 규칙표를 먼저 만든다.
3. 홈과 공고 탐색만 PC·모바일 비교 시안으로 완성한다. 영상 전/후 상태를 모두 포함한다.
4. 사용자가 선택한 안을 구현하고 나머지 화면에 공통 규칙을 적용한다.
5. 브라우저 기준 이미지 외에 키보드·실기기·200% 확대·스크린리더·대상 이용자의 과업 수행을 확인한다.

우선 추천은 '차분한 파란색, 더 단단한 글자, 정리된 지도 탐색, 실제 콘텐츠가 있는 첫 화면'이다. 이미지·애니메이션·새 UI 패키지를 늘리는 작업은 이 구성이 정해진 뒤 필요성을 판단한다.

## 조사 후 반영한 작은 수정

추가 요청에 따라 9가지 에스코어 드림 원본을 등록하고 홈 설명의 200 굵기를 400으로 조정했다. 지도는 화성시 작은 부속 섬의 화면 표시를 생략하고 제물포구·미추홀구·남동구의 이름 배치를 조정했다. 검색 지역과 행정구역 데이터 자체는 바꾸지 않았다. 큰 레이아웃 개편과 추가 시안 구현은 아직 수행하지 않았다.
