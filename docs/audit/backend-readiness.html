첫 화면과 운영자 기능은 막힌 이유가 다르다. 첫 화면의 미리보기는 프론트엔드 연결 문제다. 운영자 화면은 대응할 백엔드 API가 없어 공고 검수와 신고를 처리하지 못한다. 운영 설정이 빠지면 GET /me에서도 세션 초기화가 막힐 수 있다.

  • 삭제 서비스는 있지만 production용 삭제 이력 저장소는 연결되지 않았다. POSIX 파일 구현은 개발 환경에서만 쓸 수 있다.

3. F01~F11 백엔드 체크리스트

각 항목의 코드 경로와 조건을 확인했지만 개별 시험 로그는 대조하지 않았다. CI 통합 결과만으로 모든 세부 조건이나 외부 서비스의 성공을 확인할 수는 없다.

구현 여부와 검증 수준은 따로 표시했다. API 항목에서는 메서드·입력·서비스 연결을, 서비스 항목에서는 업무 규칙을 확인한다. 저장은 SQL/Redis, 외부 연동은 모델·카카오·공공 API 어댑터를 살폈다. 통제 항목은 소유권·동의·버전·한도, 흐름 항목은 서버 안의 단계 연결을 확인한다. 외부 연동이 필요 없는 기능은 집계하지 않았다.

구현 상태는 완료·부분·미구현·미확인·해당 없음으로, 검증 수준은 E2E·통합·단위·정적 확인·미검증·검증 불가로 표시했다. 통합 판정은 최신 CI에서 실제 DB·Redis와 서버를 시험한 범위에 한정된다. 모델·카카오·공공 API의 Mock은 실제 연동으로 세지 않았다. 운영 환경 검증 여부는 별도 표에 적었다.

8. 남은 백엔드 작업의 범위와 크기

작업 크기는 기능 개수가 아니라 변경 범위와 선행조건으로 나눴다. B01~B07은 코드·운영 구현, V01~V03은 검증·외부 준비 작업이다. 이번에는 테스트를 실행하거나 제품 기능을 구현하지 않았다.

S: 한 정책·좁은 변경. M: 한 모듈의 API·업무·회귀. L: 여러 엔드포인트·트랜잭션·권한/경합을 연결하는 변경. XL: 장애·독립 저장·복원 등 운영 설계가 선행되는 변경. 크기는 상대적 복잡도이며 인일·납기나 코드 줄 수가 아니다. 담당 가용시간·실제 계정·배포 상태 미확인으로 확정 시간·총합 점수는 제시하지 않는다. S/M/L을 숫자로 합산하지 않는다.

미완료 체크 항목은 B 작업에 연결했다. 기능을 수정하면 정상 입력과 관련된 공격·오류 경계를 확인한다. 계정이나 환경이 없어 실행할 수 없는 항목은 검증 불가로 남긴다. 원인을 모른 채 같은 시험을 반복하지 않는다. 같은 SHA에서 실제 여정을 실행해야 E2E 완료로 표시한다.

이 문서 생성이 종료 범위다. 미완료 기능 구현·리팩터링·커밋·push·이슈/PR 수정은 시작하지 않는다. 원래 전체 시스템 보고서는 system-readiness.html에서 함께 볼 수 있다.
