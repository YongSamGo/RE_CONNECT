첫 단계에서 막힌다: UX02 → 실제 체험 생성. 시작 → /consent → /conversation은 메모리 미리보기다. 현재 화면에서는 서버의 /journeys/:journeyId/... 흐름을 시작할 수 없다. 운영 안내문을 게시하고 실제 체험 화면까지 연결해야 한다.
  • PR #228(cfc1e4a)에 회원·음성·체험·수집 코드가 포함됐다.
  • 운영자 화면은 관리 요청을 보내지만 대응 서버 경로가 없어 공고 검수·공개와 신고 요청을 처리하지 못한다.

우선 순서: 실제 체험 시작을 연결한다. 검수 공고를 공급하고 핵심 텍스트 여정을 시연한 뒤 회원 삭제와 운영 경계를 마무리한다.

기능별 완료 여부는 66개 필수 세부 항목으로 판정했다. 하나라도 부분 완료이거나 미확인이면 해당 기능은 완료로 세지 않았다. E2E는 브라우저 입력부터 최종 결과까지 실행한 기록이 있어야 인정한다. 현재 막힌 기능은 F01(진입), F05(검수 공고 공급), F09(운영 삭제), F10(검수·신고)이다. 선행 기능이 막아 후속 흐름을 실행할 수 없는 경우에는 미구현 항목으로 중복 집계하지 않았다.

2. 시스템은 어떻게 움직이는가

그림의 실선은 코드에서 확인한 호출이고, 점선과 주석은 목표 구조나 아직 연결되지 않은 진입 경로다. 구성요소가 있다는 사실만으로 운영에서 실행된다고 볼 수는 없다. Context에는 사용자·운영자와 외부 기관을, Container에는 브라우저·API·저장소·모델·음성을 표시했다. Component는 Router → Service → Repository/Adapter 순으로 정리했다.

시작→UX02 동의·체험 생성 ✕ 최초 단절→대화·전사→프로필 확정·역할→검수한 실제 공고 필요→추천·자격→지원서 수정·승인→공식 안내 이동

그림의 박스는 코드 경로를 보여 줄 뿐 사용자가 여정을 끝까지 마칠 수 있다는 뜻은 아니다. 지원동기는 직접 작성해야 한다. 공식 안내 페이지에 도착한 것과 외부 기관에 신청을 마친 것은 서로 다른 단계다.

4. 기능별 체크리스트

기능별 항목은 코드에서 경로와 조건을 확인했다. 개별 실행 로그는 대조하지 않았다. 계층 표의 단위·통합 시험 결과만으로 모든 세부 조건을 확인했다고 보지는 않았다.

구현은 코드와 연결, 검증은 실행 증거다. E2E 열의 구현은 해당 기능의 하위 사용자 흐름 연결이며 홈부터 전체 여정 성공을 뜻하지 않는다. 선행 차단은 별도로 기록한다.

구현 상태는 완료·부분·미구현·미확인·해당 없음으로 표시한다. 검증 수준은 E2E·통합·단위·정적 확인·미검증·검증 불가로 나눈다. 해당 없음은 집계에서 제외한다. 이번 감사의 6개 계층은 모든 기능에 적용했다. 외부 호출 코드가 있어도 계정이나 환경이 없어 실행할 수 없다면 운영 검증은 불가다.

결정선택지와 장단점권장안
제출 시연·공개 범위비회원 텍스트 중심은 외부 인증 의존이 적음. 회원 저장은 가치가 크지만 삭제·복구 게이트 필요.비회원 전체 여정 우선. 회원 공개는 실제 로그인·삭제·복구 증거 후 결정. 시연 데이터도 출처·검수 상태 표시.
지원동기 자동화수동 입력은 사실 오생성 위험이 작음. 자동 보조는 편의성이 크지만 추가 방어·품질 검증 필요.제출 직전에는 직접 작성 범위를 명시적으로 승인하고 UI 설명 일치. 원래 F08 전체 완료로 표시하지 않음.
