# AWS를 처음 준비할 때 (#6·#157)

2026-10-29 기준 첫 배포(`v0.1.0-rc.1`)를 마쳤고, 운영 사이트는 CPU 서버로 동작 중이다. GPU 운영 전환은 진행 중이며 가동 시간·비용 상한·서버 유지 기한은 결정이 남아 있다. 세부 기록은 비공개 `security-reports/aws-production.md`에 있다. [이슈 실행 순서·시험 결과](../progress/triage-20261029.md)를 함께 본다.

## 10/29 배포 후 상태

- 기존 CLI 2.39.0과 두 프로필의 비루트 인증 성공. 재설치·계정 재생성은 필요 없다.
- 운영 EC2(`t3.medium`)와 RDS는 가동 중이다. 사이트는 화면·공고 API만 동작하며, AI·음성은 "준비 안 됨"으로 응답한다.
- 개발 서버는 JBR-313이 GPU 실측용으로 `g4dn.xlarge`로 변경해 사용했고, 10/29에 중지했다.
- RDS는 가동 중이다. 다시 중지하면 7일 뒤 자동으로 켜지므로 중지 시점에 재시작 일정을 확인한다.
- 서울 G/VT 온디맨드 한도 **8 vCPU** 증설은 10/29 승인됐다. 이 한도에서 `g4dn.xlarge`(4 vCPU)는 최대 2대, `g4dn.2xlarge`(8 vCPU)는 최대 1대를 동시에 켤 수 있다. 두 유형은 같은 한도를 공유하며 실제 가용 용량은 시작 전에 확인해야 한다.

## 1. 계정과 리전: 누가 결제하고 어디에 둘까

AWS 계정은 결제와 자원 소유의 단위다. 리전은 서버를 둘 지역이다. 서울의 코드는 `ap-northeast-2`다. 한국 사용자 대상 서비스의 운영 리전은 서울로 확정했다. 가격이 가장 싸다는 뜻은 아니다. 가격·GPU 제공 여부·할당량은 선택한 리전에서 확인한다.

기존 두 프로필의 인증과 적용 GPU 한도는 확인했다. 루트 MFA·팀원별 권한은 확인 필요다. GPU 실측은 개발 서버에서 마쳤으며 운영 GPU 전환 검증은 남아 있다.

## 2. EC2와 GPU: 어떤 컴퓨터를 빌릴까

EC2는 AWS에서 빌리는 컴퓨터다. 인스턴스는 실제 실행하는 한 대이며 `g4dn.xlarge`(NVIDIA T4) 같은 이름은 성능 조합이다.

프로젝트는 계획상 대화·음성 인식·읽어주기 모델을 서버 안에서 실행한다. 웹 서버의 CPU·RAM 외에 AI 계산용 GPU와 GPU 전용 메모리 VRAM이 필요하다. 일반 RAM과 VRAM은 다른 공간이다.

운영 GPU 전환 유형은 `g4dn.xlarge`(NVIDIA T4)로 결정했다. JBR-313이 같은 유형에서 모델 실측을 마쳤다(#34, PR #276). 운영 전환 후 사전 검사와 실제 서비스 연결을 확인해야 한다. 코드 시험 통과는 GPU 성능 검증을 대신하지 않는다.

## 3. GPU 할당량: 그 컴퓨터를 켤 권한이 있을까

할당량은 계정·리전별 사용 한도다. 잔액이나 무료 이용권이 아니다. 결제수단이 있어도 한도가 부족하면 시작되지 않는다.

G/VT On-Demand 한도는 GPU 개수가 아니라 vCPU 기준이다. 후보의 vCPU 수와 승인 한도를 비교하고 다른 GPU 인스턴스가 이미 쓰는 양도 확인한다. 한도가 충분해도 실제 장비 용량이 부족할 수 있다.

준비 도구는 승인 한도만 읽는다. 부족하면 #157에서 계정 담당자가 증설 요청·승인을 추적한다. 미승인 상태를 서버 확보 완료로 기록하지 않는다.

## 4. 예산과 가동시간: 얼마까지, 언제 켤까

비용 상한은 팀이 이번 시험/운영에 지출하기로 합의한 총 금액이다. 월 예산인지 제출일까지의 총 예산인지 기간도 정한다. AWS가 그 금액에서 모든 사용을 자동 중단해준다는 뜻은 아니다.

1. 크레딧·지원금 유무와 본인 부담 가능한 총 금액을 확인한다.
2. 선택 리전·서버 후보의 최신 단가를 조회한다.
3. 시험일·하루 가동시간을 정해 예상 실행시간을 계산한다.
4. EC2 외에 DB(RDS)·디스크(EBS)·백업·공인 IPv4·전송·삭제 이력 S3 비용을 합산한다.
5. 총 예산 안에 들어오는지 확인한 뒤 생성한다. 단가 확인 전 월 비용을 단정하지 않는다.

처음에는 On-Demand로 필요한 시간만 켜고 담당자가 종료를 확인하는 안을 제안한다. 장기 약정이나 중단 가능한 Spot은 첫 실행 검증 이후 판단한다. EC2 중지 후에도 디스크·일부 IP 등에 비용이 붙을 수 있다. 별도 RDS가 EC2와 함께 자동 중지되는 것으로 가정하지 않는다.

AWS Budgets는 지출/예상 지출 알림을 제공한다. 알림과 자동 종료 구현은 구분한다. 이번 도구는 비용·종료 설정을 변경하지 않는다.

## 5. 팀 접속: 누가 무엇을 할 수 있을까

AWS 콘솔에서 자원을 관리하는 권한과 서버 안에서 프로그램을 실행하는 권한을 나눠 생각한다.

최초 계정 이메일로 접속하는 루트에는 MFA를 적용한다. 일상 개발에는 개인별 역할/작업 계정을 사용하고 루트 비밀번호·장기 키를 공유하지 않는다. IAM Identity Center의 개인별 임시 접근을 우선 검토한다.

서버 접속은 Session Manager를 사용한다. 인터넷에 SSH 포트를 열고 개인키를 나누는 작업을 줄일 수 있지만 실제 역할·에이전트·네트워크 준비가 필요하다. Session Manager로 운영 서버 접속을 확인했다.

비밀번호·MFA 코드·액세스 키·개인키·카드번호를 채팅이나 공개 이슈에 보내지 않는다. 결정에 필요한 것은 계정 준비 여부·리전·예산·팀원별 필요한 작업 범위다.

## 6. 도메인과 HTTPS

Route 53으로 도메인을 등록했고 자동 갱신이 켜져 있다. Let's Encrypt 인증서를 DNS-01 방식으로 발급했으며 서버의 자동 갱신 타이머가 켜져 있다. CAA 레코드도 설정했다.

인증서 발급 때 만료 알림 이메일은 등록하지 않았다. 자동 갱신 타이머가 실제로 실행돼 갱신에 성공하는지 사람이 확인해야 한다.
