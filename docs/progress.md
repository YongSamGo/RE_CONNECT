## 기록 방법

작업 상태는 `미착수 → 진행 → 검토 → 통과`, 선행 자료나 외부 준비가 없으면 `차단`으로 적는다. 차단 해제 후에는 진행 또는 검토로 돌아간다. GitHub의 open/closed를 작업 상태로 그대로 옮기지 않는다. 증거를 조회하지 못한 경우에는 상태를 추측하지 않고 `미확인`으로 표시한다.

작업별로 아래 양식을 복사해 `docs/progress/`에 기록한다. 프론트엔드 상세 기록처럼 기존 파일이 있으면 그 파일을 연결하고 같은 결과를 중복 관리하지 않는다.

| 항목 | 기록할 내용 |
| --- | --- |
| 작업 | 이슈 번호·W ID·주담당 A/B/C·협력 담당 |
| 상태 / 확인일 | 상태·확인 시각(KST)·확인자 |
| 구현 단계 | 코드 작성 / 계약 예제 연결 / 실제 API 연동 / 배포 검증을 각각 완료·미검증·해당 없음으로 표시 |
| 버전·환경 | commit SHA·PR·CI run URL, 실행 환경·브라우저·기기, 모델·프롬프트·공고 버전 |
| 검증 | 사례 ID·기대 결과·실제 결과·통과/실패/미실행·재시험 결과 |
| 완료 증거 | 공개 가능한 결과 요약과 증거 링크. CI 통과는 실제 기기·인증·복구 시험을 대신하지 않음 |
| 남은 범위 | 미구현·미검증 항목과 해당 이슈, 후속 담당 |
| 차단 | 원인·영향받는 작업/게이트·해제 조건·해결 담당·다음 확인 시각 |
| 실제 시간 | 시작·종료(KST)·휴식/대기 제외 여부·실제 작업 분·작성자. 모르면 미기록 |
| 일정 변경 | 기존 목표·변경 제안·근거·영향·결정자·결정일. 합의 전에는 제안으로 표시 |

실제 시간을 추정 견적이나 Git 커밋 간격으로 채우지 않는다. 과거 기록이 없으면 `미기록`으로 두고 이후 작업부터 기록한다. 팀원의 가용시간과 일정 변경은 확인받은 값만 확정한다.

## 통합·공개 게이트

목표일은 구현 계획의 기존 **2026년 목표**다. 지났거나 가까워졌다고 통과 또는 일정 변경으로 간주하지 않는다. 아래 현재 판정은 이 문서 작성 시 필요한 전체 증거를 확인하지 못했다는 뜻이다.

G2를 **첫 통합 게이트**로 사용한다. 공개 배포 판단은 G1~G4의 필수 기준, #97 운영 인계, #105 릴리스 판정의 증거를 함께 검토한다. G2 통과만으로 회원 저장·운영자·복구까지 공개 승인하지 않는다. 대회 형식·제출 채널·최종 마감은 #106에서 별도 확인하며 이 문서가 최신 공지 확인을 대신하지 않는다.

게이트마다 `판정일·판정자·릴리스 SHA·증거 링크·실패/미실행 항목·재검증일`을 기록한다. 실패/미실행이 있으면 보완 이슈와 담당을 연결하고 완료로 올리지 않는다. 구체적인 재검증일이 아직 합의되지 않았으면 `미정 — 담당자 확인 필요`로 남긴다.

## 공개 기록과 보관

가상 사례 ID와 결과 요약만 공개한다. 사용자 본문·운영 음성·인증 코드·토큰·계정 식별자·키는 기록하지 않는다. 보안 진단 보고서와 도구 출력은 저장소 지침대로 `security-reports/`에만 보관하며 커밋하지 않는다. 미조치 취약점의 위치·재현 절차를 이 문서에 넣지 않는다.

## 목록 갱신

[조회 도구 안내](../tools/README.md)를 따라 이슈·PR을 다시 조회한다. 자동 목록은 작업 상태·실제 시간·검증 결과를 수정하지 않는다. 목록 변경 후에는 기존 PR 본문과 스택 PR의 대상 브랜치, 실제 선행 증거를 사람이 확인한다.
