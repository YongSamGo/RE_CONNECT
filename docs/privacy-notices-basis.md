# AI 처리 상세 안내 작성 근거

작성 기준일: 2026-10-28.

## 적용 범위

`/consent`의 이용 목적·처리 항목·보관 및 삭제 상세 안내에 사용하는 실제 서비스용 문안이다. 화면에는 개발 중·확인 중·미리보기 같은 임시 설명을 넣지 않는다. 문안 원본은 [notice-content.ts](../frontend/src/features/consent/notice-content.ts), 읽기용 문서는 [privacy-notices.md](privacy-notices.md)다. 문안 원본이 바뀌면 읽기용 문서도 함께 갱신한다.

이 안내는 AI 처리에 앞서 필요한 설명이다. 운영자 정보·권리행사 접수처·위탁 현황 등을 포함한 전체 개인정보 처리방침이나 이용약관을 대신하지 않는다. 안내문 작성·표시와 실제 동의 수집 기능의 활성화는 구분한다. 이번 변경은 서버의 동의 설정, 시작 버튼의 실행 상태, 로그인·저장 기능을 활성화하지 않는다.

## 확인한 공식 자료와 상용 서비스 사례

1. [개인정보 보호법 — 2026-09-11 시행본](https://www.law.go.kr/LSW/lsInfoP.do?efYd=20260911&lsiSeq=283839): 수집·이용 동의의 목적·항목·기간·거부권 고지, 최소 수집, 민감정보, 파기, 위탁·국외 이전, 처리방침과 정보주체 권리를 구분하는 법적 기준이다. 관련 조문은 제15·16·21·22·23·26·28조의8·30·35~37조다.
2. [개인정보보호위원회 「개인정보 처리방침 작성지침」 2026.4. 개정](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=I030010000&nttId=12018): 공식 첨부 PDF 원문을 확인했다. 부록 1의 인쇄면 121~124쪽(PDF 123~126쪽)은 AI의 용도·입력과 생성정보·학습 여부·구체적인 보유기간을 설명하도록 한다. 인쇄면 126·129·131쪽(PDF 128·131·133쪽)은 위탁과 제3자 제공, 국외 이전, 권리행사와 필터의 한계를 구분한다. 지침의 예시 기간이나 외부 AI 업체명을 다시잇다의 사실로 옮기지 않았다.
3. [네이버 개인정보 처리방침](https://policy.naver.com/policy-mobile/privacy.html): 수집 항목, 이용 목적, 보관 및 삭제, 정보주체 권리의 구분과 쉬운 설명 방식을 참고했다. 네이버에 적용되는 거래·통신 기록의 법정 기간은 이 서비스에 그대로 적용하지 않았다.
4. [카카오 개인정보 처리방침](https://www.kakao.com/policy/privacy): 핵심 내용의 요약과 상세 설명을 함께 제공하고 수집·이용·제공·파기를 나누는 구성을 참고했다. 카카오계정이 수집하는 이메일·연락처 등을 다시잇다가 수집하는 항목으로 간주하지 않았다.

## 실제 게시·동의 수집에 연결할 때 확정할 사항

아래 내용은 운영 확인 사항이다. 사용자에게 보이는 세 안내창에 대괄호나 임시 문구로 노출하지 않는다. 문구만 바꿨다고 운영 준비나 법적 적합성이 검증된 것은 아니다.

- 운영 주체의 정식 명칭, 개인정보 보호책임자·접수 부서와 연락처, 시행일·안내문 버전, 전체 개인정보 처리방침·이용약관의 접근 경로를 확정한다.
- AWS의 실제 계약 상대방·위탁 업무·처리 리전·재위탁·해외 접근 및 이전 여부를 확인한다. 자체 모델 사용 또는 국내 리전 선택만으로 위탁·국외 이전이 없다고 단정하지 않는다. 이전이 있다면 국가·받는 자와 연락처·목적·항목·시기와 방법·보유기간·법적 근거·거부 방법과 영향을 구체적으로 고지한다. 이 AI 동의로 별도 제공·국외 이전 동의를 대신하지 않는다.
- 본문에 적은 보관기간과 삭제 기준을 실제 Redis·DB·서버/브라우저 음성·로그 수집·백업·삭제 이력의 운영 설정에 일치시킨다. 백업 7일, 이력 30일, 복구 전 삭제 재적용은 운영에서 지켜야 하는 정책이다. 현재 개발 어댑터만으로 운영 이행을 보증하지 않는다.
- 14일·30일의 일반 운영·업무 감사 보관 정책과 개인정보 처리시스템의 법정 접속기록 보관 의무를 구분한다. 실제 처리 규모·정보 유형·사업자 지위에 적용되는 안전성 확보조치와 법정 보존 의무를 확인한다. 단지 다른 서비스가 적었다는 이유로 거래기록 5년이나 로그인기록 3개월을 붙이지 않는다.
- 운영·세션·요청 제한·삭제 이력은 각각 동의, 계약 이행, 법령상 의무, 정당한 이익 중 적용되는 근거와 필요성을 확정하여 전체 처리방침에 구분해 기재한다. AI 처리 동의 거부가 모든 보안 기록 처리의 중단을 뜻하는 문구로 사용되지 않게 한다. 법정 보존 예외가 실제로 있다면 법령·대상·기간을 명시한다.
- 추가 프로필 항목의 입력·건너뛰기가 실제로 선택 가능해야 한다. 건강이나 장애를 드러내거나 추론하게 하는 활동 조건은 일반 동의와 입력 금지 문구만으로 처리 근거가 확보되지 않는다. 최소화·차단 또는 별도 적법 근거와 동의를 검토한다. 탐지 누락 정보의 처리·삭제 절차도 정한다.
- 비회원이 동의를 철회할 수 있는 접근 경로와, 모든 이용자의 열람·정정·삭제·처리정지·동의 철회 요청 접수 경로를 실제로 제공한다. 체험 종료·개별 체험 삭제를 세션의 AI 동의 철회와 같은 기능으로 표시하지 않는다. 회원용 내 정보의 철회 기능만으로 비회원 권리행사 경로가 완성되지는 않는다.
- AI 처리 동의는 목적·항목·보유기간·거부권을 확인한 이용자의 명확한 행위로 기록한다. 선택 음성·선택 프로필 정보·회원 저장·제3자 제공·국외 이전의 구분이 필요한 경우 실제 법적 근거와 흐름에 맞춰 선택 수단을 제공한다. 안내창 열기 자체를 수락으로 기록하지 않는다.

## 문장 교정과 검증 범위

문안 작성 후 `humanize-korean`의 교정·문장 규칙을 적용해 종결체, 연락처와 민감정보의 구분, 기간의 기산점, 행동과 효과를 확인했다. 수치·법적 근거·예외·불확실성을 문체를 이유로 바꾸지 않았다. 상용 서비스 문구를 복사하지 않고 프로젝트의 항목과 처리 단계에 맞춰 새로 작성했다.

이 문서는 문안의 근거와 게시 조건을 기록한다. 보안 취약점 점검 보고서나 법률 적합성 보증서가 아니다.

검증 결과: `npm exec --no -- tsc -b --pretty false`와 변경한 TS/TSX 파일 대상 `oxlint --deny-warnings`가 통과했다. 로컬 브라우저에서 세 안내창의 열기·닫기, Escape 후 원래 버튼으로 포커스 복귀, Tab/End를 이용한 본문 스크롤, 일반·큰 글씨의 본문과 닫기 버튼 배치를 확인했다. 화면 문안과 읽기용 문서의 일치도 확인했다. 문안·표시 변경 범위이므로 전체 테스트·E2E·백엔드 동의 수집·운영 삭제 및 복구 검증은 실행하지 않았다. 실제 모바일 기기와 스크린리더에서의 동작은 별도 검증 범위다.
