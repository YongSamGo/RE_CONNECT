# 호출 한도와 공유 추론 슬롯 (W03-04)

## 현재 연결과 남은 검증

`AdmissionService`는 IP/주체의 60초 이동 창 60회, KST 일일 생성/전사·읽어주기
각 60회, 전체 LLM/STT/TTS 500회와 서버 전체 공유 슬롯 1개를 Redis에서 원자적으로
검사한다. 슬롯과 일일 집계는 하나의 비만료 제어 해시다. Redis 유실·세대 불일치·
식별키 불일치·비정상 상태는 503이며 메모리로 대체하지 않는다.

현재 `/me`는 새 세션 생성 전 IP와 기존 주체의 분당 한도를 검사한다. 프록시
처리가 끝난 ASGI peer 주소만 사용하며 직접 `X-Forwarded-For`를 읽지 않는다.
공개 공고/지역 조회·health는 추론 한도 장애로 중단하지 않는다. 미래의 사적
업무 API는 세션 확인 뒤 같은 `check_http()`를 호출해야 한다. 일반 API 전체에
자동 연결된 것으로 간주하지 않는다.

앱의 `llm_adapter`는 원본 Ollama Adapter를 감싼 `ControlledLLMAdapter`다.
서버가 확인한 `InferenceIdentity(subject_id, ip, account_id)` 없이 호출하면
실행하지 않는다. 계정 ID는 로그인 저장소에서 읽어야 하며 클라이언트 필드로
만들면 안 된다. STT/TTS의 공통 `run(identity, kind, operation)` 경계는 제공하지만
실제 음성 Adapter/서비스 연결은 #31/#32/#33에 남아 있다. 업무 여정은 #37에서
연결한다. 실제 모델/EC2 종료·취소 검증은 #34/#92에서 해야 하므로 #23을 배포
통과로 변경하지 않는다.

## 집계·재시도 계약

- IP는 IPv4/IPv6 정규화와 IPv4-mapped IPv6 통합 후 별도 32바이트 HMAC 키로
  식별한다. 키 이름과 집계에 원 IP·본문·계정 원문을 넣지 않는다. HMAC 식별자도
  완전한 익명 데이터라고 주장하지 않는다.
- 비회원 생성/전사는 IP, 회원은 계정 기준의 공유 일일 60회다. TTS는 주체와 IP
  둘 다 60회다. 전체 실행 500회는 세 종류·재시도를 모두 포함한다.
- 일일 경계는 앱 시계가 아닌 Redis `TIME`의 UTC 초에 9시간을 더해 계산한다.
  일일 초과는 다음 KST 자정까지의 `Retry-After`, 분당 초과는 이동 창이 열릴
  때까지, 슬롯 부족은 2초를 돌려준다. 모두 고정 429 코드다.
- 한도·슬롯을 모두 통과한 시도만 일일 집계를 늘리고 실행한다. busy·초과·Redis
  실패로 거절한 요청은 실행하지 않는다. 모델 연결 시도 실패도 시도 횟수에 포함된다.
- Adapter와 이 서비스는 자동 재시도하지 않는다. 업무 서비스가 재시도를 허용할
  때에도 전체 60초 안에서 새 `run()`으로 횟수를 집계해야 한다. 종료 미확인 슬롯은
  재시도할 수 없다. #24의 Replay는 `run()`을 호출하지 않아야 한다.
- 자정에 이전 날의 `limit:*` 필드를 정리하지만 진행 중 슬롯을 지우지 않는다.
  하루 최대 500회라 일일 식별자 필드 정리의 크기도 유한하다. 한도 상수는
  `Plan/05_Engineering_Constraints.md` §3의 초기 제품 값이다.

## 종료 확인과 장애

슬롯에는 TTL을 주지 않는다. 요청 취소·시간 초과·연결 단절·프로세스 종료만으로
반환하지 않는다. `RuntimeCompletion.confirm_ended()`는 해당 실행의 최종 응답이나
실제 종료 확인에만 사용한다. `finally`에서 무조건 호출하면 안 된다.

Ollama Adapter는 전체 JSON 응답의 `done=true`, `done_reason=stop|length`를 확인한
시점에만 종료 신호를 보낸다. 그 뒤 출력 JSON/스키마 검증에 실패해도 실행은 끝났으므로
슬롯은 반환한다. 응답이 잘렸거나 너무 크거나 연결이 끊겨 최종 신호를 읽지 못하면
실행이 끝났다고 추정하지 않는다. `length` 결과를 사용자에게 정상 출력으로
반환하지 않는 기존 검증은 유지한다. 응답 종료 필드는
[Ollama 공식 chat API](https://docs.ollama.com/api/chat)의 계약을 확인했다.
실제 고정 런타임의 종료 의미와 GPU 유휴 상태는 배포 시험에서 별도로 대조해야 한다.

Redis 반환에 실패하면 503이며 제어 기록을 임의로 지우지 않는다. 중단된 worker를
대신해 다른 worker가 시간만 보고 슬롯을 가져오는 경로·공개 해제 API는 없다.
운영자는 요청 유입을 차단하고 **모든** LLM/STT/TTS 런타임의 종료/작업 배출을
확인한 뒤 복구해야 한다. 프로세스 내 세마포어로 다중 worker 슬롯을 대신하지 않는다.

한 번의 시간 초과가 슬롯을 잡은 채로 남으면 그 뒤의 모든 추론이 `INFERENCE_BUSY`가
된다. 메시지 처리는 경험 추출 한 번만 모델을 부르고, 다음 질문은 서버 규칙으로
고른다([질문 흐름](../ai/question-flow.md)). 두 번째 모델 호출이 없어 바깥 제한시간이
진행 중인 호출을 취소하는 경우가 줄어든다. 경험 추출 호출의 시간 초과는 여전히 슬롯을
유지하므로 아래 운영자 복구를 쓴다.

### 운영자 슬롯 복구 (`backend/manage_inference.py`)

`backend/`에서 운영 설정(`REDIS_URL`·`REQUEST_LIMIT_KEY`·`INFERENCE_CONTROL_EPOCH`)으로 실행한다.
출력은 고정 JSON이며 비밀값·세대 UUID·원 lease token을 담지 않는다.

1. 공개 진입점에서 요청 유입을 막는다.
2. `python manage_inference.py status`로 `active`, `kind`, `lease`(16자리 지문)를 확인한다.
3. Ollama·음성 서비스 등 **모든** 런타임을 정지하거나 재시작해 진행 중 작업이 없음을 확인한다.
4. `python manage_inference.py release --lease <지문> --confirm-runtime-stopped`를 실행한다.
   세대·식별키가 일치하고 2단계에서 본 lease가 그대로일 때만 `active`·`kind`를 지운다.
   그 사이 다른 실행이 슬롯을 잡았으면 `lease_changed`로 거절하고 아무것도 지우지 않는다.
5. 일일 집계(`day`·`global`·`limit:*`)는 바꾸지 않는다. 아래의 "집계 유실 시 500" 규칙은
   제어 해시 자체가 유실된 경우에만 적용한다.

`redis-cli`로 `active`를 직접 지우지 않는다. 런타임 정지 증거를 자동으로 함께 확인하는
도구와 슬롯 만료(TTL) 도입 여부는 실제 런타임 종료 시험(#34/#92) 뒤에 정한다.

## 설정과 제어 레코드 준비

`REQUEST_LIMIT_KEY`는 hex 64자(32바이트), `INFERENCE_CONTROL_EPOCH`는 운영자가 정한
UUID다. 소스·DB·로그에 실제 값을 넣지 않는다. 키가 없거나 형식이 틀리면 사적
한도/추론 기능은 503이다. 앱 시작이나 HTTP 호출은 제어 레코드를 생성하지 않는다.

운영 준비 시 단일 Redis의 `rc:admission:v1:control` 해시를 아래 형식으로 준비하고
설정과 일치하는지 확인해야 한다. 이 작업은 외부 런타임이 정지했음을 확인할 수 있는
운영 절차(#92/#97)의 일부이며, 이 변경에서 실제 운영 초기화를 수행하지 않았다.

| 필드 | 값 |
| --- | --- |
| `epoch` | 설정의 UUID와 같은 문자열 |
| `key_id` | HMAC 키 **32바이트**의 SHA-256 hex(키 원문 아님) |
| `day` | Redis 현재 UTC 초에 32400을 더하고 86400으로 내린 KST 날짜 인덱스 |
| `global` | 신규 설치로 실행이 없음을 입증할 때만 0. 유실 복구는 500 |
| `active`, `kind` | 모든 런타임 정지 확인 후 새 세대 준비 시 없어야 함 |

해시 자체에 만료를 설정하면 거절한다. 키/세대 변경도 모든 worker에 일관되게
적용한다. 일일 집계 유실 후 0으로 리셋하면 한도를 우회하므로, 복구 시 500으로
채워 다음 KST 날짜까지 새 추론을 막는다. HMAC 키 변경은 기존 주체 집계의
식별자를 바꾸므로 같은 복구 제한을 적용한다. 기존 해시를 실행 중 덮어쓰지 않는다.
점유된 슬롯은 위 운영자 슬롯 복구 절차로만 비운다.
