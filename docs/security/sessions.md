# 익명 세션·소유권 경계 (W03-01)

관련 #20. `/api/v1/me`가 익명 세션과 서명된 CSRF 쿠키를 발급한다. 회원 로그인·MFA·
동의·저장 대기는 #73/#52/#21/#74에서 연결하며 여기서는 authenticated=false, user=null,
consents=[], pending_save_intent=null이다. Redis가 없거나 실패하면 503이며 메모리 세션으로 대체하지 않는다.

## 자격증명과 쿠키

세션 토큰은 OS 난수 32바이트의 URL-safe 문자열이다. 응답 본문·URL·브라우저 localStorage에
넣지 않고 쿠키로만 전달한다. Redis key는 토큰의 SHA-256이며 원문 토큰을 저장하지 않는다.
이 해시는 고엔트로피 불투명 토큰의 조회 인덱스이며 비밀번호 저장 해시로 사용하는 것이 아니다.
Redis에는 임의 주체 UUID, 생성/마지막 활동 시각, 세션별 CSRF 서명 비밀만 둔다.
쿠키 원문·서명 비밀은 객체 repr에서도 숨기고 DB·파일·로그에 쓰지 않는다.

운영과 test 설정에서는 `__Host-rc_session; Secure; HttpOnly; SameSite=Lax; Path=/`와
`__Host-rc_csrf; Secure; SameSite=Strict; Path=/`를 사용한다. CSRF 쿠키는 브라우저가 읽을 수
있어야 하므로 HttpOnly가 아니다. Domain은 지정하지 않는다. 서버의 development 설정에서만
HTTP 개발용 rc_session/rc_csrf와 Secure 없는 쿠키를 사용한다. 요청 헤더·URL·프록시 헤더는
이 모드를 바꾸지 못한다. 같은 이름의 중복 쿠키도 모호하게 선택하지 않는다.

임의/만료/형식 오류 토큰은 /me에서 새 토큰·새 주체로 시작하고 클라이언트가 고른 값을
세션으로 채택하지 않는다. 사적 접근에서는 이런 토큰을 새 세션으로 대체하지 않고 404로 거절한다.
공개 지역 조회는 세션 저장소 장애에도 사용할 수 있다.

## 수명·교체·소유권

세션 수명은 Plan/05 §2의 유휴 30분·절대 12시간이다. 체험의 유휴 30분·최대 2시간과 별개다.
Redis 서버 TIME으로 확인하고 정확한 만료 경계에 도달하면 거절한다. 자동 /me 조회는
last_activity나 TTL을 갱신하지 않는다. 사용자 행동으로 확인된 경로만 resolve(touch=True)를
사용하며 절대 수명을 넘지 못한다. 자동 상태 조회·폴링에서 touch=True를 사용하면 안 된다.

Lua는 고정 소스와 분리된 키/인자로 실행한다. 교체는 새 토큰·서명 비밀 발급과 이전 key 삭제를
원자적으로 수행한다. 동시에 교체해도 하나만 성공한다. 익명 교체는 주체·생성 시각·기존 유휴
기준을 유지해 수명을 늘리지 않는다. 폐기한 토큰은 touch로 되살릴 수 없다.
현재 구성은 단일 Redis이며 Cluster의 서로 다른 슬롯 간 원자 교체를 지원한다고 주장하지 않는다.

`require_session`과 `require_owner`를 사적 자원 경로에 사용한다. owner_id는 요청 본문/UUID에서
믿지 않고 저장소에서 읽어 현재 세션의 주체와 비교한다. 없는 자원·다른 소유자·세션 없음은
같은 NOT_FOUND(404)다. 앞으로 만드는 체험/저장 자원도 이 경계를 통과해야 한다.
이미 시작한 실행이 삭제 뒤 완료되는 경합은 #27의 최종 저장 CAS/폐기 검사로 별도 방어한다.

CSRF 쿠키는 세션별 비밀로 HMAC-SHA256 서명하며 세션 digest와 nonce에 결합한다.
교체한 세션은 이전 CSRF 쿠키를 인정하지 않는다. /me에서 없거나 잘못된 CSRF 쿠키를 새로
발급한다. 변경 요청의 헤더/쿠키 일치·서명·Origin 검증은 #22에서 연결한다.
회원 로그인은 익명 rotate만 호출해서 완료할 수 없다. #72/#73은 인증 검증·저장 대기 이전·
이전 체험 정리와 새 회원 세션을 함께 처리하고 두 쿠키를 다시 발급해야 한다.

## 검증과 참조

HTTP 쿠키 속성/개발 예외, 자격증명/주체 비노출, 세션 고정·중복 쿠키·타 주체 UUID 접근과
동일 사적 404, 세션 결합 CSRF, Redis 실패 503/공개 조회를 시험한다. 실제 Compose Redis에서는
원문 토큰 미저장·TTL·자동 조회 불연장·정확한 유휴/절대 만료·활동/교체의 절대 수명 제한·
12개 동시 교체의 단일 성공·폐기를 검증한다. 로컬 Redis가 없으면 이 5개는 skip하고 필수 CI에서 실행한다.
