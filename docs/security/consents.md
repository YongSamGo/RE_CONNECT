# 목적별 동의 검사 (W03-02 · #21)

## 적용 범위와 준비 상태

`POST /api/v1/consents`와 `GET /api/v1/me`에 익명 AI 처리 동의를 연결했다. 요청 계약은 [OpenAPI](../api/openapi.yaml)의 `ConsentCreate`·`ConsentState`를 따른다. 수락 시각과 주체는 서버가 정하며 요청 본문에 회원 ID·수락 시각·승인 여부를 받지 않는다.

현재 회원 인증(#73)이 없으므로 HTTP의 `storage` 수락은 항상 401이다. 회원 동의의 SQL 저장·조회는 내부 서비스로 구현했지만 인증 API와 연결했다고 보지 않는다. 인증 이후 서버가 확인한 회원 ID로만 `ConsentActor.member_id`를 채워야 한다. 익명 세션의 AI 동의를 회원의 저장 동의로 승계하지 않는다.

#9에서 실제 운영 주체·연락처·처리 리전·안내문을 확정한 뒤 `AI_NOTICE_VERSION`·`STORAGE_NOTICE_VERSION`을 설정한다. 기본값은 둘 다 미설정이다. 미설정 상태에서 수락은 503, 실행 동의 검사는 403 `CONSENT_REQUIRED`로 거부한다. 계약 예제 버전을 운영 버전으로 자동 사용하지 않는다. 새 버전을 설정하면 이전 버전은 `/me`에서 빠지고 처리 권한을 주지 않는다.

## 정상 동작과 거절

- CSRF 토큰과 단일 허용 Origin 검사가 수락 API 앞에서 실행된다. 유효한 익명 세션이 있어야 한다.
- 현재 목적·버전의 첫 수락은 201, 같은 동의 재수락은 기존 시각을 유지한 200이다. 폐기 버전은 422의 `notice_version / invalid_value`이며 원문 값을 응답·로그에 싣지 않는다.
- 익명 동의는 Redis의 해당 세션 해시에 보관한다. Lua에서 실제 세션 주체·유휴/절대 만료를 수락 직전에 확인한다. 만료/삭제된 해시를 다시 생성하지 않고, 동의 저장·조회 자체로 TTL을 연장하지 않는다. API의 명시적 사용자 수락은 세션 서비스의 사용자 활동으로 처리한다.
- 세션 교체는 현재 #20 구현에서 동의를 복사하지 않는다. 새 세션에서 다시 동의해야 한다. 로그인 시 동의 승계가 필요하면 #73에서 인증 주체와 안내문을 재검증한 명시적 정책으로 구현한다.
- 회원 수락은 활성 회원 행의 잠금을 잡고 해당 회원·목적에 대해서만 조회·추가한다. 모든 회원 동의 쓰기가 같은 행 잠금 규약을 사용해야 중복 수락 경합이 직렬화된다. SQLite 시험은 PostgreSQL 행 잠금의 증거가 아니다.
- SQL 조회는 가장 최근 수락 기록 하나를 검사한다. 철회된 최신 기록을 건너뛰어 오래된 미철회 기록을 되살리지 않는다. 저장소 장애에서 메모리 동의로 대체하지 않는다.

`ConsentService.require(actor, purpose, notice_version=...)`는 AI 실행/회원 저장 전 현재 버전 검사를 제공한다. 이 검사를 통과한 뒤 시간이 지나도 저장 권한이 유지된다는 보장은 없다. 결과 저장 직전의 철회·만료·계정 세대 검사는 #27·#74·#78에서 실제 저장 트랜잭션/Lua와 함께 연결해야 한다. 공개 AI 업무 경로는 아직 없다.

## 철회·삭제 연결 표

| 목적/사건 | 즉시 금지 | 삭제 대상 | 후속 연결 |
| --- | --- | --- | --- |
| AI 처리 동의 철회 | 새 LLM/STT/TTS 실행, 늦은 결과 반영 | 진행 중 체험·대화·전사·음성·미저장 프로필/지원서 | #27·#43·#78 |
| 저장 동의 철회 | 새 회원 영구 저장·저장 대기 확정 | 저장 프로필 전 버전과 파생 지원서·저장 대기 | #74·#78 |
| 안내문 버전 폐기 | 해당 목적의 신규 처리 | 버전 변경만으로 자동 삭제하지 않음, 재동의 필요 | #9·#21·#81 |
| 익명 세션 삭제/만료 | 해당 익명 동의 재사용 | 세션 해시에 포함된 동의 | #20·#43 |
| 탈퇴 | 새 처리·저장·로그인 세션 사용 | 계정·동의·세션·체험·저장본, 최소 삭제 이력은 별도 정책 | #78·#94·#95 |

`POST /consents/withdraw`는 [삭제·철회 안내](../data/member-deletion.md)의 실제 자료 삭제·세션 세대·원자 Redis 정리·SQL 저장 경합 및 실패 재시도에 연결한다. 동의 플래그만 바꿔 삭제 완료로 응답하지 않는다. 운영 DB 밖 이력 어댑터·안내문과 복구 리허설은 별도 완료 조건이다.

## 로컬 검증

2026-10-18 후속으로 실제 Redis 7.0.15·PostgreSQL 16.15의 격리 환경에 전체 백엔드를 연결해 633개가 모두 통과했다(건너뜀 없음). 익명 동의의 실제 Redis TTL·주체·삭제/만료 후 재생성 차단 시험도 실행됐다. 회원 동의 서비스의 SQL 단위 시험은 SQLite 범위이므로 PostgreSQL 동의 수락 행 잠금의 동시성 증거로 확장하지 않는다. 회원 로그인·저장·철회 삭제 연동은 여전히 남아 있다.

`backend`에서 `python -m pytest tests/test_consents.py -q`로 목적 분리, 반복 수락, 미동의·폐기 버전·타인 동의 거절, CSRF, 회원 사칭, 철회 최신 기록, 정지 계정을 검증한다. 가상 안내문과 가상 회원만 사용한다.

실제 Redis 시험은 `PERSISTENCE_TEST_REDIS_URL`이 설정될 때만 실행한다. 세션 TTL 유지·주체 바꿔치기 거절·삭제/만료 후 재생성 차단을 검사한다. 로컬에서 건너뛴 시험은 통과로 세지 않는다. 실제 PostgreSQL 중복 수락 경합, 회원 로그인 연동, 공개 AI 실행/저장 차단, 철회 삭제와 늦은 결과 경합, 배포 안내문 적합성은 별도 검증이 필요하다.

관련 KISA 보안약점: 적절한 인증 없는 중요 기능 허용(SEC-01), 부적절한 인가(SEC-02), 크로스사이트 요청 위조(INP-11), 오류 메시지 정보노출(ERR-01). 이 문서는 구현 범위 설명이며 전체 서비스 보안 통과 판정이 아니다.
