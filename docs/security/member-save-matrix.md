# 회원 자료 접근·저장 경합 검증 (#79)

범위는 #77 재편집과 #78 삭제·철회·탈퇴를 포함한 현재 회원 저장 API다. 실제 PostgreSQL/Redis와 HTTP 요청으로 회원A·회원B·별도 운영자 역할·익명 세션을 비교한다. 회원B/운영자도 자기 프로필·승인 지원서를 정상 저장한 뒤 타인 자료에 접근하게 해, 선행 자료가 없어서 거절되는 결과와 소유권 거절을 혼동하지 않는다. 제공자·안내문·키·본문은 가상 데이터다.

## 접근 행렬

| 요청 | 회원A(소유자) | 회원B | 운영자 역할 | 익명 |
| --- | --- | --- | --- | --- |
| `GET /profiles/me` | 자기 자료200 | B 자기 자료만200 | 운영자 자기 자료만200 | 401 |
| `GET /drafts` | 자기 목록 | B 자기 목록 | 운영자 자기 목록 | 401 |
| A 저장 지원서 상세 | 200 | 404 | 404 | 401 |
| A 저장 지원서 새 편집 | 새 미승인 임시본 | 404 | 404 | 401 |
| 자기 승인 초안을 A 문서로 저장 | 자기 기준 버전으로 저장 | 404 | 404 | 401 |
| A 저장 지원서 삭제 | 전 버전 삭제204 | 404 | 404 | 401 |
| A 임시 프로필 조회·수정·재확정 | 자기 자료만 | 404 | 404 | 다른 주체404 |
| A 임시 지원서 조회·수정·승인 | 자기 자료만 | 404 | 404 | 다른 주체404 |
| A 체험 종료·삭제 | 종료204 | 무효과204 | 무효과204 | 무효과204 |
| 삭제 본문/쿼리로 다른 회원 선택 | 미지원422 | 422 | 422 | 실제 회원 탈퇴는401 |

체험 삭제204는 다른 사람·없는 체험을 구분하지 않는 기존 계약이다. 응답만 보지 않고 A의 프로필·지원서·버전이 그대로 남는지 다시 조회한다. 저장 지원서의 타인/없는 UUID는 같은404 코드다. `X-Account-ID`, `X-User-ID`, `X-Role`, 목록의 `owner_id` 쿼리로 로그인 주체를 바꾸지 못한다. 오류 응답에 다른 회원의 본문이 포함되지 않는지도 검사한다.

운영자 비교는 DB의 실제 admin 역할을 가진 회원 세션이다. 일반 회원 자료 API는 운영자 권한을 개인 자료 접근 권한으로 승격하지 않는다. 운영자 업무의 실제 MFA 검증(#52)을 완료한 것으로 해석하지 않는다. 서로 다른 로그인 세션의 임시 체험을 자동 복원하지 않는다.

## 저장·삭제 경합과 실패

| 시나리오 | 검증하는 결과 |
| --- | --- |
| 같은 회원·같은 키의 동시 프로필 저장 | 같은 응답, 새 버전1개·응답 기록1개 |
| 다른 확정본·같은 기준 버전 동시 프로필 저장 | 한 요청201, 다른 요청409, 최신 버전 한 번 증가 |
| 같은 저장 문서의 다른 승인 초안 동시 갱신 | 한 요청201·다른 요청409, 원래 버전 본문 유지 |
| 서로 다른 회원이 같은 멱등 키 사용 | 각각 자기 문서만 갱신/재생, owner별 응답 기록 분리 |
| 기기B 저장 중 기기A 삭제 | 먼저 끝난 SQL 저장까지 삭제, 모든 옛 세션 종료, 늦은 문서 재생성 없음 |
| A의 외부 삭제 이력 저장 실패 | A의 업무만 차단, B의 기존 자료 계속 조회 가능 |
| 실패 작업 관리 재시도 | A의 대상만 삭제, B의 원문·버전 유지 |
| 탈퇴 SQL 완료 뒤 새 쿠키 발급 실패 | HTTP503/성공 쿠키 없음, 익명 상태 재조회, 다른 회원 자료 유지 |
| 화면의503·재인증403 | 완료 안내·성공 콜백 없음, 오류 원문 노출 없음 |

회원A의 준비는 실제 승인 자료 대기→가상 제공자 OAuth/state 왕복→새 회원 세션→명시 저장 동의→프로필·지원서의 두 단계 저장을 사용한다. 로그인 성공을 저장 성공으로 세지 않고 옛 세션 폐기와 대기 소비도 확인한다. 회원B/운영자의 독립된 쿠키·CSRF와 같은 공개 공고를 사용한다.

핵심 시험은 `backend/tests/test_member_security_matrix.py`, 화면 실패 시험은 `frontend/src/features/account/account-failures.test.tsx`다. 실제 DB/Redis 미설정으로 제외한 시험을 통과로 세지 않는다. CI의 PostgreSQL/Redis 잡에서도 통합 행렬을 실행한다. 기존 #74~#78의 소유권·본문 암호화·철회/삭제/재인증·복구 시험을 제외하거나 약하게 바꾸지 않는다.

## 증거의 범위

로컬 전체 회귀와 별도로 실제 TCP main 앱에서 두 제공자 테스트 신원으로 로그인·각자 저장하고 상호 조회/저장/삭제/복사404, 헤더 사칭 무효, 운영자 역할의 타인 조회404, A의 삭제·철회·재인증 탈퇴 뒤 B 원문 유지까지 확인한다. 부하 제한을 소유권 검사로 오인하지 않도록 서로 다른 루프백 peer를 사용하며 한도 기능을 끄지 않는다.

이는 실제 운영 카카오 승인·EC2·실기기 검증을 대체하지 않는다. 운영 정보 미정으로 실제 동의는 비활성이고, 운영 외부 삭제 이력 어댑터·보관/권한·AWS 복구·주기 재시도/알림과 전체 화면 연동은 후속 조건이다. 이 검증 추가만으로 운영 통과나 이슈 자동 종료를 하지 않는다.
