# 내부 계정과 회원 세션 — W10-02

## 계정과 주체

검증한 카카오 숫자 ID는 User.kakao_subject 고유 제약으로 내부 UUID 하나와 연결한다. 최초 생성은 role=user/status=active로 고정하며 브라우저가 역할·내부 계정 ID를 선택하지 않는다. 동시 첫 로그인은 ON CONFLICT와 행 잠금으로 한 User에 연결한다. 기존 운영자 역할이나 정지 상태를 덮어쓰지 않는다. 정지 계정의 로그인은 실패한다. 회원번호는 로그/응답에 반환하지 않는다.

Redis 세션 해시에 내부 user_id·reauth_until_ms만 추가한다. 카카오 코드/토큰/회원번호/DB 역할은 넣지 않는다. 기존 임의 subject_id는 체험용 세션 주체이고 user_id와 구분한다. 같은 회원의 다른 세션도 다른 subject_id를 가져 이전 익명 자료나 다른 세션의 체험을 자동 상속하지 않는다. 회원 데이터의 소유권은 require_member가 반환한 내부 User ID로 검사해야 한다.

SqlAccountRepository는 매 조회 새 트랜잭션에서 현재 상태·역할을 읽는다. PostgreSQL statement5초/lock1초 제한, SQL 값 바인딩과 고정 오류를 사용한다. Redis 확인 → DB 확인 → Redis 재확인으로 DB 대기 중 세션 회수를 검사한다. DB/Redis 장애를 익명 인증 성공이나 메모리 대체 인증으로 바꾸지 않는다.

## 로그인·로그아웃

카카오 제공자 확인 뒤에도 시작 세션이 살아 있고 같은 주체인지 다시 읽는다. MemberService의 실제 완료 처리기를 main에서 연결한다. login은 User 연결 뒤 새 난수 세션·새 임의 주체·새 CSRF를 만든다. 단일 Lua가 이전 세션 수명 검사, 새 세션 생성과 user_id 결합, 이전 세션/남은 OAuth state 삭제를 함께 수행한다. 새 세션은 새 유휴30분·절대12시간 수명이다. 이전 세션의 동의·MFA·재인증 값을 복사하지 않는다.

쿠키는 기존 Secure/HttpOnly/SameSite=Lax 세션과 SameSite=Strict 서명 CSRF 경계를 사용한다. 실제 HTTP 개발의 rc_session/rc_csrf 예외는 development 설정에만 적용한다. SQL과 Redis 사이에 분산 트랜잭션이 있다는 뜻은 아니다. 새 Redis 세션을 만든 뒤 계정 상태 최종 조회가 실패하면 쿠키를 반환하지 않고 새 세션을 회수한다. SQL 계정 연결 자체는 남을 수 있다. 모든 중요 회원 요청도 현재 DB 상태를 확인해야 한다.

POST /auth/logout은 기존 Origin/CSRF 검사를 거친다. 현재 세션을 원자 폐기하고 새 익명 세션·CSRF를 주며204다. 이전 회원 결합·재인증은 세션과 함께 지워진다. 정지 계정도 로그아웃할 수 있다. 정리 훅 실패 시503이고 이전 세션을 회수한다. 실패를 정상 삭제 완료로 보고하지 않는다. 익명용 SessionService.rotate는 회원 세션을 조용히 익명화하거나 재사용하지 못하도록 거절한다.

## 체험/저장 대기 경계

현재 이 브랜치의 앱에는 체험/저장 대기 경로가 아직 함께 조립되지 않았다. 해당 모듈을 합칠 때 session_transition_hook을 연결해야 한다. 앱에 journey_service 또는 save_intent_service가 있는데 실제 훅이 없으면 로그인 전환은 실패한다. 로그아웃은 실패를 반환하면서도 이전 인증을 회수한다. 훅을 빈 성공 처리로 대신하면 안 된다.

훅은 이전 세션의 진행 체험·본문·늦은 추론 결과를 정리해야 한다. 저장 대기는 #74의 실제 조건 검사·원자 이동을 연결해야 한다. 이 PR은 존재하지 않는 저장 대기를 만들어 내지 않으므로 purpose=save는 expired다. 기존 분리 브랜치의 체험/저장 대기를 실제로 합친 삭제·이동 검증은 #74 후속이며 이 PR만으로 완료를 주장하지 않는다.

## GET me·현재 권한·재인증

GET /me는 세션에 결합한 내부 User ID·현재 DB 역할을 반환한다. 내부 role=admin은 API roles=[operator], 일반 계정은 [user]다. 카카오 식별자/세션 주체/원문/토큰은 반환하지 않는다. 정지·삭제된 계정은 새 익명 세션으로 전환하고 이전 인증을 폐기한다. DB 장애는503이며 임의 익명 전환으로 숨기지 않는다. 현재 안내문 버전/회원 동의 연결과 저장 대기는 아직 이 브랜치에 없으므로 consents=[]/pending_save_intent=null이고 동의를 추정해 부여하지 않는다(#21/#74 통합 후속).

reauth는 이미 로그인한 세션만 시작한다. 검증한 카카오 ID가 현재 내부 계정과 같아야 하며, 다른 계정이면 새 User를 만들지 않고 failed다. 같은 계정은 쿠키/세션/CSRF를 교체하지 않고 Redis TIME 기준 최대5분, 기존 세션의 남은 수명 이내로 재인증한다. GET me는 유효한 reauth_until만 반환하며 만료 후 null이다. require_member(reauth=True)는 미인증·만료를 거절하므로 탈퇴 API(#79)가 사용할 수 있다. 실제 탈퇴 API는 이 PR이 구현하지 않는다.

require_member는 현재 쿠키의 세션을 다시 읽고 실제 사용자 활동일 때만 유휴 시각을 갱신한다. 회원 결합도 같은 해시에 있어 만료·회수·활동 연장과 분리되지 않는다. role/status를 세션이나 클라이언트 입력에서 신뢰하지 않는다. operator=True는 일반 계정이면 FORBIDDEN, 운영자라도 실제 MFA(#52)가 연결되기 전에는 MFA_REQUIRED다. GET me의 mfa_verified도 false다. 역할만으로 관리 API가 열리지 않는다.

중요 DB 변경 모듈은 이 입구 검사와 별도로 실제 저장 트랜잭션 안에서도 현재 권한·소유권·기준 버전을 확인해야 한다. 입구 검사 뒤 무제한 대기해도 권한이 보장된다는 뜻은 아니다. #52/#74/#79와 기존 늦은 결과 확정 경계를 함께 연결한다.

## 검증

가상 제공자와 실제 Redis·SQLite/PostgreSQL을 결합해 쿠키/CSRF·주체 교체, 이전 세션 회수, 동시 callback/첫 계정 연결, 현재 역할·정지, 동일/다른 계정 재인증, 만료, 외부 대기 중 logout, DB 최종 확인 실패 후 세션 회수, 미연결 체험 훅의 실패 닫기를 시험한다. 테스트용 보호 라우트는 tests 안에만 있고 운영 앱에는 추가하지 않는다.

실제 loopback TCP API·PostgreSQL·Redis로 login→me→reauth→logout을 확인했으며 제공자는 고정 전송 대역이다. 개발 HTTP 쿠키 예외와 실제 운영 HTTPS/카카오 승인을 구분한다. 실제 카카오 앱·사용자 정상 승인, 운영 프록시/HTTPS, #21/#74 자료 통합, #52 MFA·#79 탈퇴, EC2 배포는 별도 검증이 남아 있다.
