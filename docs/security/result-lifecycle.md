# 삭제·만료 후 늦은 결과 차단 (W03-08 · #27)

## 구현 경계

`RequestService.create_guarded_resource()`로 익명 체험의 세대·세션·AI 안내문 버전을 결합한 임시 자원을 만든다. `CompletionGuard`는 서버 내부 입력이며 HTTP 본문에서 받지 않는다. 자원은 최대 2시간, 유휴 수명은 30분이다. 이 단계에는 활동 시각 갱신 API가 없으므로 장시간 체험의 실제 사용자 활동 갱신은 #36에서 연결해야 한다.

`complete(..., guard=...)`의 단일 Redis Lua 스크립트는 아래를 모두 검사하고 요청 완료·결과 참조·리비전 증분을 함께 기록한다.

1. 세션이 존재하고 같은 주체이며 유휴/절대 수명이 남아 있는지 확인한다.
2. 현재 세션의 AI 동의 버전이 호출자가 전달한 현재 안내문 버전과 같은지 확인한다.
3. 체험의 세대·세션 digest·안내문 버전·생성/활동 시각·TTL이 일치하는지 확인한다.
4. 실행 토큰·입력 해시·대기 상태·기준 리비전이 일치하는지 확인한다.

체험 생성 때에도 실제 Redis 시각으로 세션·동의를 검사한다. 주체가 없거나 만료됐거나 동의가 없으면 키를 생성하지 않는다. 읽기/완료로 수명을 연장하지 않는다. 체험 세대는 서버에서 새 UUID로 생성하며 기존 체험 식별자를 재사용하지 않는다.

보호 자원의 리비전은 내부적으로 `g:<정수>`로 저장한다. 요청의 `guarded` 표식과 함께 검사해 보호 정보를 빼고 기존 완료 함수를 호출하는 우회를 거부한다. 수명 메타데이터가 유실되면 새 예약과 완료를 거절하며 정상 자원으로 낮추지 않는다. 클라이언트가 사용하는 리비전은 여전히 정수다.

`cancel(permit)`은 실행 토큰을 확인하고 요청을 `cancelled`로 바꾼다. 반복 취소는 성공이며 늦은 완료는 404다. 이미 완료된 요청을 취소하면 409 `INVALID_STATE_TRANSITION`이다. 취소와 완료의 원자 스크립트 중 먼저 실행된 작업이 이긴다. 체험 삭제는 리비전·수명 메타데이터·연결 요청을 함께 지운다.

## 결과 저장과 적용 한계

현재 완료 저장소는 **결과 참조만** 보관한다. 프로필·지원서·전사 본문을 별도 DB/Redis 쓰기로 저장한 뒤 이 함수를 호출하면 본문 쓰기의 경합은 보호되지 않는다. #37·#38·#67의 실제 임시 본문 쓰기는 위 검사와 같은 스크립트 안에서 커밋하도록 확장해야 한다. 이전 결과를 재생할 때에도 업무 서비스가 세션·소유권·현재 동의·체험 수명을 먼저 확인하고 실제 결과를 조회해야 한다.

회원 영구 저장은 이 Redis 스크립트로 보장하지 않는다. #74·#75·#76·#78에서 활성 계정·삭제 세대·저장 동의·기준 버전·멱등 저널·암호화 INSERT를 **동일한 PostgreSQL 트랜잭션**으로 묶어야 한다. 탈퇴로 계정이 사라진 뒤 Redis 결과를 근거로 회원을 다시 만들지 않는다. DB 밖 최신 최소 삭제 이력의 위치·권한·보관기간은 [백업·복원 문서](backup-restore.md)(#94)에 정했고, 복구 재적용 검증은 #95에서 한다. 해당 회원 저장/복구 기능은 아직 구현하지 않았다.

안내문 배포 시 모든 worker에 같은 현재 버전을 적용하고, 이전 worker의 요청 유입과 실행을 배출해야 한다. 업무 서비스는 완료 때 현재 정책의 버전을 사용한다. 시작 때 캡처한 버전만으로 버전 폐기 이후의 처리 권한이 유지된다고 보지 않는다.

## 런타임 중단과 공유 슬롯 복구

결과 취소·체험 삭제·HTTP 연결 종료·타임아웃은 GPU 작업 종료를 증명하지 않는다. 기존 `AdmissionService`는 최종 응답/종료가 확인된 경우에만 슬롯을 반환한다. 요청 취소 API에서 `RuntimeCompletion.confirm_ended()`나 슬롯 해제를 호출하지 않는다.

프로세스가 중단돼 종료를 확인할 수 없으면 다음 절차를 따른다.

1. 모든 worker의 신규 추론 유입을 차단한다. 미확인 슬롯을 시간만으로 해제하지 않는다.
2. Ollama·STT·TTS 전체의 진행 작업을 종료/배출하고 GPU 실행이 남지 않았다는 운영 증거를 확보한다.
3. [추론 제어 문서](inference-admission.md)의 새 epoch와 일관된 식별키를 준비한다. 제어/한도 기록 유실 복구는 당일 전역 집계를 500으로 채워 한도 초기화를 통한 재실행을 막는다.
4. 모든 worker 설정을 새 세대로 일치시키고 readiness를 확인한다. 이전 실행의 취소/삭제된 체험에 결과를 반영하지 않는지 검사한 뒤 유입을 연다.

현재 공개 슬롯 해제/자동 복구 API는 없다. 실제 런타임 종료를 확인할 수 없는 이 로컬 환경에서 운영 제어 레코드를 변경하지 않았다.

## 검증 상태

`backend`에서 `python -m pytest tests/test_result_lifecycle.py tests/test_request_coordination.py tests/test_admission.py -q`로 실행한다. 순수 검증은 로컬에서, Redis 원자성·경합은 `PERSISTENCE_TEST_REDIS_URL`이 있는 실제 Redis에서 실행한다. 테스트에는 삭제/만료/철회/세대 변경 후 늦은 완료, 보호 정보 유실 우회, 취소·완료 경합, 응답 유실 재완료와 TTL 유지를 포함한다.

2026-10-18 후속으로 격리된 WSL 시험 환경의 Redis 7.0.15·PostgreSQL 16.15에 전체 백엔드를 연결해 633개 시험이 모두 통과했다(건너뜀 없음). 이 결과에는 실제 Redis의 원자 완료·취소/삭제 경합·수명/동의 재검사와 슬롯 시험이 포함된다. 시험 데이터는 가상 자료만 사용했고 PostgreSQL은 tmpfs, Redis는 비영속 모드로 실행한 뒤 모두 종료했다. Docker 이미지의 정확한 빌드·EC2 런타임 검증으로 대신하지 않는다. 실제 AI 업무 본문 쓰기, 회원 SQL 계정 삭제 세대, 외부 삭제 이력 복구 증거는 남아 있으므로 #27 전체 완료로 표시하지 않는다.

관련 KISA 보안약점은 경쟁조건: 검사시점과 사용시점(TOCTOU, TIM-01), 부적절한 인가(SEC-02), 오류 메시지 정보노출(ERR-01)이다.
