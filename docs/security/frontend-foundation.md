## 검증

- `npm run build`: 타입 검사·배포 빌드 통과.
- `npm run lint`: 통과.
- `npm test`: 12건 통과. 공백·과대 입력, 안내 확인·확정 전 직접 경로 접근, 수정 중 이전 확정본 유지, 종료 취소/삭제, 앱 재생성, 미연동 경로 확인 포함.
- XSS 입력 `<img src=x onerror=alert(1)>`이 폼 값으로 유지되고 이미지 DOM을 만들지 않는지 확인.
- 체험 흐름에서 Storage.setItem 호출이 없고 종료·앱 재생성 시 입력이 사라지는지 확인. 코드에서 IndexedDB·쿠키·스토리지 사용 및 API 호출이 없는지 검토.
- `npm audit --audit-level=moderate`: 전체 의존성 알려진 취약점 0건.
- `npm audit signatures`: 패키지 234개 레지스트리 서명 검증, 96개 attestation 검증.
- 내장 브라우저에서 시작 → 안내 → 경험·지역·활동 입력 → 프로필 확정과 새로고침을 확인. 데스크톱 및 좁은 뷰포트·큰 글씨에서 가로 넘침을 확인하고 모바일 버튼의 접근성 이름을 보완. 실제 Android/iPhone 및 스크린리더 검증은 미완료.

이 검증은 클라이언트의 입력 처리를 다룬다. 서버의 필수조건 검사·인가·CSRF·세션 수명·삭제 보장·운영 CSP/캐시 정책은 API·배포 연동 시 별도 구현하고 검증해야 한다. 화면의 접근 분기는 서버 인가를 대신하지 않는다.

## 공고 탐색·신청 준비 화면 후속 작업 (2026-10-16)

동일 작업 흐름에서 이미 확인한 위 진단가이드 두 문서를 적용했다. 추가 보안 원문을 임의로 수정하거나 불필요하게 다시 읽지 않았다. 웹 서비스 요청 및 결과 검증(제2장 제3절 1.5, PDF 64~71쪽)의 원칙에 따라 검색어는 100자 UI 제한과 문자열 비교로 처리하고 지역·활동 필터를 함께 적용한다. 결과가 없을 때 조건을 자동 변경하지 않는다. 크로스사이트 스크립트(제4장 제1절 4, PDF 211~213쪽 참조)의 출력 문맥 원칙에 따라 예시 설명과 검색어는 문자열로 취급하며 정규식 실행·HTML 삽입을 사용하지 않는다. 위 표에 원문 프로젝트 상대경로를 기록했다.

가상 예시와 실제 공고의 구분, 자격 판단 미제공, 신청 완료 오표시 방지, 준비 체크 메모리 유지·초기화는 `Plan/01_UX_Flow.md` §4 및 `Plan/Implementation_Plan.md` W11-06/07의 프로젝트 요구사항을 적용한 판단이다. 공식 보안 가이드의 고정 정책으로 설명하지 않는다. 실제 URL·파일·외부 API를 추가하지 않아 해당 외부 연동 구현이 완료됐다고 주장하지 않는다.

- `npm test`: 전체 19건 통과. 예시 선택 전 데이터 미표시, 복합 필터·빈 결과·조건 유지, HTML/정규식 형태 검색어의 문자열 처리, 공고별 체크 격리·화면 이동 유지, 종료 후 초기화 및 앱 재생성 확인.
- `npm run lint`, `npm run build`: 통과. 추가 의존성 없음.
- 준비 체크도 React 메모리에만 두며 체험 종료 시 초기화한다. 프로필 없이 예시를 살펴볼 때도 종료 기능을 제공한다.
- 서버 자격 대조·검수·접수·오류 신고 및 실제 기기 검증은 후속 연동 범위다.

## 지원서 직접 작성·확인·복사 후속 작업 (2026-10-16)

참조는 위 표의 동일 원문이다. `SW개발보안_obsidian/Security/SW-Diagnosis-2021/제2장-소프트웨어-개발보안/제3절-설계단계-보안설계-기준/023-1.5-웹-서비스-요청-및-결과-검증.md`(제2장 제3절 1.5, PDF 64~71쪽)의 입력 검증 원칙을 자기소개·지원동기의 공백/누락·길이 검사에 적용했다. 항목별 2,000자는 프론트 체험의 임시 한도이며 공식 가이드나 확정 API 수치가 아니다.

`SW개발보안_obsidian/Security/SW-Diagnosis-2021/제4장-구현단계-보안약점-진단/제1절-입력데이터-검증-및-표현/047-4.-크로스사이트-스크립트.md`(제4장 제1절 4, PDF 211~213쪽 참조)의 출력 문맥 원칙을 따라 확정 경험·지원서·복사 대체 텍스트를 React 문자열로 렌더링한다. HTML 삽입은 하지 않는다. Python 구현 지침을 프론트 코드에 직접 대입하지 않았다.

`Plan/04_Functional_Specification.md` F03·F08 및 `Plan/01_UX_Flow.md` §4의 프로젝트 승인·변경·보관 요구사항에 따라 확정 프로필이 있어야 직접 작성할 수 있다. 확인 전 복사를 막고 문장 수정 시 확인을 해제한다. 프로필 재확정 시 기존 문장과 근거 버전을 유지해 재검토가 필요함을 표시하고 재확인 전 복사를 막는다. 본문·체크·확인 상태는 현재 체험 메모리에만 두고 종료 시 초기화한다. 복사한 클립보드는 이 삭제 범위에 포함되지 않음을 화면에서 알린다. 이는 실제 물리 메모리 소거 보장을 뜻하지 않는다.

- `npm test`: 전체 26건 통과. 프로필 선행, 필수/길이·사실 확인, 정확한 복사 문자열, HTML 형태 입력 처리, 수정 시 확인 해제, 프로필 변경 후 재검토, 복사 거부 대체 화면·지연 응답, 공고별 격리와 종료·재생성 검증.
- `npm run lint`, `npm run build`: 통과. 추가 의존성 없음.
- 내장 브라우저에서 생성한 시험용 문장으로 작성→확인→복사를 실행하고 실제 클립보드와 줄바꿈까지 일치함을 확인했다. 좁은 화면·큰 글씨에서 가로 넘침이 없음을 확인했다.

AI 생성, 실제 공고 변경/마감에 따른 서버 검증, 서버 승인·버전·인가·암호화 저장·신청은 미연동이다. 화면 체험을 W09/W11-07 전체의 통과로 처리하지 않는다. 실제 Android/iPhone·스크린리더·브라우저별 클립보드 정책 검증은 남아 있다.

## 현재 체험 자료 조회·지원서 개별 삭제 (2026-10-16)

동일하게 확인한 XSS 진단 원문 `SW개발보안_obsidian/Security/SW-Diagnosis-2021/제4장-구현단계-보안약점-진단/제1절-입력데이터-검증-및-표현/047-4.-크로스사이트-스크립트.md`(제4장 제1절 4, PDF 211~213쪽 참조)의 출력 문맥 원칙을 적용했다. 내 정보의 확정 경험과 지원서 미리보기·삭제 안내는 React 문자열로 표시한다. HTML 형태의 경험이 이미지 DOM을 만들지 않는지 검사했다.

`Plan/01_UX_Flow.md` §4의 임시/저장 상태 구분과 `Plan/Implementation_Plan.md` W11-01/08을 참고해 현재 체험 자료를 회원 저장 자료와 구분했다. 개별 삭제는 해당 메모리 지원서만 제거하며 프로필·체크·클립보드를 삭제했다고 표현하지 않는다. 확인·삭제·재검토 표시는 프로젝트 판단이며 공식 보안 가이드의 특정 UI 요구사항으로 설명하지 않는다. 서버 인증·소유권·삭제 API를 추가하지 않아 이를 구현하거나 검증한 것으로 취급하지 않는다.

- `npm test`: 전체 31건 통과. 내 정보의 미확정/빈 상태, 현재 확정본·지원서별 상태/경로, 프로필 변경 재검토, 삭제 취소·Escape 및 실행 시 범위·포커스·스토리지 미사용 검증을 추가했다.
- `npm run lint`, `npm run build`: 통과. 새 의존성 없음.
- 내장 브라우저에서 시험용 프로필·지원서로 요약 화면 연결, 네이티브 모달과 Tab/Shift+Tab, Escape 후 삭제 버튼 포커스 복원, 삭제 후 목록 제목 포커스를 검증했다. 취소 후 포커스가 빠지는 문제를 보완해 재검증했다.
- 좁은 화면의 큰 글씨에서 가로 넘침을 확인했다. 실제 기기·스크린리더, 로그인·저장·철회·탈퇴와 서버 인가·삭제 검증은 후속 작업이다.
