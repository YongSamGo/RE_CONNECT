# 보안 지식 베이스 경로 전환

공식 보안 자료는 프로젝트 루트의 `SW개발보안_obsidian/Security/INDEX.md`에서 탐색합니다. Obsidian에서는 루트의 `SW개발보안_obsidian/`를 볼트로 엽니다. 문서·PR 템플릿·에이전트 지침도 이 경로를 기준으로 합니다.

## 반영 순서

1. PR #159의 새 볼트·PDF·변환 도구를 먼저 반영합니다. 이 참조 전환은 #159에 의존하며 새 볼트가 없는 상태에서 단독 병합하지 않습니다.
2. `AGENTS.md`에는 기존 팀 지침과 새 지식 베이스 안내를 함께 둡니다. #159와의 충돌을 해결할 때 팀 지침을 삭제하지 않습니다.
3. README·PR 템플릿·프론트 인계 문서의 참조를 새 경로로 통일합니다. #159의 변환 도구 `legacy/security_kb/build.py`는 이미 루트의 새 볼트를 사용하므로 경로를 다시 바꿀 필요가 없습니다.
4. 양쪽 자료의 차이와 개인 파일을 확인하고 필요한 내용을 보존합니다. 새 인덱스에서 원문·이미지·PDF가 열리는지 확인합니다.
5. 기존 볼트 삭제는 사용자가 별도 변경으로 반영합니다. 삭제 후 남은 참조와 검사 설정을 정리하고 CI를 확인합니다.

## 기존 볼트 삭제 전 확인

PR #159의 `7ef539e`와 전환 작업의 develop 기준 `6431dfe`를 비교하면 기존 `team-vault/SW개발보안_obsidian/`와 새 볼트는 각각 989개 파일입니다. 상대경로가 같은 982개는 Git blob이 같고 다음 7개는 다릅니다. 이 숫자는 비교 시점의 기록이며 삭제 직전에 다시 비교해야 합니다.

- `.obsidian/graph.json`
- `Security/INDEX.md`
- `Security/Python-2023/제1장-개요/제1절-배경/002-제1절-배경.md`
- `Security/Python-2023/제2장-시큐어코딩-가이드/제1절-입력데이터-검증-및-표현/006-1.-SQL-삽입.md`
- `Security/Python-2023/제2장-시큐어코딩-가이드/제2절-보안기능/024-2.-부적절한-인가.md`
- `Security/Python-2023/제2장-시큐어코딩-가이드/제3절-시간-및-상태/041-2.-종료되지-않는-반복문-또는-재귀-함수.md`
- `Security/Python-2023/제2장-시큐어코딩-가이드/제4절-에러처리/043-1.-오류-메시지-정보노출.md`

원문을 기계적으로 덮어쓰지 말고 차이를 PDF와 대조합니다. `.obsidian/workspace.json`처럼 Git에서 제외된 개인 상태, 미추적 노트·첨부 파일은 위 비교에 포함되지 않습니다. 필요한 개인 파일은 로컬에 별도 보관하며 공개 저장소에 추가하지 않습니다.

## 검사 설정

기존 볼트가 추적되는 동안 `.gitleaks.toml`의 기존 경로 예외는 유지합니다. 이 예외는 기존 자료 검사에만 쓰며 작업 지침이나 탐색 경로가 아닙니다. 기존 볼트를 삭제하는 변경에서 해당 예외도 제거합니다.

새 볼트의 예외는 #159와 동일한 공식 교육 예시 Markdown 한 파일과 원시 추출 한 파일로 한정합니다. 새 볼트 전체를 검사에서 제외하지 않습니다. 숨은 문자 검사와 이력 비밀값 검사의 처리 여부는 #159에서 별도로 확인하며, 경로 전환만으로 CI 실패가 해결되지는 않습니다.

전환 후 `git grep -n -I 'team-vault' -- . ':!team-vault'`로 남은 참조를 확인합니다. 전환 설명인 이 문서, README의 이전 사본 안내, 삭제 전까지의 gitleaks 예외 이외에 기존 경로를 탐색 대상으로 안내하는 곳이 없어야 합니다.
