# 카카오 로그인 앱 설정 (W01-04)

> 기준일: 2026-10-17 · 담당: C(백엔드·보안), 협력 A(기획·프론트엔드) · 관련 이슈: #7 → 후속 #72(W10-01 카카오 인증 왕복 검증)
>
> 근거: [카카오 로그인 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api) (2026-10-17 확인), [API 계약](README.md#26-로그인-저장-흐름)의 `/auth/kakao/start`·`/auth/kakao/callback`

카카오 디벨로퍼스 콘솔에 둘 설정과 그 이유를 적는다. 키·시크릿 값과 시험 계정 정보는 여기에 적지 않는다(7절).

## 1. 결정

| # | 항목 | 결정 | 이유 |
|---|---|---|---|
| K1 | 앱 구성 | 개발용 앱과 운영용 앱을 따로 만든다. 소유자는 C, A는 개발용 앱 팀원으로 초대한다 | 개발 키를 팀원 PC에 나눠도 운영 시크릿은 운영 서버 밖으로 나가지 않는다. 회원번호는 앱마다 달라 개발·운영 계정이 섞이지 않는다 |
| K2 | 동의 항목 | 개인정보 동의 항목을 켜지 않는다. 회원번호(`id`)만 쓴다 | 내부 User는 카카오 식별 연결만 가진다([02 Data Design](../../Plan/02_Data_Design.md#1-핵심-엔터티)). 닉네임·이메일·프로필 사진은 기능에 필요 없다 |
| K3 | 신원 확인 | OpenID Connect를 켜지 않는다. 토큰 교환 후 `GET /v2/user/me`의 `id`만 읽고 액세스 토큰은 저장하지 않는다 | 회원번호 하나만 필요하다. ID 토큰 서명 검증·nonce 관리를 더하지 않는다 |
| K4 | Client Secret | 사용(ON)한다 | REST API 키만으로 토큰을 받을 수 없게 한다. ON이면 토큰 요청에 필수다 |
| K5 | PKCE | 쓰지 않는다 | 카카오 인가·토큰 요청에 `code_challenge`·`code_verifier`가 없다. 이 PR에서 계약의 "가능하면 PKCE" 문구를 뺐다. 세션 결합 1회용 state와 Client Secret으로 막는다 |
| K6 | Redirect URI | 서버 설정값 `KAKAO_REDIRECT_URI` 하나로 고정한다. 요청의 Host 헤더로 만들지 않는다 | 등록 목록과 다른 주소로 코드가 가지 않게 한다 |
| K7 | 로그아웃 | 서비스 세션만 끝낸다. 카카오계정 함께 로그아웃은 쓰지 않아 로그아웃 Redirect URI를 등록하지 않는다 | 공용 PC에서도 서비스 세션 회수로 충분하고, 등록 주소를 줄인다 |
| K8 | 탈퇴 연결 끊기 | 어드민 키를 발급·보관하지 않는다. 연결 끊기 방식은 #78(W10-07)에서 정한다 | 어드민 키는 앱의 모든 사용자를 다룰 수 있어 노출 피해가 크다. 액세스 토큰으로도 `POST /v1/user/unlink`를 부를 수 있다 |
| K9 | 재인증 | `purpose=reauth`는 인가 요청에 `prompt=login`을 붙인다 | 이미 로그인된 카카오계정으로 자동 통과하지 않게 한다. 카카오톡 인앱 브라우저는 지원하지 않으므로 W10-01에서 그 경우를 시험한다 |

## 2. 콘솔 설정 (두 앱 공통)

1. 앱 만들기 → 앱 이름 `다시잇다(개발)` / `다시잇다`
2. 제품 설정 → 카카오 로그인 → 활성화 ON
3. 제품 설정 → 카카오 로그인 → 동의항목: 모두 사용 안 함 (K2). 콘솔이 하나 이상을 요구하면 설정하지 말고 이 문서와 #7에 기록한 뒤 다시 정한다
4. 제품 설정 → 카카오 로그인 → OpenID Connect: OFF (K3)
5. 제품 설정 → 카카오 로그인 → 보안 → Client Secret: 코드 생성, 활성화 ON (K4)
6. 제품 설정 → 카카오 로그인 → Redirect URI: 3절 목록만 등록
7. 앱 설정 → 플랫폼 → Web 사이트 도메인: 3절의 출처만 등록
8. 로그아웃 Redirect URI·연결 끊기 알림 콜백: 등록하지 않음 (K7, K8)

## 3. Redirect URI 목록

경로는 API 계약의 `/api/v1/auth/kakao/callback`이다. 출처는 세션 쿠키를 받는 화면 출처와 같아야 한다.

| 앱 | Redirect URI | 쓰임 |
|---|---|---|
| 개발 | `http://localhost:8000/api/v1/auth/kakao/callback` | 백엔드 단독 실행(`uvicorn`, 기본 포트 8000)으로 W10-01 왕복 시험 |
| 개발 | `http://localhost:5173/api/v1/auth/kakao/callback` | 프론트엔드 개발 서버가 `/api`를 백엔드로 넘길 때(#13). 포트가 바뀌면 함께 고친다 |
| 운영 | `https://<운영 도메인>/api/v1/auth/kakao/callback` | 도메인 확보(#6 W01-03) 뒤 등록한다. 그 전까지 운영 앱은 만들기만 한다 |

`127.0.0.1`·사설 IP·와일드카드 주소는 등록하지 않는다.

## 4. 취소·실패 경로

| 상황 | 카카오가 보내는 값 | 서버 처리 |
|---|---|---|
| 동의 화면에서 취소 | `?error=access_denied&error_description=...&state=...` | state를 확인·삭제하고 토큰 교환 없이 `/auth/result?purpose=<목적>&status=cancelled` |
| 그 밖의 `error` | `?error=<코드>&state=...` | `status=failed`. `error_description`은 로그·Location에 남기지 않는다 |
| state 없음·불일치·만료·재사용 | — | 토큰 교환 없이 `status=failed` (API 계약 §2.3) |

## 5. 시험 계정

- 팀원 계정 외에 이 앱에 처음 로그인하는 카카오계정 1개를 준비해 첫 동의 화면·취소·재로그인·연결 끊기를 확인한다(W10-01).
- 시험 계정은 팀원이 직접 만든다. 계정 정보·회원번호는 저장소·이슈·PR에 적지 않는다.
- 시험 후 카카오계정 → 연결된 서비스 관리에서 연결을 끊어 처음 상태로 되돌린다.

## 6. 환경변수

| 이름 | 값 | 위치 |
|---|---|---|
| `KAKAO_REST_API_KEY` | 앱 키 → REST API 키 | `.env` (개발 앱), 운영 서버 비밀값 저장소 (운영 앱) |
| `KAKAO_CLIENT_SECRET` | 2절 5번의 코드 | 위와 같음 |
| `KAKAO_REDIRECT_URI` | 3절 목록 중 그 환경의 주소 | 위와 같음 |

코드에서 읽기 시작하는 것은 #72(W10-01)다. 이름은 [.env.example](../../.env.example)에 있다.

## 7. 비밀 관리

- REST API 키·Client Secret은 루트 `.env`에만 둔다. 코드·테스트·로그·이슈·PR·채팅에 적지 않는다([개발 환경 7절](../development.md#7-비밀값)).
- 개발 앱 키는 소유자(C)가 팀원에게 직접 전달하고, 팀원은 콘솔에서 직접 확인할 수 있게 개발 앱 팀원으로 둔다.
- 운영 앱 키는 운영 서버에서만 설정한다. 노출이 의심되면 Client Secret을 다시 만들고 서버 값을 바꾼다.
- `VITE_` 변수로 넘기지 않는다. 인가 URL은 서버가 만든다.
