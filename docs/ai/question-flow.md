# 대화 질문 흐름

> 기준일: 2026-10-29 · 코드: [questions.py](../../backend/app/modules/generation/questions.py) · 시험: [test_questions.py](../../backend/tests/test_questions.py)

다음 질문은 서버 규칙과 고정 질문 목록으로 고른다. 모델은 사용자의 답에서 경험을 뽑는 데만 쓰고, 질문 선택이나 질문 문장 생성에는 쓰지 않는다. 대화 한 번에 모델 호출은 경험 추출 한 번이다.

## 진행 규칙

- 한 번에 질문 하나. 질문 문구는 ID가 붙은 고정 문장이다.
- 고른 질문 ID를 그 답 턴에 남긴다(`ConversationTurn.next_question`, 내부 문맥에만 저장하고 공개 API로 내보내지 않는다). 이 칸이 생기기 전 코드는 이 칸이 든 대화를 읽지 못하므로, 이 변경을 되돌려 배포할 때는 진행 중인 체험 문맥(Redis)을 비운다. 같은 질문은 정해진 횟수까지만 묻는다. 경험별 후속 질문은 `<질문 ID>:<경험 ID>`로 경험마다 따로 센다.
- 답변 상태는 "없음"(`없어요`·`해 본 적 없어요`), "모르겠음"(`잘 모르겠어요`·`기억이 안 나요`), 일반 답으로 나눈다. 정보 추출이 아니라 다음 질문 분기에만 쓴다.
- 추천에 필요한 항목(경험·희망 지역·활동 유형)이 모두 있으면 질문을 끝내고 프로필 확인으로 넘긴다. 이 조건은 화면(`next_step`)과 같다.
- 희망 지역·활동 유형은 그 질문(`cond.region`·`cond.type`)에 대한 답에서만 정해진 목록·낱말과 맞춰 초안에 넣는다. 모델을 쓰지 않고, 이미 고른 값은 덮지 않는다. 근거로 그 답의 메시지 ID를 남기고, 사용자가 프로필에서 확정하기 전까지 초안이다.

## 질문과 분기

| 상황 | 질문 ID | 횟수 |
| --- | --- | --- |
| 첫 질문 | `exp.first` 기억에 남는 일 한 가지 | 1 |
| 경험이 없고 답이 "없음" | `exp.other` 가게 운영·봉사·모임·돌봄 등 다른 경험 안내 → `exp.hint` | 각 1 |
| 경험이 없고 답이 "모르겠음" | `exp.hint` 예시 문장 → `exp.other` | 각 1 |
| 경험이 없고 답에서 경험을 못 찾음 | `exp.retry` 구체적으로 → `exp.hint` → `exp.other` | 각 1 |
| 위를 다 물었는데도 경험이 없음 | `exp.later` 나중에 말해도 됨, 프로필에서 조건 먼저 선택 | 반복 |
| 최근 경험에 기간이 없음 | `exp.duration` 언제부터 언제까지·몇 년쯤 | 경험마다 1 |
| 최근 경험에 맡은 일이 없음 | `exp.tasks` 직접 맡은 일(조리·응대·계산·재고 관리 예시) | 경험마다 1 |
| 후속 질문을 다 함 | `exp.more` 다른 일·봉사·모임 활동 | 1 |
| 희망 지역이 없음 | `cond.region` 구·시 이름으로. 서울·경기·인천 시·군·구 목록과 맞춤, 시·도만 말하면 시·도 전체 | 2 |
| 활동 유형이 없음 | `cond.type` 일자리·봉사·둘 다 | 2 |
| 그래도 못 읽음 | `cond.profile` 프로필 화면에서 고르도록 안내 | 반복 |

음성 인식이 지명을 비슷한 소리의 다른 말로 적는 경우가 있다(2026-10-29 서울 25개 구 음성 합성 → 인식: "마포구요" → "맛보고요", "영등포구요" → "영등포고요"). 정확히 맞는 이름이 없을 때만, 25자 이하의 짧은 답에서 글자 단위로 가장 비슷한 지명을 고른다. 비슷한 소리(ㅂ/ㅍ, ㄱ/ㅋ, ㅗ/ㅜ 등)는 차이를 반만 센다. 시·도를 말했으면 그 안에서 차이 1.5까지, 말하지 않았으면 0.5까지만 받고, 끝의 구·시·군도 비슷해야 하며, 두 후보가 비슷하게 가까우면 고르지 않는다. 페르소나 인터뷰 43턴에서 엉뚱하게 고른 경우는 없었다.

지역 이름은 세 시·도에서 겹치지 않는다. "성남"처럼 끝 글자를 뺀 말도 받지만, 다른 낱말의 일부("남동생"의 "남동")는 받지 않도록 뒤에 조사·단위·공백이 올 때만 받는다. 한 글자 어간(중구 → 중)은 받지 않는다.

"모르겠음"이나 "없음"으로 답해도 같은 후속 질문을 다시 하지 않고 다음 항목으로 넘어간다. 경험이 없다고 답해도 질문을 반복하지 않고 `exp.later`로 끝낸다.

## 아직 반영하지 않은 것

질문 목록·분기 보완 제안 중 아래는 프로필 항목 추가나 화면 변경이 함께 필요해 이번 변경에 넣지 않았다.

- **나머지 활동 조건 질문**(요일·시간대·주당 시간·시작일·참여 기간·이동 시간·급여 여부·자격·교육): 지금은 대화에서 이 값을 뽑지 않고 프로필 화면에서 직접 고른다. 대화로 받으려면 선택지 입력(요일·시간 버튼 등)과 검증 규칙을 화면에 두는 편이 안전하다. 시간대·시작일·참여 기간·증빙 준비 상태는 프로필 항목도 없다.
- **애매한 조건 답 분기**(예: "아무 때나 괜찮아요" → 평일·주말·시간대 확인, "컴퓨터 조금 해요" → 작업별 수행 수준): 위 조건 항목이 생긴 뒤 같은 방식(고정 질문 + 횟수 제한)으로 넣는다.
- **앞선 답과 충돌할 때 확인 질문**: 조건 항목이 대화에서 채워져야 충돌을 알 수 있다.
- **"희망 업무"·"상대한 사람"·"다시 하고 싶은 일" 질문**: 답을 저장할 프로필 항목이 없어, 물어도 결과에 남지 않는다.
- **관심 공고별 추가 질문**: 공고의 필수조건·서류와 프로필을 대조해 빈 항목만 묻는 단계. 자격 대조 결과의 "확인 필요" 항목을 질문으로 바꾸는 방식이 맞다.
- **경험이 없어도 추천**: 지금 추천은 경험이 하나 이상 있어야 한다(`missing_for_recommendation`). 경험 없이 볼 수 있는 기회를 열려면 추천 조건을 바꿔야 한다.
- **예외적인 모델 질문 생성**: 고정 질문으로 처리하지 못한 사례를 모은 뒤 필요하면 검토한다. 넣을 때는 허용 항목·길이·개인정보 요청 여부를 서버에서 검증하고, 실패하면 고정 질문으로 되돌린다.
