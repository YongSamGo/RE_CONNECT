# 경험·질문·지원서 근거 검증 (W04-03)

관련 이슈: #30. [LLM Adapter](../../backend/app/adapters/llm.py) 뒤에서 사용하는 내부 서비스이며 공개 HTTP 계약을 추가하지 않는다. 프롬프트 버전은 `grounded-v1`이다.

## 처리 범위

| 처리 | 모델이 선택하는 것 | 서버가 검사·반환하는 것 |
| --- | --- | --- |
| 경험 추출 | 사용자 턴 번호·원문 부분 문자열, 기존 경험 ID 또는 null | 실제 전송된 같은 턴의 원문인지 확인. 기존 ID는 호출자가 전달한 목록에 있어야 하고 기존 설명과 일치해야 함. 새 경험 ID는 null인 `ExperienceInput` 미리보기 |
| 다음 질문 | 현재 누락된 추천 필드 하나 | `experiences`, `preferred_regions`, `activity_types` 중 요청한 누락 필드만 허용. 질문 문장은 서버의 고정 문구 한 개. 누락 항목이 없으면 모델 호출 없이 null |
| 지원서 미리보기 | 확정 사실 목록의 ID | 확정 경험·기간·역량·자격·교육에서 선택한 사실만 서버의 고정 문구로 조립. 근거 프로필 ID·버전은 서버 입력에서 반환 |

세 처리의 고정 지시문을 분리하고, 사용자·저장 자료는 JSON 데이터로 `user` 턴에만 전달한다. Adapter의 JSON Schema 검증 이후에도 결과 스키마와 근거를 다시 검사한다. 도구 실행·계정 변경·프로필 확정·DB/Redis 저장 기능은 없다.

경험·지원서 결과의 `requires_confirmation`은 항상 true다. 원문 인용은 실제 사실인지 또는 해당 경험과 연결되는지의 의미 판단을 대신하지 않는다. 특히 부정·가정·다른 경험에 관한 기간·직무명과 자격 보유의 차이는 사용자 확인이 필요하다.

## 전송 최소화와 제외

- 경험 추출은 사용자 텍스트만 받는다. 이전 assistant 출력이나 시스템 메시지를 경험 근거로 전달하지 않는다. 기존 경험은 안전한 설명·ID만 비교 자료로 전달한다.
- 알려진 주민번호·전화·이메일·진단명·가족사·직접 인젝션 패턴, 숨은 문자, 빈 값, 과대 입력을 발견하면 해당 턴 전체를 제외한다. 인덱스를 바꾸지 않고 `excluded_turn_indices`로 호출자에게 알려 직접 수정을 안내할 수 있게 한다. 안전한 턴이 하나도 없으면 모델을 호출하지 않는다.
- 턴은 최대 64개, 각 텍스트는 최대 4,000자, 전송할 사용자 텍스트 합은 UTF-8 12,000바이트다. 실제 요청의 지시문·스키마·기존 설명을 포함한 최종 한도는 Ollama Adapter가 추가 검사한다.
- 지원서에는 출생연도·거주지·요일·이동 조건·사용자 ID·프로필 ID/버전을 모델에 전달하지 않는다. 알려진 개인정보·지시문이 들어 있는 확정 사실도 전송에서 제외한다.
- 예외 메시지와 로그에 입력·출력 원문을 기록하지 않는다. 근거가 없거나 잘못되면 고정 메시지의 `LLMInvalidOutputError`를 반환한다. Adapter의 시간 초과·불가용 예외를 그대로 전달하며 자동 재시도·가상 성공으로 대체하지 않는다.

이 필터는 표본 중심의 보수적인 문자열 검사다. 모든 개인정보·다른 표현의 질환/가족사·우회 지시를 탐지하는 의미 분석기가 아니다. 정상 문장을 제외하거나 위험 문장을 놓칠 수 있다. 제외된 문장에 있던 유용한 활동 조건은 임의 복원하지 않고 사용자가 직접 수정해야 한다.

## 호출자의 선행 책임

`GroundedGenerationService`는 아직 라우터나 앱의 공개 경로에 연결하지 않았다. #37·#67 등 실제 업무 서비스에서 연결할 때 아래 조건을 먼저 적용한다.

1. 세션 소유권·AI 동의·호출 한도를 검사한 뒤 사용자 턴과 해당 주체의 기존 경험만 전달한다.
2. `ConfirmedProfileSnapshot`은 서버가 조회하고 확정을 확인한 자료로만 만든다. HTTP 요청 본문으로 받아 확정을 증명하는 타입으로 사용하지 않는다. 타입 이름 자체가 소유권·확정 검사를 수행하지는 않는다.
3. 실행 후 세션 수명·삭제 여부·현재 리비전·확정 프로필 버전을 다시 검사한 뒤 미승인 초안에만 반영한다. #27·#37·#67의 저장 경합 경계와 연결한다.
4. `excluded_turn_indices`를 보고 개인정보를 제외한 직접 입력을 안내한다. 모델 검증 실패는 입력을 유지하고 직접 작성으로 연결한다.
5. 사용자 확인·편집·최종 승인은 별도 API에서 처리한다. 출력은 일반 텍스트로 렌더링하고 HTML·명령·URL로 해석하지 않는다.

현재 경험 추출은 원문 인용 방식이며 전체 `ProfileContent`의 지역·선호·연령·자격을 구조화하는 구현은 아니다. 지원서도 확정 사실의 목록형 미리보기이며 공고별 자연스러운 자기소개·지원동기를 생성하는 #67 전체 구현을 대신하지 않는다. 새 경험의 서버 ID 부여와 직접 편집은 후속 업무 서비스에서 처리한다.

## 검증과 다음 확인

`backend/`에서 실행한다.

```powershell
.venv/Scripts/python -m pytest tests/test_grounded_generation.py -q
.venv/Scripts/python -m pytest -q
```

정상 원문, 원문에 없는 기간·역량, 타 경험 ID·중복 ID, 턴 바꿔치기, 승인 필드 삽입, 개인정보 요청 질문, 없는 확정 사실, 저장된 지시문, 호출 한도, 실패 시 재시도 없음 등을 시험한다. P03·P07·P08 표본으로 알려진 진단명·인젝션·불필요 개인정보 턴의 전송 제외와 근거 참조 거절을 확인한다. 기존 Ollama Adapter와의 연결은 가짜 HTTP 전송 계층으로 검사한다.

실제 Ollama/EC2 호출, 한국어 추출 정확도, P01~P08 전체 기대 프로필의 의미 일치, 자연스러운 지원서 품질, 실제 API 동의·소유권·종료/삭제 경합은 미검증이다. #29의 런타임·#10의 표본 준비 상태와 구분하며, 이 코드만으로 #30 전체 통과나 후속 기능 완료로 표시하지 않는다. #34에서 모델·프롬프트 버전을 고정하고 품질·지연을 실측해야 한다.

관련 보안 기준은 오류 메시지 정보노출(ERR-01), 프롬프트 인젝션(LLM-01), 민감정보 노출(LLM-02), 부적절한 출력 처리(LLM-05), 잘못된 정보/환각(LLM-09)이다. LLM 번호는 저장소 스킬의 OWASP 대응 항목이며 KISA 약점 번호와 구분한다. 점검 보고서·도구 출력은 `security-reports/`에만 보관한다.
