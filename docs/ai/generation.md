# 경험·질문·지원서 근거 검증 (W04-03)

관련 이슈: #30. [LLM Adapter](../../backend/app/adapters/llm.py) 뒤에서 사용하는 내부 서비스이며 공개 HTTP 계약을 추가하지 않는다. 프롬프트 버전은 `grounded-v3`다(v2: 경험이 아닌 문장 목록·짧은 구절 인용, v3: 표시용 요약·표준 태그 선택 추가. [2026-10-22 예비 측정](extraction-eval-2026-10-22.md), [2026-10-28 EC2 측정](extraction-eval-2026-10-28.md)).

## 처리 범위

| 처리 | 모델이 선택하는 것 | 서버가 검사·반환하는 것 |
| --- | --- | --- |
| 경험 추출 | 사용자 턴 번호·원문 부분 문자열(설명·기간·기술), 표시용 요약, 서버가 보낸 표준 태그 중 선택, 기존 경험 ID 또는 null | 설명 인용이 원문에 없으면 결과 전체를 거절. 기간·기술 인용은 각자 가리킨 턴의 원문에 있을 때만 남김(같은 일의 세부 내용을 다른 턴에서 말해도 묶임, 제외된 턴은 근거 불가). 요약은 근거 턴과 대조해 통과할 때만 설명으로 쓰고 아니면 원문 인용으로 되돌림. 기간은 서버가 "35년"·"약 30년"으로 표기. 표준 태그는 요청에 보낸 목록에 있는 것만 남김. 기존 ID는 호출자가 전달한 목록에 있어야 하고, 그 경험의 세부 내용(태그·기간)으로만 쓰며 저장된 설명은 바꾸지 않음. 경험마다 근거 턴 번호(`source_turns`)를 함께 반환 |
| 다음 질문 | 현재 누락된 추천 필드 하나 | `experiences`, `preferred_regions`, `activity_types` 중 요청한 누락 필드만 허용. 질문 문장은 서버의 고정 문구 한 개. 누락 항목이 없으면 모델 호출 없이 null |
| 지원서 미리보기 | 확정 사실 목록의 ID | 확정 경험·기간·역량·자격·교육에서 선택한 사실만 서버의 고정 문구로 조립. 근거 프로필 ID·버전은 서버 입력에서 반환 |

세 처리의 고정 지시문을 분리하고, 사용자·저장 자료는 JSON 데이터로 `user` 턴에만 전달한다. Adapter의 JSON Schema 검증 이후에도 결과 스키마와 근거를 다시 검사한다. 도구 실행·계정 변경·프로필 확정·DB/Redis 저장 기능은 없다.

경험·지원서 결과의 `requires_confirmation`은 항상 true다. 원문 인용은 실제 사실인지 또는 해당 경험과 연결되는지의 의미 판단을 대신하지 않는다. 특히 부정·가정·다른 경험에 관한 기간·직무명과 자격 보유의 차이는 사용자 확인이 필요하다.

## 요약·표준 태그 검사 (v3)

프로필에 말투가 그대로 들어가고 표현이 달라 공고와 매칭이 안 되는 문제로 추가했다. 원문 글자 그대로만 받던 방식에서 "원문에 근거한 다듬기"로 바뀌므로 아래 검사를 둔다([wording.py](../../backend/app/modules/generation/wording.py)).

- **요약:** 40자 이하, 숨은 문자·개인정보 패턴 없음, 줄바꿈 없음. 요약의 수(아라비아·한자어)는 근거 턴에 있는 수여야 한다(삼십오 → 35). 자격·면허·급수 표현은 넣을 수 없다. 두 글자 이상 단어는 앞 두 글자가 근거 턴에 있거나 사실을 더하지 않는 일반어(경력·업무·봉사 등)여야 한다. 하나라도 어기면 요약을 버리고 원문 인용을 쓴다. 형식이 이상한 요약 때문에 경험 전체를 버리지 않는다.
- **한계:** 의미를 이해하는 검사가 아니다. 근거 턴의 글자로 시작하는 다른 단어(예: "학교" → "학교장")는 통과할 수 있다. 그래서 결과는 계속 미승인 초안이고 사용자 확인을 거친다.
- **표준 태그:** 메시지 서비스가 역할 사전의 표준 기술 태그를 `standard_tags`로 함께 보낸다. 모델은 이 목록에서만 고를 수 있고, 서버는 목록에 없는 태그를 버린다. 사전을 읽지 못하면 빈 목록으로 보내고 원문 기술 구절만 남는다. 사전 자료는 서버 자료지만 사용자 데이터와 같은 `user` 턴 JSON으로 보내며 지시문에 넣지 않는다.
- **기간 표기:** "이십오 년" → "25년", "한 삼십 년"·"칠 년 정도" → "약 30년"·"약 7년". 단순한 기간 표현만 바꾸고 "마지막 팔 년"처럼 다른 말이 섞이면 원문을 그대로 둔다.
- **메시지 서비스:** 다듬은 문구는 원문 부분 문자열이 아니므로, 이번 턴의 사실인지는 생성 서비스가 대조한 `source_turns`로 확인한다(이전 턴만으로 경험을 되살리지 않는 규칙은 그대로).
- **여러 턴에 나눠 말한 경험:** 같은 대화 묶음 안에서는 세부 업무·기간 인용이 다른 턴에서 와도 그 턴의 원문에 있으면 받는다. 다음 메시지에서 기존 경험의 세부 내용을 말하면 모델이 그 경험 ID를 가리키고, 메시지 서비스는 그 경험에 **새 태그를 더하고 비어 있던 기간만 채운다.** 설명·기존 태그·사용자가 정한 기간은 바꾸지 않고, 그 메시지를 근거로 덧붙인다. 지워진 경험은 되살리지 않는다.
- **기간 정정:** "팔 년? 아니, 정규직은 육 년"처럼 고쳐 말하면 고친 뒤 구절만 기간으로 쓰고, 무엇을 고쳤는지 불명확하면 비운다. 합산·차이 계산은 하지 않는다. 이 두 항목은 #283(성욱 님)의 프롬프트 아이디어를 옮긴 것이다.

## 전송 최소화와 제외

- 경험 추출은 사용자 텍스트만 받는다. 이전 assistant 출력이나 시스템 메시지를 경험 근거로 전달하지 않는다. 기존 경험은 안전한 설명·ID만 비교 자료로 전달한다.
- 알려진 주민번호·전화·이메일·진단명·가족사·직접 인젝션 패턴, 숨은 문자, 빈 값, 과대 입력을 발견하면 해당 턴 전체를 제외한다. 인덱스를 바꾸지 않고 `excluded_turn_indices`로 호출자에게 알려 직접 수정을 안내할 수 있게 한다. 안전한 턴이 하나도 없으면 모델을 호출하지 않는다.
- 턴은 최대 64개, 각 텍스트는 최대 4,000자, 전송할 사용자 텍스트 합은 UTF-8 12,000바이트다. 실제 요청의 지시문·스키마·기존 설명을 포함한 최종 한도는 Ollama Adapter가 추가 검사한다.
- 지원서에는 출생연도·거주지·요일·이동 조건·사용자 ID·프로필 ID/버전을 모델에 전달하지 않는다. 알려진 개인정보·지시문이 들어 있는 확정 사실도 전송에서 제외한다.
- 예외 메시지와 로그에 입력·출력 원문을 기록하지 않는다. 근거가 없거나 잘못되면 고정 메시지의 `LLMInvalidOutputError`를 반환한다. Adapter의 시간 초과·불가용 예외를 그대로 전달하며 자동 재시도·가상 성공으로 대체하지 않는다.

이 필터는 표본 중심의 보수적인 문자열 검사다. 모든 개인정보·다른 표현의 질환/가족사·우회 지시를 탐지하는 의미 분석기가 아니다. 정상 문장을 제외하거나 위험 문장을 놓칠 수 있다. 제외된 문장에 있던 유용한 활동 조건은 임의 복원하지 않고 사용자가 직접 수정해야 한다.

## 호출자의 선행 책임

경험 추출·다음 질문은 [#37 메시지 서비스](../data/journey-messages.md)에 연결했다. 지원서 생성(#67) 등 후속 업무 연결에서도 아래 조건을 적용한다.

1. 세션 소유권·AI 동의·호출 한도를 검사한 뒤 사용자 턴과 해당 주체의 기존 경험만 전달한다.
2. `ConfirmedProfileSnapshot`은 서버가 조회하고 확정을 확인한 자료로만 만든다. HTTP 요청 본문으로 받아 확정을 증명하는 타입으로 사용하지 않는다. 타입 이름 자체가 소유권·확정 검사를 수행하지는 않는다.
3. 실행 후 세션 수명·삭제 여부·현재 리비전·확정 프로필 버전을 다시 검사한 뒤 미승인 초안에만 반영한다. #27·#37·#67의 저장 경합 경계와 연결한다.
4. `excluded_turn_indices`를 보고 개인정보를 제외한 직접 입력을 안내한다. 모델 검증 실패는 입력을 유지하고 직접 작성으로 연결한다.
5. 사용자 확인·편집·최종 승인은 별도 API에서 처리한다. 출력은 일반 텍스트로 렌더링하고 HTML·명령·URL로 해석하지 않는다.

현재 경험 추출은 원문 인용 방식이며 전체 `ProfileContent`의 지역·선호·연령·자격을 구조화하는 구현은 아니다. 지원서도 확정 사실의 목록형 미리보기이며 공고별 자연스러운 자기소개·지원동기를 생성하는 #67 전체 구현을 대신하지 않는다. 새 경험의 서버 ID 부여와 원자 초안 반영은 메시지 서비스, 직접 편집은 #39에서 처리한다.

## 검증과 다음 확인

`backend/`에서 실행한다.

```powershell
.venv/Scripts/python -m pytest tests/test_grounded_generation.py -q
.venv/Scripts/python -m pytest -q
```

정상 원문, 원문에 없는 기간·역량, 타 경험 ID·중복 ID, 턴 바꿔치기, 승인 필드 삽입, 개인정보 요청 질문, 없는 확정 사실, 저장된 지시문, 호출 한도, 실패 시 재시도 없음 등을 시험한다. P03·P07·P08 표본으로 알려진 진단명·인젝션·불필요 개인정보 턴의 전송 제외와 근거 참조 거절을 확인한다. 기존 Ollama Adapter와의 연결은 가짜 HTTP 전송 계층으로 검사한다.

실제 API 동의·소유권·종료/삭제 경합은 #37의 Redis/HTTP 시험에서 별도 검증했다. 실제 Ollama/EC2 호출, 한국어 추출 정확도, P01~P08 전체 기대 프로필 의미 일치와 자연스러운 지원서 품질은 미검증이다. 이 코드만으로 #30 전체 통과나 후속 기능 완료로 표시하지 않는다. #34에서 모델·프롬프트 버전을 고정하고 품질·지연을 실측해야 한다.

관련 보안 기준은 오류 메시지 정보노출(ERR-01), 프롬프트 인젝션(LLM-01), 민감정보 노출(LLM-02), 부적절한 출력 처리(LLM-05), 잘못된 정보/환각(LLM-09)이다. LLM 번호는 저장소 스킬의 OWASP 대응 항목이며 KISA 약점 번호와 구분한다. 점검 보고서·도구 출력은 `security-reports/`에만 보관한다.
