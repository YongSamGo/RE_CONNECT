# 한국어 음성 평가 표본 (W01-07 · #10)

> 기준일: 2026-10-27 · 담당: B(AI·데이터) · 대본: [eval/speech_cases.json](../../eval/speech_cases.json) · 스크립트: [eval/check_speech.py](../../eval/check_speech.py) · 쓰는 곳: #31(STT), #34(EC2 성능·품질), #102(음성 한도)

STT가 시니어의 경력 이야기를 얼마나 정확히 받아 적는지, 그리고 받아 적은 뒤에도 개인정보 필터가 그대로 동작하는지 본다. 운영 사용자의 음성은 평가에 쓰지 않는다. 동의한 팀원이나 지인이 가상 대본을 읽어 녹음한다.

## 대본

50문장이다. 페르소나 8명의 인터뷰 43턴 전부와, 개인정보 필터 사례(`privacy_filter_cases.json`) 중 인터뷰에 없는 7문장이다.

| 보는 것 | 사례 |
|---|---|
| 한글로 읽는 숫자(기간·시간·출생연도) | "삼십오 년", "주 삼십 시간", "1958년생", "육십삼년생" |
| 지역 이름 | 성동구·광진구, 안양시 동안구, 인천 남동구, 분당·성남시, 일산동구 |
| 자격증·직무 용어 | 전기기능사, 주택관리사 보, 한식조리기능사, 전산회계 1급, 금융투자상담사 |
| 짧은 대답 | P06 "노원구요.", "시간은 많아요." |
| 전사 후 필터 | 주민번호·전화번호를 한글 숫자로 읽은 문장, 가족사, 인젝션 문장(S36·S46) 등 7문장은 원문이 필터에서 제외된다 |

`keywords`는 전사에 반드시 남아야 하는 말이다. 채점은 띄어쓰기·문장부호를 빼고, 낱말 첫머리에서 단위어(년·시간·세 등) 앞에 오는 한글 숫자를 아라비아 숫자로 바꾼 뒤 비교한다. 그래서 "삼십오 년"과 "35년"은 같은 답으로 본다.

## 녹음

1. **동의를 먼저 받는다.** 목소리는 개인정보다. 녹음자에게 아래를 알리고 서면(메신저 기록 가능)으로 동의를 받는다.
   - 목적: 이 서비스의 음성 인식 품질 평가. 학습·화자 복제·외부 공유에 쓰지 않는다.
   - 수집 항목: 녹음 파일, 연령대(예: 60대), 녹음 기기 종류, 녹음 환경(조용함·생활 소음)
   - 보관: 커밋하지 않는 `security-reports/speech/`와 EC2 측정 기간에만 둔다. 대회 심사가 끝나면 지운다. 녹음자가 요청하면 바로 지운다.
   - 거부해도 불이익이 없다.
2. **대본을 출력해 읽는다.** `python -I eval/check_speech.py script`. 문장마다 파일 하나로 녹음하고, 파일 이름은 사례 ID로 한다(`S01.wav` …). 읽다가 틀리면 그 문장만 다시 녹음한다.
3. **형식.** 서비스 화면과 같은 조건으로 녹음하는 게 가장 좋다(브라우저 녹음, webm). 파일로 녹음하면 WAV 16kHz·16bit·mono가 안전하다. 한 파일 90초·6MiB 이하([녹음 한도](../../Plan/05_Engineering_Constraints.md)).
4. **녹음자 정보**는 파일 이름이나 폴더에 실명을 쓰지 않고 `R1`, `R2`처럼 기호로 적는다. 연령대·기기·환경은 `security-reports/speech/녹음자.md`에 따로 적는다.

시니어 목소리 대표성이 중요하다. 가능하면 60대 이상 녹음자를 한 명 이상 포함한다. 녹음자를 구하지 못하면 공개 데이터(Mozilla Common Voice 한국어, OpenSLR Zeroth-Korean 등)를 대신 쓸 수 있다. 다만 대본 문장이 달라 핵심어·필터 채점은 할 수 없고 CER만 본다. 내려받을 때 라이선스와 화자 연령 정보를 다시 확인한다.

## 실행 (EC2)

로컬 PC에서는 모델을 돌리지 않는다(메모리 부족). 음성 서비스와 같은 내부 네트워크에서 실행한다.

```bash
# 1) 전사: 녹음 폴더 → 전사 JSON (내부 주소 http://speech:8001)
python -I eval/check_speech.py transcribe security-reports/speech/R1/ --out security-reports/speech/R1.json

# 2) 채점: 백엔드 가상환경(개인정보 필터를 불러옴)
backend/.venv/bin/python -I eval/check_speech.py score security-reports/speech/R1.json
```

채점 결과는 사례별 CER·놓친 핵심어·필터 결과 표와 평균·중앙값 CER, 지연 중앙값·최대값이다. 원문이 필터에서 제외되는 문장이 전사 후 필터를 통과하면 "필터 실패"로 표시하고 종료 코드 1을 낸다. CER·핵심어는 합격선을 두지 않는다. EC2 실측 전에 기준을 정하지 않고, 결과를 보고 #34에서 정한다.

결과는 녹음자 기호·기기·환경·모델 revision과 함께 `docs/progress/` 기록 양식으로 남긴다. 전사 원문은 커밋하지 않고 요약 수치와 놓친 핵심어 유형만 적는다.

## 한계

- 대본을 읽는 말투는 실제 대화보다 또박또박하다. 실제 사용 조건보다 결과가 좋게 나온다.
- 한글 숫자 정규화는 단순 규칙이다. "열두 시간" 같은 고유어 숫자와 "공일공 일이삼사"처럼 단위 없이 읽는 번호는 바꾸지 않는다. 그래서 같은 번호를 아라비아 숫자로 받아 적으면 CER이 높게 나올 수 있다. 이 경우에도 필터 판정은 영향을 받지 않는다.
- 스크립트 자체는 합성 전사로만 시험했다(정확한 전사, 숫자·띄어쓰기를 바꾼 전사, 필터를 피한 전사). 실제 녹음·STT 결과는 아직 없다.
