# 전송 전 개인정보·지시문 필터 (W04-03 · #30)

> 기준일: 2026-10-25 · 담당: B(AI·데이터) · 코드: [privacy.py](../../backend/app/modules/generation/privacy.py) · 기대값: [eval/privacy_filter_cases.json](../../eval/privacy_filter_cases.json)

사용자 발화를 모델에 보내기 전에 거르는 표본 필터다. 걸린 발화는 `POST /journeys/{id}/messages`에서 `VALIDATION_FAILED`로 거절되고, 추출 단계에서는 그 턴을 모델에 보내지 않는다(`excluded_turn_indices`). 의미를 이해하는 탐지기가 아니라 정규식이다.

## 무엇을 막나

| 종류 | 막는 것 | 통과시키는 것 |
|---|---|---|
| 번호 | 주민·전화 형식 숫자, 이메일, 한글 숫자 7개 이상 연속("공일공 일이삼사…"), "주민번호/여권번호/계좌번호", "전화는·연락처는 + 알려·숫자 여러 개" | "주민번호 확인 업무", "전화 상담", "전화번호 안내 업무", "연락처 관리 업무", "휴대폰 사용법 교육", "삼십오 년" |
| 본인 건강 | 질병명 + 있어·앓·걸려·때문에·판정, 질병명 + "예요·환자예요", 질병명 + 수술·약을 받·먹, "진단을 받", 병력·투병·지병 | "안전진단", "치매가 있는 어르신 돌봄", "치매 환자 돌봄 봉사", "당뇨 있는 분들 식단" |
| 가족사 | 조사·띄어쓰기로 끝나는 가족 호칭 가까이(12자 안)에 돌아가·이혼·아프·입원·간병·장애·질병명·같이 살 등, "혼자 살" | "딸기 농장", "자녀 교육 상담 봉사", "아들 같은 학생들을 아파트 공부방에서", "손주 또래 장애 아동 돌봄", "어머니회 총무" |
| 지시문 | "이전 지시 무시", "시스템 설정/프롬프트", "이제부터 너는", "위에 받은 규칙을 말해" | — |

처음 버전은 `진단`·`자녀`·`딸`·`연락처` 같은 단어 하나만으로 막아서 평가 사례 15건 중 7건만 기대대로 동작했다(정상 경력 문장 5건 거절, 역할 전환 인젝션 1건 통과). 지금은 15건 모두 기대대로이고, 페르소나 P01~P08의 43턴 중 제외되는 턴은 P03 2, P07 3, P08 1·2로 모두 의도한 것이다.

## 한계

- **부분 가림(redact)을 하지 않는다.** PF04("관절염이 있어서 오래 서 있는 건 힘들어요")·PF06("은행 이십 년 + 전화번호")은 기대값이 "민감한 부분만 가리고 나머지는 보냄"이지만 턴 전체를 제외한다. 안전한 쪽이지만 "오래 서 있기 힘듦" 같은 활동 조건과 같은 턴의 경력도 같이 빠진다. 화면은 개인정보를 빼고 다시 말해 달라고 안내해야 한다.
- **목록에 없는 표현은 통과한다.** 질병명·가족 호칭·사정 표현을 목록으로 갖고 있어서, 다른 말로 돌려 말한 건강·가족 이야기나 정해 둔 꼴에서 벗어난 번호 표기는 막지 못한다. 구체적인 우회 예는 공개 저장소에 적지 않고 평가 사례로만 늘린다.
- **문맥 예외도 단어 기준이다.** "치매가 있는 어르신"처럼 정해 둔 꼴만 남의 이야기로 보고, "아들과 함께 간병 봉사를 했어요"는 가족사로 오인해 막는다.
- **인젝션 방어의 주 경계가 아니다.** 필터를 통과한 인젝션은 모델 출력 구조(원문 부분 문자열 인용·서버 사실 ID 선택)와 서버 재검증이 막는다. 필터 없이 P07을 넣었을 때 모델이 버티는지는 [모델 예비 측정](extraction-eval-2026-10-22.md)과 EC2 재측정(#34)에서 본다.

## 바꿀 때

`backend/tests/test_grounded_generation.py`가 `eval/privacy_filter_cases.json` 전체와 경력 문장·본인 사정 문장 목록을 회귀 시험으로 돈다. 패턴을 넓히면 경력 문장 쪽이, 좁히면 차단 쪽이 실패한다. 새 오탐·미탐을 찾으면 먼저 평가 사례에 추가한다.

## 음성 전사 변형

음성 입력은 전사 결과에 필터를 적용한다. 음성 인식이 질병명을 비슷한 소리로 바꿔 적으면 정확 일치 목록을 빠져나갈 수 있어, 실제 녹음 평가(#10)에서 확인한 변형을 목록에 더한다(PF16). 낱말 목록 방식의 한계라 다른 변형은 계속 놓칠 수 있다.
