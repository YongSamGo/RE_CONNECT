## 1. 제약과 의사결정

- 개발자 3명. 역할은 기획·프론트엔드, AI·데이터, 백엔드·보안.
- 숙련도는 미확인이다. 별도 시험 대신 첫 실제 작업에서 병목을 확인한다.
- 외부 계정·API 승인·서버·도메인은 아직 없다.
- 10월 23일까지 인당 주당 약 14시간, 24~30일 인당 하루 최대 약 6시간.
- 제출 마감은 2026년 10월 30일 18시(한국시간), 개발 60%·보안 40%.
- 참가 트랙은 **A(자유주제)**다. 기존 자료의 트랙 표기 불일치는 이 기준으로 처리하고 공식 원본은 보존한다.
- 실제 공고량·승인 속도·로컬 모델의 한국어 품질·RAM/VRAM 요구량·지연·시니어 이용 성과를 가정하지 않는다.
- 사용자 지정 구조는 EC2 Docker Compose의 Nginx·FastAPI·Redis·Ollama + Qwen3·로컬 STT/TTS와 EC2 밖의 RDS PostgreSQL이다. 실제 AWS 리전·인스턴스·GPU·RDS 연결은 아직 준비·검증하지 않았다.

## 2. 위협 모델과 통제

| 신뢰 경계·위협 | 통제 |
|---|---|
| 브라우저 → API: 위조 ID·권한·과대 입력 | 서버 소유권·역할 검사, 스키마·크기 제한 |
| 브라우저 출력: 공고·AI 문장의 XSS | 일반 텍스트 렌더링, 임의 HTML 실행 금지 |
| 쿠키 인증: CSRF·세션 탈취·고정 | CSRF·Origin 검사, 안전한 쿠키, 로그인 시 교체·만료 |
| EC2 API → RDS: SQLi·과도한 권한·DB 연결 노출 | SQLAlchemy 바인딩, 정렬·연산 허용 목록, 최소 DB 권한, VPC 비공개 접근·TLS 인증서/호스트 검증 |
| 수집 → 외부: SSRF·XXE·과대 응답 | 고정 대상·리다이렉트 검사, DTD·외부 엔티티 차단, 시간·크기 제한 |
| API → 로컬 LLM/STT/TTS: 개인정보·인젝션·환각 | 최소 정보, 도구 접근 금지, JSON Schema·근거 참조 검증, 원문 로그·학습·화자 복제 금지 |
| 인터넷 → 모델 런타임: 인증 우회·모델 관리·GPU 남용 | Ollama·음성 서비스 포트 비공개, FastAPI를 통한 권한·한도·입력 검증, Ollama Cloud 비활성화 |
| 모델·런타임 준비: 공급망·변조·임의 코드 | 공식 배포원·라이선스 확인, 가중치 revision/digest·컨테이너/의존성 고정, 임의 모델·원격 코드 사용 금지 |
| 저장·백업: 개인정보·키 노출 | AES-256-GCM, 키 분리, 접근권한, 암호화 백업 |
| 종료·삭제 ↔ 처리 완료: 재생성 | 저장 직전 활성 상태·버전 재검사, 만료 자료 폐기 |
| 공개 AI: GPU/CPU·메모리 고갈·서비스 남용 | IP·세션·계정·전역 한도, LLM/STT/TTS 공유 자원 슬롯·입력/출력·시간 제한 |
| 운영자: 권한 남용 | MFA·서버 권한·감사, 개인 본문 조회 기능 없음 |

암호화는 검증된 라이브러리를 사용하고 매번 새 nonce를 생성한다. 키 버전과 암호화 대상 식별자를 기록한다. 키는 저장소·DB·DB 백업과 분리하며 복구용 키의 별도 보관 절차를 둔다.

세션 쿠키는 `Secure`, `HttpOnly`, `SameSite=Lax`를 적용하고 세션 식별자를 URL·브라우저 영구 저장소에 넣지 않는다. 로그인·권한 상승 시 세션을 교체한다. 인증 세션은 유휴 30분·절대 12시간을 초기 기본값으로 두며 체험 자료의 유휴 30분·최대 2시간 수명은 별도로 적용한다. 운영자 MFA는 인증 세션에 결합하고 세션 교체·만료·권한 회수 시 효력을 잃는다.

정상 사용자와 운영자는 서버 역할로 구분한다. 최초 운영자 권한·MFA 등록과 복구는 팀의 제한된 관리 절차로 수행한다. 관리 API 호출마다 역할과 MFA를 검사하며 화면 숨김만으로 통제하지 않는다.

개인정보 전달은 최소화하고 연락처·주민등록번호·상세 병력 등 불필요한 입력은 로컬 AI 입력·저장 전에 탐지·안내한다. 패턴 필터가 모든 개인정보를 탐지한다고 주장하지 않는다. 자체 AI 처리와 AWS EC2/RDS 저장·리전·백업을 안내하고, 로컬 추론을 사용자 기기 내 처리나 AWS 보관 없음으로 설명하지 않는다.

Ollama Cloud는 `OLLAMA_NO_CLOUD=1`로 비활성화한다. 모델 추론용 포트·관리 API를 공개하거나 사용자 요청으로 모델·런타임 주소·가중치 URL을 바꾸지 않는다. 모델 준비 다운로드와 운영 추론 통신을 구분하고 사용자 내용의 외부 AI 추론 전송이 없는지 확인한다.

모델 볼륨은 가중치 전용이며 음성·대화·프로필 저장에 사용하지 않는다. 음성의 메모리/tmpfs 처리·swap·코어 덤프·컨테이너 디버그 로그가 임시 개인정보를 디스크·스냅샷에 남기는지 확인한다. 로컬 모델 사용만으로 민감정보 보관·유출 위험이 없어졌다고 판단하지 않는다.

## 3. 운영 기본값

| 항목 | 초기 값·동작 |
|---|---|
| 일반 JSON 요청 | 최대 64KiB |
| 대화 입력 | 1회 최대 2,000자 |
| 녹음 | 1회 최대 90초·6MiB |
| 공고 본문 | 최대 5,000자 |
| 추론 자원 슬롯 | 사용자별 동시 1개, EC2 전체 LLM/STT/TTS 공유 슬롯 초기 1개. 실측 후 조정 |
| 일반 API | 주체/IP별 분당 60회 |
| 비회원 생성·전사 | IP별 하루 60회 |
| 회원 생성·전사 | 계정별 하루 60회 |
| TTS | 주체/IP별 하루 60회, 요청당 최대 2,000자 |
| 전체 로컬 추론 실행 | 하루 500회. LLM·STT·TTS와 재시도 포함 |
| AI 처리 제한시간 | 요청당 최대 60초 |
| 자동 재시도 | 일시 오류에 최대 1회, 전체 제한시간 내 |
| 공고 확인 지연 | 48시간 초과 시 추천 보류·운영자 확인 |
| 백업 | RDS 자동 백업 7일 보관 기본값, 저장 암호화·복구·삭제 재적용 검증. 수동 스냅샷은 별도 목록·만료 관리 |

수치는 정상 여정의 실제 사용량과 EC2 부하 시험을 거쳐 조정한다. 재시도·TTS·STT도 실행량에 포함한다. 하루 500회는 공급자 과금 쿼터가 아닌 애플리케이션 자원·남용 통제 기본값이다. EC2 실행시간·GPU·EBS·RDS·백업·네트워크 비용을 산정하며 인스턴스와 가동시간을 확정하기 전 비용을 보장하지 않는다.

IP 정보는 신뢰한 프록시에서만 받고 클라이언트의 위조 헤더를 신뢰하지 않는다. 한도·자원 슬롯 획득과 실행 집계는 Redis에서 원자적으로 처리한다. LLM·STT·TTS의 실제 공유 GPU/CPU 자원을 같은 슬롯 정책으로 제어하고 음성 서비스와 Ollama 자체 병렬 설정도 이에 맞춘다. 슬롯이 없으면 429를 반환하며 별도 상시 작업 큐를 만들지 않는다. 날짜별 한도는 한국시간 날짜를 기준으로 초기화한다.

한도 때문에 거절한 요청은 모델을 실행하지 않는다. 실제 런타임 호출 시도와 재시도는 각각 집계하고 동일 요청 ID의 응답 재사용은 새 실행으로 집계하지 않는다. Adapter·런타임의 재시도가 중첩되지 않게 한다. 메모리 부족·형식 오류·시간 초과를 무조건 재시도하지 않는다.

요청 취소·60초 제한시간 경과가 실제 GPU 작업 종료를 보장하지 않는다. 런타임의 작업 종료·중단을 확인하기 전 공유 자원 슬롯을 새 실행에 넘기지 않고, 완료 후에도 만료·삭제·취소된 체험의 결과는 폐기한다. 모델 준비 실패·메모리 부족은 503, 슬롯 부족은 429로 처리한다.

Redis 장애에서는 임시 개인정보 처리·호출 제한을 우회하지 않는다. 관련 기능을 중지하고 공개 공고 조회는 가능한 범위에서 유지한다.

로그에는 음성·대화·프로필·지원서 본문, 토큰·인가 코드·OTP·비밀키를 남기지 않는다. 요청 ID·기능·결과·지연·오류 코드 중심으로 기록한다. Nginx 콜백 접근 로그에도 인가 코드·state 등 쿼리스트링을 남기지 않는다.

RDS는 인터넷 공개 접근을 비활성화하고 EC2의 필요한 보안 그룹만 DB 연결을 허용한다. CA·호스트명 검증 TLS 연결과 최소권한 DB 계정을 사용한다. EC2 내부 Redis·모델 서비스도 지정된 내부 네트워크에서만 접근하도록 분리한다. 인증서 검증을 끄지 않고 개발 설정이 운영 HTTPS·접근통제를 우회하지 않게 한다.

RDS 복원은 EC2 모델/애플리케이션 복원과 구분한다. 자동 백업의 7일 수명 외에 수동 스냅샷·내보내기·복제본은 각각 보관·삭제 목록을 유지한다. 임시 개인정보·로그·키는 DB/EC2 백업에 섞이지 않도록 범위를 분리하고 복구 후 삭제 이력 재적용을 확인한다.

### 로컬 모델·하드웨어 확정 기준

1. 첫 후보는 [03 §1.2](03_Architecture_and_Dependencies.md#12-텍스트음성-로컬-추론-계약)의 Qwen3 4B·다국어 small STT·Qwen3-TTS 0.6B다. 이는 시험 후보이며 검증된 운영 사양이 아니다.
2. 한국어 경험·지역·자격·불명확 조건과 악성 지시문 표본으로 구조화 추출·사실성·지원서 생성을 평가한다. 기존 사용자 확정·자격 규칙을 완화하지 않는다.
3. 90초 STT 입력과 최대 읽기 길이의 TTS를 시험하고 준비된 모델의 단일 요청·반복 요청·LLM/STT/TTS 교대 실행의 지연·최대 RAM/VRAM·OOM·취소를 기록한다.
4. 서버 전체 공유 슬롯 1개로 먼저 검증한다. 60초 처리 기준을 만족하지 못하면 모델 크기·정밀도·입력 길이·실제 EC2 사양을 조정하고 재검증한다. 외부 AI 추론 API 전환이나 음성 기능 제외를 성공으로 처리하지 않는다.
5. 공개 기한까지 실행 성능·GPU 쿼터·비용을 확인하지 못하면 미검증 상태와 영향을 보고한다. 가능한 사양·동시 처리량을 추측해 완료로 표시하지 않는다.

CI는 프론트엔드 타입·빌드와 Pytest·Bandit·pip-audit·gitleaks를 실행한다. 동적 보안 시험과 실제 기기 접근성·사용성 확인을 별도로 수행한다. 이는 구현 단계의 검증 계획이며 문서 생성 시 도구 실행·통과를 주장하지 않는다.

추천 평가는 실제 검수 공고와 대표 페르소나 5~10개로 진행한다. 명백한 조건 미충족·근거 없는 경험 연결은 없어야 한다. 현재 유효 공고 20건을 확보 목표로 하되 없는 공고를 만들어 채우지 않는다.

평가용 가상 데이터는 실제 운영 공고와 분리한다. 결과에는 입력·프로필/공고 버전·기대 동작·실제 동작·결함·수정·재시험을 남기고 개인정보 원문을 검증 로그나 제출 자료에 노출하지 않는다.

기획·프론트엔드는 사용자 과업·영상·발표·포스터, AI·데이터는 출처·AI·추천 평가 증거, 백엔드·보안은 실행·배포·보안·복구 증거를 맡는다. 문서 존재만으로 제출 완료로 처리하지 않고 파일 열람·영상 재생·새 환경 실행·URL·수신 확인을 점검한다.
