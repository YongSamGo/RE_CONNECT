> 버전: 2026-10-28 v2 (기획자 의도 반영) / 범위: 기존 프론트엔드 개선 + 미완성 사용자 화면 구현
> 근거: `references/01-home.png` ~ `04-login.png` 4개 캡처.
> 주의: 캡처는 **시각적 스타일 레퍼런스**다. 아래 「확인된 기획 의도」는 기획자가 직접 설명한 사항이므로 이미지에 대한 외부 추정보다 우선한다. 사진으로 알 수 없는 내부 동작·실제 CSS 값·폰트명은 반드시 현재 저장소에서 확인한다.

## 0. 디자인 의도 (한 줄)

**시니어를 위한 간결하고 신뢰할 수 있는 디지털 서비스: 공공서비스의 안정감과 현대적인 미니멀리즘을 결합하되, 화려한 장식보다 읽기 쉬운 정보 구조와 명확한 다음 행동을 우선한다.**

톤: `Calm / Trustworthy / Clear / Accessible / Warm but not childish / Deliberately low-density`.

### 화면 문장 부호 규칙

- 화면의 제목, 안내, 레이블, 버튼 문구에는 가운데점을 사용하지 않는다. 항목을 나눌 때는 줄바꿈, 쉼표, 괄호 또는 별도 정보 블록을 사용한다.

- 공공 안내 서비스처럼 신뢰감을 주되 낡거나 딱딱하지 않다.
- 시니어 친화적이되 과장되게 유아적이거나 의료·복지 포스터처럼 보이지 않는다.
- 기능과 사용자의 판단을 돕는 문구가 화면의 중심이다.
- 기존 디자인을 전면 재설계하지 않는다. **같은 브랜드의 나머지 화면**처럼 확장한다.

### 기획자가 직접 확인한 설계 의도 — 최상위 원칙

1. **메인 화면의 큰 빈 영역은 서비스 소개 영상을 삽입하기 위해 의도적으로 예약된 공간**이다. 디자인 결함이나 채워야 할 공백으로 판단하지 않는다. 영상용 영역을 삭제하거나 여러 홍보 카드/일러스트/텍스트로 채우지 않는다.
2. **한 화면에 제시하는 정보량을 적게 유지하는 것 자체가 핵심 UX 전략**이다. 시니어·고령 사용자의 탐색/조작 부담을 고려하여 불필요한 옵션·설명·시각요소를 억제한다.
3. 단순히 모든 요소를 크게 만드는 게 아니라 **한 번에 하나의 판단, 명확한 다음 행동, 단계별 정보 공개**를 지향한다. 입력/선택/결과를 한 화면에 한꺼번에 밀어 넣지 않는다.
4. 현재 UI의 **넉넉한 여백·단순한 카드·큰 버튼·간결한 문구는 의도적으로 선택된 스타일**이다. 근거 없이 '여백 부족/정보 부족'의 반대인 '공간 낭비'로 재해석하지 않는다.
5. 개선할 대상은 실제 문제(잘림, 모호한 상태, 접근 불가능한 조작, 반응형 깨짐, 불필요한 반복)이다. **빈 공간 자체는 버그가 아니다.**

### 정보 밀도와 인지 부담 관리

- 첫 화면에서 전달할 메시지와 행동은 극소수로 제한한다. 상세 설명은 영상, '자세히 보기', 후속 단계에서 **점진적 공개(Progressive Disclosure)** 한다.
- 핵심 문장은 짧고 평이하게 쓴다. 업계용어·복잡한 기능명 대신 사용자가 수행할 행동을 표현한다.
- 여러 선택지가 필요한 경우 묶고, 기본값/현재 선택/다음 단계가 분명하게 드러나게 한다. 선택지를 한꺼번에 과도하게 전시하지 않는다.
- 시각적인 장식보다 명료함을 우선한다. 레이블은 명확하게, 터치 목표는 충분하게, 콘텐츠는 무리하게 조밀하게 배치하지 않는다.
- 접근성은 연령에 대한 고정관념이 아니라 실제 과업 수행 가능성으로 판단한다. 키오스크 조작 부담에 관한 기획자의 문제의식을 반영하되 모든 시니어의 능력을 동일하게 가정하지 않는다.

## 1. 이미지에서 실제로 관찰된 규칙 (확인됨)

| 관찰 항목 | 4개 화면의 공통적 특징 | 구현 시 해석 |
|---|---|---|
| 배경 | 거의 흰색인 연한 회청색 | 앱 전체 배경을 저채도 쿨 그레이로 유지 |
| 본문 서피스 | 큼직한 흰색 둥근 패널 | 주요 작업을 담는 안정적인 Surface |
| 색 | 먹색에 가까운 네이비, 짙은 청색, 연한 하늘색 | 강한 색 대비를 적은 수의 색상으로 구현 |
| 텍스트 | 한글 산세리프, 제목은 굵고 큼 | 읽기 쉽고 중요도 차이가 뚜렷한 타이포 위계 |
| 버튼 | 넓고 모서리가 둥글며 명확한 윤곽선 | 큰 터치 영역, Primary/Secondary 대비 |
| 형태 | 절제된 그림자, 얇은 선, 라운드 | Flat 중심 + 약한 elevation |
| 레이아웃 | 여백이 넓고 섹션 수가 적음 | 단일 과제 중심, 과잉 정보 지양 |
| 헤더 | 좌측 워드마크 / 우측 뒤로가기·글씨크기·로그인 | 전체 사용자 화면에서 일관된 네비게이션 |
| 지역 검색 | 지도와 우측 필터 패널을 병치 | 목적이 다른 영역을 명료하게 분할 |

### 스크린샷 해석 주의 및 개선 가능한 부분

1. **홈 화면의 넓은 공백은 예정된 소개 영상 영역이다. 유지한다.** 영상 삽입 후 제목·영상·CTA가 자연스러운 순서로 인지되도록 조정하되, 현 시점에서 요소를 임의로 한쪽으로 몰거나 빈 영역을 채우지 않는다.
2. 다른 화면의 넉넉한 여백도 우선 **낮은 정보 밀도를 위한 의도**로 취급한다. 실제 콘텐츠가 작아 보여도 정보 추가나 카드 축소가 자동 정답은 아니다.
3. 로그인 화면의 큰 흰색 영역 역시 일관된 시각적 여백의 일부일 수 있다. 명시적 요청 없이 중앙 소형 로그인 카드로 바꾸지 않는다. 실제 사용성·반응형 문제가 있다면 최소 수정한다.
4. 지도 오른쪽 필터 패널이 캡처에서 화면 아래로 이어진다. **단순한 캡처 잘림인지 실제 조작 불가능한 UI인지 확인**하고, 실제로 잘린다면 스크롤/높이 제약을 해결한다.
5. 선택 상태가 색만으로 전달되지 않도록 **텍스트·체크·aria-pressed 등으로 분명하게 표현**한다.
6. 큰 글씨 모드는 정보 위계를 보존하면서 확장하고, 확대 시 콘텐츠가 잘리지 않게 한다.

## 2. 디자인 토큰 (현재 CSS를 우선 확인하고 적용)

아래 색상은 **캡처 픽셀에서 채집·근사한 시작값**이다. 기존 코드에 가까운 명시값이 있으면 그것을 유지하고 토큰으로 통합한다. 전체 사이트 색을 새 팔레트로 갈아엎지 않는다.

```css
:root {
  --ui-bg: #F4F7F9;           /* 화면 배경: 캡처 실제 픽셀 */
  --ui-surface: #FFFFFF;      /* 주 콘텐츠 카드 */
  --ui-text: #182B38;         /* 핵심 텍스트 */
  --ui-text-secondary: #465E70;
  --ui-primary: #245976;      /* 주요 CTA: 캡처 근사 */
  --ui-primary-hover: #1C4A66;
  --ui-primary-soft: #E5F0F5; /* 필터/안내 보조 면 */
  --ui-border: #D6E4EB;
  --ui-focus: #1F729E;
  --ui-shadow: 0 12px 32px rgba(24, 43, 56, 0.06);
  --ui-radius-surface: 28px;
  --ui-radius-card: 18px;
  --ui-radius-control: 12px;
}
```

- Accent 색은 기본적으로 추가하지 않는다. 카카오 OAuth 버튼 같은 **외부 제공사 고유 색상**만 예외로 유지한다.
- 색상으로만 정보를 표현하지 않는다. 성공/경고/오류는 의미 있는 문구와 함께 표시한다.
- 본문·버튼 대비는 WCAG AA(일반 텍스트 4.5:1, 큰 텍스트 3:1)를 목표로 검증한다. 위 근사 색은 자동으로 대비를 보장하지 않으므로 점검한다.

## 3. 타이포그래피

**폰트 패밀리:** 저장소에 현재 적용된 한글 폰트와 폰트 로딩 방식을 먼저 확인하고 그대로 사용한다. 캡처만으로 특정 폰트명을 단정하거나 다른 웹폰트를 새로 도입하지 않는다.

권장 시작점 (실제 기존 px·브라우저 줌과 맞춰 조정):

| Role | Desktop | Mobile | Weight / Line height |
|---|---:|---:|---|
| Hero title | clamp(42px, 5vw, 68px) | 34–42px | 700–800 / 1.15–1.25 |
| Page title | 32–40px | 27–32px | 700 / 1.25–1.35 |
| Section title | 24–28px | 21–24px | 650–700 / 1.3–1.4 |
| Body | 19–22px | 18–20px | 400 / 1.5–1.65 |
| Button / control | 19–22px | 18–20px | 600–700 / 1.3–1.4 |
| Caption | 16–18px | 16px | 400–500 / 1.45 |

- 긴 정보를 굵은 글씨로 채우지 않는다. 제목·핵심 수치·주요 행동에만 강조를 쓴다.
- line-height는 한국어 긴 문장이 붙어 보이지 않도록 확보한다.
- 기본 텍스트가 아주 작은 일반 SaaS 대시보드처럼 변하지 않게 한다.
- **큰 글씨 보기**는 재사용 가능한 typography scale로 구현하여 모든 주요 화면/입력/버튼/모달에 적용한다. 확대해도 잘리거나 겹치지 않아야 한다.

## 4. 레이아웃 및 간격

- 공통 헤더: 워드마크 왼쪽, 우측 필수 액션. 높이는 고정 숫자보다 콘텐츠에 맞추되 데스크톱 대략 72~88px의 안정적 비중.
- 공통 페이지 배경: `--ui-bg`; 메인 작업은 하얀 서피스.
- 데스크톱 대형 페이지: max-width 약 1380–1480px, 좌우 여백 24–40px. 상세·폼 등 읽기 중심 화면은 내용 폭 800–1080px로 제한.
- 카드 내부 padding: 데스크톱 32–48px, 태블릿 24–32px, 모바일 20–24px.
- 8px 기반 spacing scale: 8 / 12 / 16 / 24 / 32 / 48 / 64. 컴포넌트 사이 간격은 의미에 따라 통일.
- 표면 radius 24–32px; 내부 카드 16–20px; 버튼·입력 12–14px.
- 주로 border 1px + 아주 약한 shadow; 여러 겹 중첩 그림자·테두리는 금지.
- 페이지마다 **주요 행동 1개**를 명확하게 표시한다. 다만 홈의 CTA 위치는 영상이 들어갈 전체 구성의 일부이므로 현재 빈 공간만 보고 강제로 제목 아래로 옮기지 않는다.
- **여백과 넓은 흰 서피스는 브랜드의 의도적인 요소**다. 현재 공백이 영상 예약 공간인지, 읽기/인지 부담을 줄이는 공간인지 먼저 파악한다. 의미 없는 spacer로 내용이 가려지는 등 실제 문제가 있을 때만 수정한다.
- 데스크톱은 필요할 때 2열, 좁은 화면에서는 한 열. 고정 폭·고정 높이로 내용이 잘리지 않도록 한다.

### 반응형 동작

- ≥1200px: 넓은 카드/필요한 화면에서 2열(예: 결과 목록 + 필터, 지도 + 필터).
- 768–1199px: 비율 재조정, 도구 패널 축소/재배치.
- <768px: 한 열, 헤더 액션 압축, 주 CTA 충분한 폭, 폼과 목록을 세로로 배치.
- 지도+필터: 모바일에서 필터를 상단 접이식 패널 또는 독립 시트로 제공하고, 지도가 다른 기능을 가리지 않도록 한다.
- 360/390/768/1280/1440 폭 및 큰 글씨 모드에서 가로 스크롤·잘림이 없어야 한다.

## 5. 컴포넌트 규칙

### 버튼

- Primary: `--ui-primary` 배경 + 흰 글씨. 한 화면에서 원칙적으로 1개.
- Secondary: 흰색 배경 + 얇은 청색 테두리 + 짙은 청색 글씨.
- Tertiary: 뒤로가기, 취소, '일단 둘러볼래요'처럼 낮은 우선순위는 텍스트/경량 버튼.
- 최소 터치 타깃 48×48px 권장; 실제 주요 버튼 높이 56–64px. 키보드 focus-visible을 선명하게 구현.
- Disabled는 비활성 이유와 다음 조치를 알 수 있게 표시. hover/pressed/loading 상태 포함.

### 정보 카드 / 폼

- 카드 하나에는 명료한 제목 + 간결한 내용 + 필요할 때 단일 행동. 한 화면에 카드가 과도하게 많이 보이지 않도록 한다.
- 연한 파란 배경은 선택·요약·보조 정보에만 활용; 화면 전체를 파랗게 칠하지 않는다.
- 입력은 항상 visible label을 우선 사용; placeholder만으로 의미 전달 금지.
- 설명이 긴 동의·개인정보 화면은 간략한 요약을 먼저, 자세한 내용은 펼침/상세보기로 제공. 필수 동의와 선택 동의, 실제 사용처·보관·삭제 정보를 명확히 분리. 법적 필수 정보나 선택·동의 행위를 숨기지는 않는다.
- Empty / Loading / Error / Success / Validation state를 같은 컴포넌트 언어로 설계.

### 헤더/내비게이션

- 워드마크 '다시잇다'를 눈에 띄게 유지하되 과도한 로고 개발 금지.
- '뒤로가기'는 브라우저와 충돌하지 않도록 동작하고, 첫 화면에서는 불필요한 뒤로가기 제거.
- '큰 글씨 보기'의 상태가 유지되고 토글 라벨/aria가 실제 상태를 나타내게 한다.
- 로그인 상태에 따라 '로그인'/내 정보/로그아웃 등 실제 상태가 바뀌도록 한다.

## 6. 화면별 확장 청사진

우선 이미 구현된 컴포넌트·API 계약·라우트·비즈니스 로직을 찾아 재활용한다. 화면 미구현을 이유로 가짜 데이터를 영구 채우지 않는다.

**모든 후속 화면은 저밀도·단계형 구성:** 한 번에 하나의 질문/선택/행동이 중심이다. 세부항목은 필요할 때 펼치고, 복잡한 다중 패널을 무작정 도입하지 않는다. 데이터가 많을 때는 핵심 요약 → 상세보기 순서로 제공한다. 사용자의 진행 상황, 뒤로가기, 입력값 보존, 오류 시 복귀 경로를 알기 쉽게 만든다.

### 홈 화면 — 소개 영상 영역 (기획 의도 확정)

- 메인의 넓은 중앙 여백은 **소개 영상 자리**다. 제목·서브카피·시작하기/공고 보기 CTA와 함께 하나의 차분한 안내 화면으로 설계한다.
- 실제 영상 파일/URL/플레이어가 제공되기 전에는 **반응형 16:9 영상 슬롯 또는 콘텐츠 플레이스홀더**만 제공한다. 영상 내용·파일 경로·썸네일을 임의로 만들어 실제 영상인 것처럼 표현하지 않는다. 기존 구현에 동영상 자산이 있는지 먼저 확인한다.
- 영상은 사용자가 **명시적으로 재생**하도록 한다(음성 자동재생 금지). 자막 제공을 지원하고, 시청하지 않아도 '시작하기' 등 주요 기능을 바로 이용할 수 있게 한다. 영상이 로드되지 않을 때도 CTA는 정상 동작해야 한다.
- 영상/대체설명/재생 조작은 키보드 접근과 명확한 레이블을 갖추고, 모바일과 큰 글씨 모드에서 잘리거나 CTA를 가리지 않아야 한다.
- 영상의 크기와 위치는 실제 화면 해상도에서 제목·CTA와 균형을 이루도록 하되 **영상 영역을 제거하고 홍보용 카드로 대체하지 않는다.**

### A. AI 대화 화면 (핵심 시연)

- 제목: `경험을 들려주세요` 계열의 인간적인 표현. 불필요한 AI 용어·장식 제거.
- 한 개의 주 작업 영역: 대화 리스트, 안내/진행 상태, 메시지 입력, 보내기.
- 봇과 사용자 메시지는 절제된 흰색/연한 파랑 영역으로 구분. 채팅 버블을 과하게 꾸미지 않는다.
- 메시지 입력과 보내기 버튼은 화면에서 쉽게 찾고 누를 수 있어야 한다.
- '경험 정리하기' 같은 다음 핵심 행동은 유효한 단계에서만 노출.
- 음성 입력이 실제 구현되어 있지 않다면 마이크 버튼을 보여주거나 작동하는 척하지 않는다.
- API 호출 중 로딩, 네트워크 실패, 재시도, 입력 길이 제한 처리.

### B. AI 경험·역량 확인 화면

- AI가 추출한 경험/수행 업무/역량/선호/제약을 큰 제목의 읽기 쉬운 카드 또는 구분된 섹션으로 표시.
- 항목별 수정·삭제, `이 내용이 맞나요?` 확인 액션을 제공.
- **AI 추론값은 사용자가 승인하기 전 확정 프로필로 취급하지 않는다.**
- 저장 전후 상태가 명확하고 이전 화면으로 돌아갈 수 있어야 한다.

### C. 추천 공고 목록 화면

- 상단에 `OO님의 경험과 연결되는 기회` 같은 명료한 제목과 짧은 안내.
- 공고 카드: 역할명, 기관, 장소/일정, 유형, 마감, 추천 이유, 필수 조건 상태, 상세보기.
- 추천 이유는 'AI가 추천함' 대신 **어떤 경험/역량과 연결되는지** 한두 문장으로 보여준다.
- 조건 미충족 / 확인 필요 / 확인된 일치 상태를 텍스트로 구분.
- 결과가 없으면 검색 조건 변경/지역 확대/다시 탐색하는 경로 제공.
- 카드 장식은 최소한, 정보·CTA 중심.

### D. 공고 상세 화면

- 제목/기관/출처/공고 상태를 최상단에서 파악 가능.
- 역할, 업무, 장소·시간, 자격 조건, 준비 서류, 마감 순서로 정리.
- 공식 출처 링크가 명확해야 하고 외부 페이지 이동임을 안내.
- 다음 행동은 `참여 준비하기`처럼 단 하나의 주 CTA.
- 검증된 사실과 AI 설명을 시각·문구로 구분.

### E. 참여 준비 화면

- `참여 전 확인할 사항` → 자격조건 대조 → 준비서류 체크리스트 → 지원서 초안 확인 → 공식 신청으로 이어지는 흐름.
- '지원 가능'은 확정된 정보에 근거할 때만, 모호하면 `확인 필요`.
- 자동 제출 기능이 없다면 절대로 '지원 완료'로 오인될 UI를 만들지 않는다.
- 사용자가 승인한 정보에만 기반한 초안을 제공하고 편집/확인 가능.

### F. 기존 4개 화면 개선

- `01-home`: **중앙의 넓은 여백은 소개 영상 예정 공간**이므로 그대로 존중한다. 영상 슬롯을 중심으로 제목·서브타이틀·주요 행동을 알아보기 쉽게 구성한다. 여백을 메우려고 홍보 카드/일러스트를 추가하거나 CTA 위치를 근거 없이 바꾸지 않는다.
- `02-consent`: 정보 요약 + 자세히 보기 + 명시적 동의가 한 흐름으로. 실제 개인정보 취급 정책을 사실 그대로 설명한다.
- `03-opportunity-search`: 지도+필터 2열 유지, 잘리는 패널 수정, 지역 다중선택/선택해제와 검색 상태를 명확히. 결과 확인 경로 보장.
- `04-login`: 동일한 팔레트/타이포와 여유 있는 공간을 존중한다. 과도하게 복잡하게 채우거나 임의로 축소하지 않는다. 카카오 브랜드 색은 허용. OAuth 실패/취소 상태 처리.

## 7. 금지되는 스타일 (기계적 AI 생성물 느낌 방지)

- 그라데이션 배경, 글래스모피즘, 네온 컬러, 유광 3D 아이콘, 글로우/헤비 블러, 파티클, 주목적과 무관한 애니메이션.
- 페이지마다 다른 색, 다른 카드 반경, 다른 그림자, 다른 폰트 크기 규칙.
- 모든 정보에 badge/icon/카드를 붙여 복잡해지는 화면.
- 실제 정보 대신 '완벽한 경험을 시작하세요' 같은 추상적 홍보 문구 남발.
- 불필요한 스크롤 스냅·모션, **영상 예약 공간과 의도된 저밀도 레이아웃을 무시한** 장식성 풀스크린 섹션.
- 데스크톱 1장만 예쁘고 모바일·큰 글씨 모드에서 잘리거나 접근성이 낮은 구현.
- 가짜 완료/가짜 지원/가짜 추천, 작동하지 않는 버튼, 백엔드로 연결되지 않은 폼.

## 8. 구현 지침 (프로젝트 변경 범위)

1. 먼저 저장소를 탐색해 기존 라우트, API 타입, 주요 컴포넌트, 전역 스타일, 인증 및 큰 글씨 모드 상태를 파악한다.
2. 기획자의 **소개 영상 예약 공간과 낮은 정보 밀도** 의도를 변경 불가능한 기본 요구사항으로 반영한다. 이후 `tokens`·`PageShell`·`Header`·`Button`·`Card`·`FormField`·`StatusMessage` 등 최소한의 공통 기반을 확보한다. 기존 공통 컴포넌트를 우선 수정/재사용하고 중복 생성하지 않는다.
3. **기능이 구현된 백엔드와 기존 인터페이스는 보존**한다. 프론트 개선 때문에 API/스키마/인증체계를 임의로 재작성하지 않는다.
4. 미완성 핵심 화면을 A→B→C→D→E 사용자 흐름에서 실제 동작하도록 연결한다. 먼저 E2E 작동, 그다음 세밀한 장식.
5. 페이지마다 정상/로딩/에러/빈 상태와 취소/뒤로가기를 점검한다.
6. 모바일/태블릿/데스크톱/큰 글씨 모드에서 잘림과 포커스/키보드 동작 검증.
7. lint/typecheck/build/관련 테스트 실행. 실패를 숨기지 않고 원인·수정·남은 문제를 보고한다.
8. 수정 범위가 큰 API/보안/개인정보 정책은 무단 변경하지 않는다. 특히 민감정보를 로그/브라우저 저장소에 노출시키지 않는다.
9. **시연 마감이 임박한 프로젝트**이므로 미학적 전면 리팩터링을 피하고, 핵심 화면 구현과 안정적 배포 가능성을 최우선으로 한다.

## 9. 완료 기준 (Definition of Done)

- [ ] 다섯 핵심 사용자 단계 모두 화면 및 실제 주요 동작 구현.
- [ ] 네 스크린샷과 동일한 브랜드/컴포넌트 언어를 인지할 수 있음.
- [ ] 홈 소개 영상 영역을 보존하고, 실제 영상이 없다면 접근 가능한 플레이스홀더만 구현했음.
- [ ] 모든 핵심 화면에서 단일 주 행동과 낮은 정보 밀도를 유지하며 상세 내용은 단계적으로 공개함.
- [ ] 전체 페이지에서 헤더·폰트·버튼·간격·컬러가 일관됨.
- [ ] 주요 버튼은 실제 이벤트·라우트/API와 연결됨.
- [ ] AI가 만든 정보를 사람이 확인/수정하고 이후 단계로 넘어갈 수 있음.
- [ ] 검색/추천·조건 확인 정보는 실제 데이터/명시된 상태로 제공됨.
- [ ] 로딩·빈 결과·에러·재시도·접근 제한 처리.
- [ ] 360, 390, 768, 1280, 1440px + 큰 글씨 보기에서 overflow/잘림 없음.
- [ ] 키보드로 주요 흐름을 완료할 수 있고 focus 및 라벨이 명확함.
- [ ] lint, typecheck, build 및 주요 테스트 결과 보고.
- [ ] 최종 구현한 화면, 변경 파일, 미완성/리스크를 간결하게 보고.
