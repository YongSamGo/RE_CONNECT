# 프로필 명시적 확정과 버전 참조 (W05-05/06 · #40 · #41)

`POST /api/v1/journeys/{journey_id}/profile/confirm`은 요청한 기준 리비전의 현재 초안을 확정한다. 본문은 `base_revision` 하나만 받는다. 사용자/AI가 넘긴 본문·확정 시각·버전·소유권을 확정 증거로 받지 않는다. 공개 계약은 [OpenAPI](../api/openapi.yaml)의 `BaseRevision`·`ProfileConfirmResult`·`ProfileRef`·`ConfirmedVersion`이다.

## 확정과 불변 스냅샷

세션과 체험의 소유권·수명을 확인하고 경험·희망 지역·활동 유형이 각각 한 개 이상인지 검사한다. 빠진 항목은 422의 `draft.<필드> / required`로 반환한다. 직접 입력한 프로필도 확정할 수 있으며 AI 동의나 모델 호출을 요구하지 않는다. CSRF와 일반 API 분당 한도는 적용한다.

서비스에서 검증한 초안의 정규 JSON이 현재 Redis 초안과 정확히 일치하고 기준 리비전이 여전히 같은 경우에만 저장한다. 이 검사와 새 버전 스냅샷 쓰기·서버 시각·최신 확정 참조·리비전 증분·실제 활동의 유휴 갱신을 한 Lua 스크립트에서 확정한다. 응답의 시각은 Redis `TIME`, 버전은 해당 체험의 서버 카운터에서 부여한다.

스냅샷은 체험의 수명 메타 해시 안에 `confirmed:<버전>:content`·시각으로 보관한다. 이미 존재하는 버전 필드는 덮어쓰지 않는다. 확정 뒤 초안을 수정해도 이전 스냅샷과 그 확정 시각은 그대로다. 재확정하면 새 버전을 만들고 미확정 변경 표시를 해제한다. 같은 이전 리비전의 재전송은 409이며 확정 버전을 추가하지 않는다.

확정본에는 프로필 내용만 복사하며 초안의 대화 근거·메시지 ID는 복사하지 않는다. 메타 해시 하나의 삭제/만료로 버전별 자료도 함께 사라진다. 이 기능은 Redis 임시 체험이며 회원 영구 저장이 아니다.

초안 한 건은 기존 64KiB 상한을 따르고, 체험당 확정본은 최대 64개로 제한한다. 이는 임시 저장량을 제한하는 현재 구현 선택이며 KISA의 정해진 수치 요구가 아니다. 초과하면 429 `RATE_LIMITED`와 남은 체험 TTL에 근거한 `Retry-After`를 반환하고 기존 스냅샷을 지우거나 덮어쓰지 않는다. 유휴 갱신은 절대 수명 2시간을 연장하지 않는다.

## 후속 기능의 확정 참조 조회

`JourneyService.resolve_profile(session, ProfileRef, require_current=...)`는 소유권과 수명을 다시 검사해 저장된 **확정 스냅샷만** 반환한다. 미확정 초안을 확정본처럼 반환하지 않는다.

- 확정본이 없으면 409 `PROFILE_NOT_CONFIRMED`다.
- 존재하지 않는 버전이나 `require_current=True`에서 과거 버전을 요청하면 409 `VERSION_CONFLICT`다.
- 과거 확정본이 필요한 명시적 버전 조회는 `require_current=False`로 불변 스냅샷을 읽는다. 현재 기준으로 계산해야 하는 추천/자격 업무는 `True`를 사용해야 한다.
- 다른 주체/없는 체험/만료 세션은 동일한 404다. 참조 ID를 알고 있다는 사실이 권한이 되지 않는다.
- 현재 공개 인증은 익명만 있으므로 `kind=saved`는 401로 거절한다. 회원 인증과 암호화 저장본 소유권 조회는 #42·#73·#75에서 별도로 연결한다.

자격 대조(#60)와 추천(#63/64)은 현재 확정본을 매번 검사하는 비저장 계산이다. 편집 중에는 이전 확정본을 유지하고 추천에 `based_on_previous_confirmed=true`를 반환한다. 재확정 뒤 이전 버전으로 계산하려 하면 409이므로 새 확정 참조로 다시 요청해야 한다. 기존 응답의 근거 참조를 새 버전으로 바꿔 붙이지 않는다. 화면의 이전 결과 제거·재조회는 #84/#85에서 이 구분을 사용해야 한다.

`JourneyService.profile_dependency(session, stored_reference)`는 지원서 조회의 **표시용 내부 인터페이스**다. 소유권·수명과 원래 확정 버전의 실재성을 확인한 뒤 원래 `reference`, 현재 `current_profile`, 추가할 `review_reasons`, 수정 중 표시를 반환한다. 편집만 했을 때는 `profile_changed`를 만들지 않고 재확정으로 근거 버전이 달라졌을 때만 만든다. 이전 참조와 불변 스냅샷은 유지한다. 알 수 없는 버전·타인 참조·만료는 정상 비교로 처리하지 않는다.

이 인터페이스는 지원서 본문·원래 근거 버전·사용자 승인·공고 변경 사유를 쓰거나 삭제하지 않는다. 후속 지원서 서비스(#69)는 `profile_changed`를 기존 공고 재검토 사유에 합쳐 표시해야 하며, 본문을 자동 변경하거나 사용자의 재승인 없이 근거 버전만 최신화하면 안 된다. 지원서 저장소/조회 HTTP는 아직 구현하지 않았으며 이 내부 인터페이스가 실제 지원서 화면 연결까지 완료했다는 뜻은 아니다.

## 검증

#41 추가 검증: `test_reconfirmed_results.py`는 실제 Redis와 SQLite/PostgreSQL HTTP에서 편집 중 구 확정본 유지, 재확정 뒤 구 버전 추천/자격 요청 409, 새 버전의 판정·추천 재계산, 기존 근거의 `profile_changed`와 불변 스냅샷 보존을 확인한다. 표시 인터페이스의 타인/없는 버전/saved 사칭/삭제 후 참조도 검사한다. 2026-10-18 실제 서버 전체 백엔드 861개 통과·건너뜀 없음이며 시험 서버를 종료했다. 실제 지원서 본문 저장과 화면 연결은 후속 범위다.

2026-10-18 격리된 WSL의 실제 Redis 7.0.15·PostgreSQL 16.15에 연결한 전체 백엔드 633개가 통과했고 건너뜀은 없었다. 이 파일의 확정 관련 시험 9개도 모두 실행됐다. 가상 자료를 tmpfs·비영속 Redis에만 넣고 시험 후 서버를 종료했다. 실제 EC2·브라우저·회원 저장 연동을 증명하는 결과는 아니다.

`backend`에서 `python -m pytest tests/test_profile_confirmation.py -q`를 실행한다. 순수/HTTP 시험은 누락 필드·미확정 참조·서버 버전/시각·CSRF·위조 승인 본문·타인/잘못된 참조·낡은 리비전·재편집/재확정 후 이전 버전 보존을 확인한다. 시험 대역의 불변성을 실제 Redis 원자성 증거로 사용하지 않는다.

실제 Redis 전용 시험은 `PERSISTENCE_TEST_REDIS_URL`이 있을 때만 실행하며 확정/편집 스냅샷 분리, 현재/과거 참조, 동시 확정 승자 한 명, Redis 시각, 삭제 이후 늦은 확정의 재생성 차단, 버전 상한을 검사한다. 로컬에서 건너뛴 항목은 통과로 세지 않는다. 실제 EC2·Redis·회원 저장·파생 결과 재검토와 브라우저 흐름은 별도 검증이 필요하다.

관련 KISA 보안약점은 부적절한 인가(SEC-02), 경쟁조건: 검사시점과 사용시점(TOCTOU, TIM-01), 크로스사이트 요청 위조(INP-11), 오류 메시지 정보노출(ERR-01)이다.
