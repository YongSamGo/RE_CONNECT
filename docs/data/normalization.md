# 공고 원문 → 검수 대기 후보 (W06-03 · #46)

[정규화 함수](../../backend/app/modules/ingestion/normalize.py)는 [필드 매핑](field-mapping.md)의 확인된 값만 `OpportunityContent`로 옮긴다. 네트워크·DB·LLM을 호출하지 않는다. 원문이 승인 상태·URL·역할·설명 절단 여부를 제안해도 이를 권한이나 서버 메타데이터로 사용하지 않는다.

## 입력과 결과

- `normalize(source, listing, detail, checked_at=...)`: 출처 `senuri`/`volunteer`, 목록 1건과 상세 1건의 필드 사전, 서버가 측정한 시간대 있는 확인 시각을 받는다.
- `normalize_items(...)`: #45의 제한 파서가 만든 목록/상세 `item`을 받는다. XML을 다시 파싱하지 않으며 중복 필드·중첩·속성·혼합 본문을 거절한다. dict로 덮어써 원문 충돌을 숨기지 않는다.
- 상세가 없거나 ID·필수 필드·날짜·계약이 잘못되면 `held`와 고정 사유 코드만 반환한다. 원문·검증 예외를 오류에 넣지 않는다.
- 명확한 수도권 밖의 **지역 이름**과 1365 `adultPosblAt=N`은 `excluded`로 구분한다. 해석이 불확실한 지역 이름/코드를 정상 제외로 집계하지 않는다.
- `candidate`는 내용 계약을 통과한 **검수 대기 후보**다. `review_status=pending`은 생성자 입력으로 바꿀 수 없다. 공개 승인·버전 번호·공개 ID를 만들지 않는다.

후보에는 내용, `external_id`, UTC `source_checked_at`, `description_truncated`, 고정 `review_reasons`, 최대 64자 코드만 허용한 `unmapped_fields`가 있다. `unmapped_fields`는 지역/요일/접수/고용형태/분류 코드의 허용목록이며 담당자·주소·원본 전체를 복제하지 않는다. 내용과 미확인 값은 기본 repr에서도 제외한다.

## 확인된 사실만 매핑

- 제목·기관은 정해진 상세→목록 우선순위로 선택한다. 1365의 등록센터를 모집기관으로 대신 쓰지 않는다. 모집기관 필드 의미는 추가 검수 대상으로 표시한다.
- 노인 구인정보의 원 시스템이 `워크넷`이고 `wantedAuthNo`가 고정 형식일 때만 고용24 공식 URL을 만든다. 1365는 검증한 숫자 공고 ID만 공식 상세 경로에 넣는다. 원문의 임의 URL을 수집/신청 주소로 쓰지 않는다.
- 서울·경기·인천의 실제 **지역 이름**은 현재 서버 지역 목록에 정확히 일치할 때만 매핑한다. 인천의 개편 전 중구 등은 추측해 배정하거나 시·도 전체로 넓히지 않는다.
- 1365의 구·군 코드와 인천 개편 매핑은 아직 검증되지 않았다. 코드는 검수 메타데이터에 보존하고 활동 지역은 null로 둔다. 수도권 밖 코드도 확인된 코드표 없이 추정해 제외하지 않는다.
- 원격 허용·주당 시간·보수 설명·역할·역량을 만들어 채우지 않는다. 출처 분류로 확인한 유급/봉사 값만 고정한다. 요일 수 × 하루 시간으로 주당 시간을 계산하지 않는다.
- 활동 시간은 명시된 정수 시각/기간만 표시한다. 요일 코드의 자리 순서와 ANY/ALL 의미가 미확정이므로 사람이 읽는 요일로 바꾸지 않는다.
- 확인한 접수방법 이름만 매핑한다. 모르는 코드는 방법을 추측하지 않고 보류한다. 같은 방법이 반복됐다고 복수 방법으로 만들지 않는다.
- 실제 달력 날짜를 확인하고 한국 날짜로 모집 상태를 판정한다. 날짜에 임의 마감 시각을 붙이지 않는다. 출처가 확인한 종료 코드와 지난 마감일은 닫힘으로 처리한다.

## 조건과 근거

숫자 `60`을 `만 60세 이상`으로 바꾸지 않는다. `만 N세 이상/이하`가 명시된 구인 연령만 구조화하며 `그리고`/`또는`의 동종 그룹을 보존한다. 혼합 AND/OR나 해석하지 못한 표현은 `other`에 원문 근거를 남긴다. 나이 기준일을 만들지 않으며 모든 조건은 `needs_review`다.

기타 우대사항을 필수 자격으로 바꾸지 않는다. 1365 본문에 등장하는 자격·연령을 임의로 추출하지 않는다. 미해석 설명의 최대 900자 발췌를 `other.source_evidence`에 남긴다. 처리 상태 안내와 공식 원문 발췌를 구분해 표시한다.

조건 필드가 비어 있어도 `requirements=[]`를 만들지 않는다. 필수조건 전체 검수가 끝나지 않았다는 처리 상태 조건을 추가한다. 이는 공식 기관이 제시한 추가 자격이 아니며, 후속 검수에서 실제 원문을 확인해 해소해야 한다. 조건 ID와 그룹 ID는 출처/공고/필드에 따라 안정적으로 생성해 재수집 때마다 다른 버전이 생기는 것을 피한다.

## 설명·개인정보·저장/공개 계약

- 설명이 없으면 null이다. 제목이나 모델 생성 문장으로 보충하지 않는다.
- CRLF/CR을 줄바꿈으로 정리한다. 숨은/방향 제어 문자는 제거해 뜻을 바꾸지 않고 후보를 보류한다. HTML 문자 참조로 생긴 제어 문자도 다시 검사한다.
- HTML은 실행·URL 접근 없이 일반 텍스트로 바꾼다. 속성과 script/style/iframe 등 실행 내용은 남기지 않는다. 숨은 요소를 제거했다고 원문 지시문이 안전하다고 판정하지 않는다. 후속 LLM 호출에서 비신뢰 자료로 분리해야 한다.
- 연락처·이메일·식별번호 형태를 치환하고 `contact_redacted`를 표시한다. 이름/특이한 연락처를 모두 검출한다는 보장은 없으므로 공개 전 원문/설명 최소 수집 검수가 필요하다. 담당자 전용 필드·상세주소·좌표는 선택하지 않는다.
- 정리한 설명이 5,000자보다 길면 앞부분만 `description_text`로 넣고 내부 `description_truncated=true`와 검수 사유를 붙인다. 다른 필드는 길이 초과 시 보류한다. 잘린 이후의 자격조건을 모두 보존했다고 주장하지 않는다.
- `description_text`는 기존 `OpportunityContent`/공개 API 계약의 일반 텍스트 필드다. 내부 절단 표시는 공개 API 스키마에 임의로 더하지 않는다. #47 저장 연결 시 `OpportunitySnapshot`에 내용과 `description_truncated`를 함께 전달하고 새 버전은 pending으로 저장해야 한다.
- `review_reasons`와 `unmapped_fields`의 검수 상태 보관, 승인 조건 해소는 후속 저장/운영자 작업에서 연결한다. 보존하지 않은 상태로 정규화 완료/공개 승인으로 처리하면 안 된다.

## 검증 범위

2026-10-20 가상 표본으로 정상 매핑, 불명확 연령·AND/OR·안정 ID, 지역 개편·미확인 코드, 날짜/KST 경계, 원문 URL/승인 필드 무시, 개인정보 형태·HTML·숨은 문자, 5,000자 경계, 중복 XML 필드를 검증했다. 실제 PR #196의 파서 코드가 만든 XML 트리 → 이번 정규화 후보 연결도 가상 표본으로 확인했다. 이 시험은 실제 인증 API 수집·DB 저장·공개 승인·추천의 전체 여정 증거가 아니다.

남은 실제 확인은 [필드 매핑의 확인 목록](field-mapping.md#7-남은-확인-사항)과 동일하다. #46 전체 통과나 실제 API 정상 연동 완료로 표시하지 않는다.
