# 승인 지원서의 암호화 저장 — W10-05

## 명시적인 두 단계 저장

`POST /api/v1/drafts`는 승인 원본 참조, document_id, base_document_version만 받는다. 본문·회원 ID·승인 시각은 서버가 조회한다. 새 문서는 문서/기준 버전이 모두 null이고, 갱신은 두 값을 함께 보내야 한다. 현재 회원·저장 동의·Origin/서명 CSRF·HTTP 한도·UUID 멱등 키를 검사한다.

원본은 자기 체험의 승인 지원서 리비전 또는 로그인 때 옮긴 저장 대기다. 미승인·수정 후 재승인 누락·근거 재검토·리비전 충돌은 거절한다. 승인 프로필과 현재 자기 저장 프로필의 복호화 본문이 같아야 하며 그 저장 ID/버전을 연결한다. 다르거나 없으면 PROFILE_NOT_SAVED다. 지원서 저장이 프로필을 몰래 저장하거나 교체하지 않는다.

프로필+지원서 대기에서는 화면이 프로필도 저장하겠다는 확인을 받고 `POST /profiles/me/versions`를 먼저 호출한다. 이 명시적 첫 단계는 프로필만 저장하고 지원서 대기/원래 TTL을 유지한다. 그다음 POST /drafts가 정확한 대기를 한 번 소비한다. 이미 자기 현재 저장 프로필과 내용이 같으면 그 버전을 연결할 수 있다.

## 저장 경계와 불변 버전

같은 User 행을 잠근 트랜잭션에서 현재 동의·근거 프로필·문서 소유권·기준 버전·현재 공개 공고를 검사한다. 공고 공개 포인터/버전은 PostgreSQL 공유 행 잠금으로 고정하고, 중요 미검수 변경·마감·확인 지연·버전 변경은 보류한다. 거절할 조건은 대기 소비 전에 검사한다.

같은 문서를 갱신하면 새 ApplicationDraft 버전을 INSERT하고 이전 본문/승인 시각을 수정하지 않는다. 본문 두 필드만 [AES-256-GCM](../security/encryption.md)으로 암호화한다. 소유자/종류 application/문서/버전/스키마를 대상별 키와 AAD에 결합한다. 키 없음·변조는 고정503이며 평문 대체는 없다.

원본과 현재 세션을 쓰기 전후 재검사한다. SQL 작업 취소는 worker 종료 후 롤백하고, 로그아웃·체험 종료는 같은 User 잠금 경계 뒤에 성공을 반환한다. 본문과 응답 기록은 같은 SQL 트랜잭션으로 저장한다.

## 재전송과 삭제

`application_write_receipts`는 User+요청 UUID, 입력 해시·선택적 대기 ID 해시, 결과 문서/버전·프로필/버전·시각, 24시간 만료만 기록한다. 본문·원래 대기 ID·키는 없다. UPDATE는 DB 트리거로 거절하고 User+대기 해시 고유 제약이 다른 요청 키를 이용한 대기 재사용도 막는다.

같은 키/입력은 소비한 대기나 과거 문서 기준을 다시 사용하지 않고 같은201 응답을 SQL에서 재전송한다. 현재 회원·저장 동의는 다시 검사한다. 다른 입력이면409다. 삭제된 결과는404이고 같은 요청으로 새 문서를 만들지 않는다. 문서 삭제 뒤 기록은 만료까지 유지되며 User 삭제는 기록도 cascade한다.

SQL/Redis 분산 트랜잭션은 없다. 대기 소비 후 SQL 실패/취소이면 새 지원서/응답 기록은 롤백하지만 대기는 복구하지 않는다. 앞서 별도 요청으로 명시 저장한 프로필은 유지된다. 실패한 저장은 다시 확인/발급해야 한다.

## 목록·상세와 재검토

`GET /drafts`는 자기 문서의 최신 버전만 최근 저장 순/문서 ID 순으로 반환한다. page는1부터, page_size는최대20이며 전체 건수도 자기 자료만 센다. 목록에 본문을 넣지 않는다. `GET /drafts/{id}`는 소유한 최신 버전만 복호화한다. 읽기는 세션 유휴 수명을 연장하지 않고 응답은 no-store다.

제목/기관은 저장 당시 공고 버전을 표시한다. 현재 저장 프로필·공개 공고 버전/중요 미검수 변경·마감이 바뀌면 profile_changed/opportunity_changed/opportunity_closed를 계산한다. 기존 본문과 승인 시각은 그대로 유지하며 자동 수정·재승인하지 않는다.

## 검증 범위

실제 Redis·SQLite/PostgreSQL·ASGI에서 명시적 프로필 선행 저장, 승인/소유권/동의/CSRF/근거/공고 보류, 문서 갱신·불변 본문·응답 재전송·동시6요청→1저장, SQL 실패/로그아웃 롤백, 키 없음/변조, 삭제 후 재생성 차단, 목록/상세·재검토 표시를 시험한다. 실제 TCP API에서도 대기→프로필 저장→지원서 저장·재전송·조회→회원 새 체험 지원서로 같은 문서 새 버전 저장을 검증한다.

시험 제공자·안내문·키·본문은 가상이다. 운영 정보 미정으로 실제 동의는 비활성이다. 실제 카카오 정상 승인·운영 HTTPS/EC2·키 보관/복구·기기, #77 저장 자료 재편집, #78 삭제·철회·탈퇴와 #79 접근·경합 검증는 별도 구현/검증이 남아 있다.
