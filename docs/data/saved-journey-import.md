# 저장 자료로 새 체험 시작 — W05-07

## 저장 프로필 가져오기

`POST /api/v1/journeys`의 saved_profile은 자기 저장 프로필 ID/버전 참조다. 회원만 사용할 수 있고 현재 AI 처리 동의와 현재 안내문 버전이 필요하다. 익명은401, 다른 회원/없는 버전은404, 키 없음/변조는503이다. 본문·소유자·확정 시각을 클라이언트로부터 받지 않는다.

현재 User 행 잠금 안에서 목적 ai_processing의 최신 동의·소유권을 확인하고 정확한 저장 버전을 복호화한다. 잠금을 유지한 채 새 Redis 체험을 만들고 세션을 최종 확인한다. AI 동의의 Redis 세션 guard 결합은 이 잠금 전에 수행하며 다른 SQL 연결에서 같은 행 잠금을 중복 획득하지 않는다.

새 체험에는 저장 프로필 본문만 가져와 확정본1번으로 초기화한다. 기존 확인 사실과 원래 확정 시각을 유지하고, 새 체험 ID/삭제 세대/첫 질문 ID·생성/유휴 시각을 부여한다. 대화·음성·프로필 근거 메시지·역할 제외·임시 지원서·준비 체크는 복원하지 않는다. 생성 멱등성/하루 계정 한도/세션별 자원 인덱스는 일반 체험과 같은 Lua로 처리한다.

가져온 체험의 편집은 그 새 Redis 편집본만 바꾼다. 저장 프로필의 본문/버전/확정 시각은 자동 변경되지 않는다. 바뀐 내용은 다시 확정하고 명시적으로 저장해야 한다. 같은 생성 키는 같은 체험을, 새 키는 독립적인 새 편집본을 만든다.

## 저장 지원서 편집 자료 참조

`SavedDraftService.edit_source`는 자기 문서의 정확한 버전과 근거 저장 프로필을 SQL 소유권 조건으로 조회·복호화하는 내부 경계다. 현재 회원/AI 동의와 같은 User 잠금을 사용한다. 편집에 필요한 문서/버전·프로필 참조·공고 참조·본문만 준비하고 원래 승인 시각·대화·체크 상태는 반환하지 않는다. 본문은 repr/log에서 숨긴다.

이 참조 준비는 지원서를 자동으로 편집하거나 저장하지 않는다. 실제 mode=from_saved 새 임시 지원서 생성·수정·재승인·다시 저장하는 사용자 흐름은 #77에서 연결하며 현재 그 경로의 실패 닫기를 유지한다.

## 동시성·검증·운영

로그아웃은 Redis 인증/체험을 먼저 회수하고 같은 PostgreSQL User 잠금 경계를 지난 뒤 성공을 반환한다. 원본 SQL 조회 중 로그아웃하면 늦은 Redis 생성은 기존 세션을 확인해 거절한다. #78 삭제·철회도 같은 User 잠금과 파생 세션/체험 무효화 계약을 사용해야 한다. SQL과 Redis의 분산 트랜잭션을 주장하지 않는다.

실제 Redis·SQLite/PostgreSQL·ASGI로 현재 동의/다른 사용자/키 없음/새 확정1번/대화 미복원/독립 편집/저장본 불변/생성 멱등성, 지원서의 편집 자료 참조와 승인 미승계, PostgreSQL 로그아웃 경합을 검증한다. 실제 TCP API에서도 저장 프로필 가져오기·새 편집·저장본 유지·복원하지 않은 자원을 확인한다.

제공자·안내문·키·본문은 가상 시험 데이터다. 실제 운영 정보 미정으로 실동의는 비활성이다. 실제 카카오 승인·운영 HTTPS/EC2·키 보관/복구·기기, #77 재편집/#78 삭제·철회·탈퇴/#79 접근·경합 전체 검증은 후속이다.
