# 자격 비교 규칙 구현·검증 기록

관련 이슈: #58 (W08-01), #59 (W08-02). 기준: Plan/02 §4, Plan/04 F07.

`backend/app/modules/eligibility/rules.py`의 `compare_condition`은 검증된
`ProfileContent`와 `Requirement`를 받아 조건 ID·3상태 결과·고정된 사유 코드만
돌려주는 순수 함수다. DB, LLM, 시계, 로그를 사용하지 않는다. 필드·연산·값 허용표는
`backend/app/contracts/requirement.py`를 사용한다. 정의되지 않은 필드는 계약에서 거절한다.

- 미확인 null과 없음 확인인 빈 배열을 구분한다. 거주는 희망 활동 지역과 구분한다.
- 출생연도와 조건의 기준일로 가능한 나이 범위 전체를 비교한다. 생일을 추정하지 않는다.
- 자격·교육명은 정확히 같아야 충족이다. 부분 일치·동일 종목의 다른 등급은 확인 필요다.
  공인된 상하·동등 관계표가 확보되지 않았으므로 자동 인정 목록은 비워 둔다.
- 미해석 조건·검수 필요 조건은 확인 필요다. 지원 여부·자격 판정은 LLM으로 결정하지 않는다.

평가 표본 48건의 모든 조건별 기대값을 서비스 코드와 직접 대조한다. null/빈 배열,
다른 자격 등급, 거주·희망 지역 혼동, 시간 경계, 연령 범위, 허용되지 않은 연산·형식과
클라이언트 판정 필드 주입도 테스트한다. 표본 검사 도구를 서비스 코드로 가져오지 않는다.

`evaluator.py`의 `evaluate`는 그룹 내부를 먼저 AND/OR로 결합한 뒤 독립 조건과 각 그룹
결과를 AND로 결합한다. OR의 단일 미충족을 전체 탈락으로 쓰지 않는다. 조건이 없으면
`no_requirements=True`로 구분하고 전체는 충족이다. 같은 그룹의 연산자가 충돌하면 해당
그룹은 확인 필요이며 구조 사유를 남긴다. 중복 조건 ID·30개 초과 조건은 거절한다.
중첩 구조·알 수 없는 연산은 계약에서 거절하며 평탄화하지 않는다. API는 구조 문제를
확인해야 한다. 현재 공개 공고 계약은 모순/중첩 그룹을 저장 전에 거절하며, API가 손상된 저장 구조를 만나면 503으로 거절한다. 연산자를 추측해 직렬화하지 않는다.

그룹·독립 조건의 전체 판정도 48개 기대값과 대조한다. AND/OR 진리표 18개 조합,
분리된 그룹의 AND 결합, 연산자 충돌·중복 ID·중첩 입력, 조건 없음, 프로필/기준일
변경 후 재평가를 검증한다. 결과는 불변 튜플이며 판정 캐시를 두지 않는다.

HTTP API·확정본·소유권·공고 승인 검사는 아래 #60 구현에 연결했다.
이 규칙의 충족 결과는 접근 권한이나 신청 성공을 의미하지 않는다. 실제 공고·배포 환경 검증은 남아 있다.

## 확정 정보의 자격 대조 API (W08-03 · #60)

`POST /api/v1/opportunities/{id}/eligibility`는 `profile` 참조와 화면의 `opportunity_version`만 받는다. 원문 프로필·판정·승인 필드를 보내면 422다. 세션·CSRF·일반 API 분당 한도를 적용하고, 해당 주체의 현재 확정 스냅샷과 승인된 최신 공개 공고 포인터를 서버에서 조회한다. 현재 회원 인증은 미연결이므로 `kind=saved`는 401이다.

조건마다 실제로 비교한 확정 사용자 값·원문 근거·결과·확인 사유를 반환한다. 미확인 null과 없음 확인 빈 배열을 바꾸지 않으며 희망 지역을 거주지로 사용하지 않는다. 응답은 `EligibilityUserValue`로 단일 Region과 빈 배열을 표현한다. 조건 피연산자의 `RequirementValue` 제약은 완화하지 않는다.

미해석·이름 동등성 미검증은 `unclear_requirement`, 없는 사용자 값은 `missing_profile_value`, 누락한 기준일은 `reference_date_missing`, 연령 경계는 `age_boundary`로 전달한다. 같은 그룹 안의 단일 미충족을 OR 그룹 전체 탈락으로 만들지 않는다. 검수된 필수조건이 없으면 `no_requirements=true`를 별도로 반환한다.

모델·판정 캐시·사용자 자료 저장을 사용하지 않는다. 자동 재대조만으로 체험 유휴 시간을 연장하지 않는다. 초안을 수정하는 동안에는 이전 확정본으로 계산하며 재확정 후 이전 참조는 409다. 새 참조와 새 공개 버전으로 요청하면 매번 다시 계산한다. 미승인 새 공고는 평가 대상으로 사용하지 않고 현재 공개본을 사용한다. 모집 마감·변경 검토에 따른 추천/지원서 이용 가능 여부는 별도 업무 검사이며 조건 충족이 신청 가능·선발을 보장하지 않는다.

결과 반환 직전에도 프로필 참조와 공개 공고 버전을 다시 검사해 도중 만료/재확정/공개 변경을 발견하면 결과를 버린다. Redis와 SQL의 전역 트랜잭션을 보장하는 구현은 아니다. 응답에 정확한 기준 참조·평가 시각을 포함하며 이후 변경에는 새 요청이 필요하다.

`test_eligibility_api.py`는 소유권·위조 본문·빈/미확인 자격·거주/희망 구분·OR·연령 경계·원문·상태 변경을 검사한다. 실제 Redis 확정본과 SQLite/PostgreSQL 공개 포인터를 쓰는 HTTP 시험은 CSRF, 미확정 편집 중 이전 확정본 사용, 재확정 후 409/재계산, 공고 공개 버전 변경 후 409/재계산을 확인한다. 2026-10-18 격리된 실제 Redis 7.0.15·PostgreSQL 16.15에서 전체 백엔드 801개가 통과했고 건너뜀은 없었다. 실제 기관의 자격 해석·회원 저장본·배포/브라우저 검증은 별도다.
