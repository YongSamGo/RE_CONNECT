# 자격 비교 규칙 구현·검증 기록

관련 이슈: #58 (W08-01). 기준: Plan/02 §4, Plan/04 F07.

`backend/app/modules/eligibility/rules.py`의 `compare_condition`은 검증된
`ProfileContent`와 `Requirement`를 받아 조건 ID·3상태 결과·고정된 사유 코드만
돌려주는 순수 함수다. DB, LLM, 시계, 로그를 사용하지 않는다. 필드·연산·값 허용표는
`backend/app/contracts/requirement.py`를 사용한다. 정의되지 않은 필드는 계약에서 거절한다.

- 미확인 null과 없음 확인인 빈 배열을 구분한다. 거주는 희망 활동 지역과 구분한다.
- 출생연도와 조건의 기준일로 가능한 나이 범위 전체를 비교한다. 생일을 추정하지 않는다.
- 자격·교육명은 정확히 같아야 충족이다. 부분 일치·동일 종목의 다른 등급은 확인 필요다.
  공인된 상하·동등 관계표가 확보되지 않았으므로 자동 인정 목록은 비워 둔다.
- 미해석 조건·검수 필요 조건은 확인 필요다. 지원 여부·자격 판정은 LLM으로 결정하지 않는다.

평가 표본 48건의 모든 조건별 기대값을 서비스 코드와 직접 대조한다. null/빈 배열,
다른 자격 등급, 거주·희망 지역 혼동, 시간 경계, 연령 범위, 허용되지 않은 연산·형식과
클라이언트 판정 필드 주입도 테스트한다. 표본 검사 도구를 서비스 코드로 가져오지 않는다.

HTTP API·확정본·소유권·공고 승인 검사는 #60, AND/OR 전체 판정은 #59에서 연결한다.
이 규칙의 충족 결과는 접근 권한이나 신청 성공을 의미하지 않는다. 실제 공고·배포 환경 검증은 남아 있다.
