# 확정 경험 근거의 역할 후보 (W08-04 · #61)

`GET /api/v1/journeys/{journey_id}/roles`는 실제 확정 경험 ID를 근거로 역할 후보를 반환한다. 미확정이면 409, 다른 주체/만료/없는 체험은 동일한 404다. 세션 소유권·일반 API 분당 한도를 검사하고 `Cache-Control: no-store`로 응답한다. AI·외부 요청·후보 캐시는 사용하지 않으며 GET으로 체험 수명을 연장하지 않는다.

`profile_version`을 생략하면 현재 확정본을 조회한다. 명시한 과거 버전이 있으면 해당 불변 확정본으로 대조하고 응답에도 그 버전을 명시한다. 없는 버전은 409다. 계산 도중 체험 리비전이 바뀌면 결과를 버리고 409로 다시 조회하도록 한다.

## 역할 사전과 일치 규칙

사전은 SQL `RoleDefinition` 테이블이며 `CatalogRole`로 저장값을 검증한다. DB가 없거나 구조가 잘못됐으면 503이며 대체 후보를 만들어 반환하지 않는다. 이름 50자·설명 300자는 공개 계약 한도이며 길이를 잘라 정상 자료로 만들지 않는다. 현재 조회 상한은 사전 500개, 응답은 최대 20개다. 후보는 연결 경험 수 내림차순·역할 ID 순으로 정렬하며 이 순서를 자격이나 선발 가능성 점수로 표현하지 않는다.

확정 경험 각각의 `skill_tags`를 공백 정리·대소문자 통일 후 사전의 태그와 대조한다. 사전의 `aliases`는 `{alias, skill_tag}` 목록이며 대상은 해당 역할에 있는 정식 태그여야 한다. 중복/충돌 별칭을 거절하고 확인되지 않은 동의어·유사 문자열·정규식을 추측하거나 실행하지 않는다.

`experience_rules`가 빈 목록이면 사전 태그 중 하나 이상이 같은 경험에 있어야 한다. 규칙이 있으면 `{operator: all|any, skill_tags: [...]}` 중 하나가 그 **한 경험 안에서** 성립해야 한다. 서로 다른 경험의 태그를 합쳐 복합 역량처럼 만들지 않는다. 규칙에 없는 태그나 다른 연산·코드 실행 필드는 거절한다.

후보의 근거에는 해당 확정 경험의 실제 ID와 그 경험에 있던 원래 태그를 반환한다. 별칭의 정식 태그를 새로운 프로필 사실로 쓰지 않는다. 프로필 전체의 `skills`나 경험 설명만으로 임의 경험 ID를 붙이지 않는다. 근거가 없으면 `items=[]`이며 화면은 일반 공개 공고 탐색을 안내해야 한다. 후보·자격·채용 가능을 임의로 보장하지 않는다. 실제 화면 연결은 #84의 범위다.

## 초기 사전과 변경 책임

마이그레이션 `0003_initial_role_catalog`는 OpenAPI 예시의 `reading_companion`(낭독)·`library_assistant`(자료 정리)만 초기값으로 추가한다. 예시에 없는 별칭·자격 관계를 만들어 채우지 않는다. 같은 ID가 이미 있으면 운영자가 만든 행을 덮어쓰지 않는다. 다운그레이드에서도 기존 공고 참조·운영자 수정을 보호하기 위해 데이터 행을 지우지 않는다. 스키마 전체를 내리는 기존 base 롤백과는 구분한다.

역할·태그·별칭·복합 연결 기준의 의미 검토는 운영 사전 관리 책임이다. `CatalogRole`의 구조 검증이 의미상 동등성이나 활동 자격을 인증하는 것은 아니다. 사전 수정 경로에서도 같은 검증을 사용해야 한다. 데이터 테이블의 JSON 열에 임의 값을 직접 넣은 경우 API는 구조 오류를 거절한다.

현재 체험의 제외 상태는 후보의 `excluded`에 표시하며 확정 프로필에 복사하지 않는다. `PUT /journeys/{id}/role-exclusions`는 현재 `base_revision`과 역할 ID 전체 목록을 받아 제외 상태를 교체한다. 빈 목록은 모두 복원하며 사전 DB 장애 중에도 복원할 수 있다. 중복·형식 오류·사전에 없는 역할은 422, 오래된 리비전은 409다. 소유한 확정 체험과 CSRF 검사를 통과해야 하며 원자적으로 리비전을 증가시킨다. 확정본·초안·프로필 변경 표시는 바꾸지 않는다. 맞춤 추천은 제외 역할 중 하나라도 공고 역할과 겹치면 해당 공고 전체를 제외한다([추천 안내](recommendations.md)). 공개 공고 검색에는 이 개인 선택을 적용하지 않는다.

## 검증

`GET /journeys/{id}/role-exclusions`는 확정한 소유 체험의 전체 제외 목록과 현재 리비전을 반환한다. 최대 20개 후보 밖의 선택까지 보존해 전체 교체 PUT을 구성하기 위한 조회다. 사전 SQL을 요구하지 않으며 GET으로 수명을 연장하지 않는다. 서버 검사는 후보 조회와 같고 응답은 no-store다. [프로필 화면 연결 범위](../../frontend/src/features/profile/SERVER.md)를 따른다.

`test_roles.py`는 실재 경험 근거·전역 역량만으로 후보 생성 금지·명시 별칭·원래 태그 보존·같은 경험의 복합 규칙·정렬/상한·잘못된 별칭/연산·미확정/타인/없는 버전을 검사한다. SQLite와 PostgreSQL에서 초기 사전 마이그레이션·기존 운영 행 보존·구조 오류 거절을 검증한다. 실제 Redis 확정본과 SQL 사전을 함께 쓰는 HTTP 시험도 포함한다.

`test_role_exclusions.py`는 제외/복원·프로필 불변·입력 검증을 검사하고 실제 Redis에서 동시 갱신의 단일 성공, SQLite/PostgreSQL 사전을 연결한 HTTP에서 CSRF·소유권·리비전·알 수 없는 역할 거절을 확인한다.

2026-10-18 격리된 Redis 7.0.15·PostgreSQL 16.15에서 전체 백엔드 823개가 통과했고 건너뜀은 없었다. 시험 후 서버를 종료했다. 기관별 실제 역할 사전의 의미 검수·배포 빌드·브라우저/기기 여정 검증은 별도다.

관련 KISA 보안약점은 부적절한 인가(SEC-02), 보안기능 결정에 사용되는 부적절한 입력값(INP-15), 오류 메시지 정보노출(ERR-01)이다.
