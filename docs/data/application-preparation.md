# 공식 신청 준비 안내 (W09-01 · #66)

`GET /api/v1/opportunities/{opportunity_id}/preparation`은 공개 공고의 공식 서류·접수 방법·절차·출처·마감 상태를 반환한다. [공개 공고 조회](public-opportunities.md)와 같은 승인 공개 포인터를 한 번 조회해 필요한 필드만 전달한다. 응답 계약은 [OpenAPI](../api/openapi.yaml)의 `Preparation`이다.

## 원문과 확인 필요 상태

- 접수 방법 `online`·`phone`·`visit`·`email`·`mixed`와 공식 안내문을 그대로 전달한다. 전화·방문·이메일 접수에도 `application_url`은 공식 접수 **안내** 경로이며 대리 접수/신청 완료를 뜻하지 않는다.
- `required_documents=null`은 서류가 명시되지 않았다는 뜻이다. 사용자에게 공식 안내 확인을 요청해야 하며 이력서·자격증·주민등록등본 등을 임의로 필수 추가하지 않는다. `[]`와 실제 명시 목록도 그대로 유지한다.
- `recruitment_status=unknown`과 `change_pending=true`를 그대로 전달해 확인이 필요한 상태를 숨기지 않는다. 종료된 공개 공고도 상세와 동일하게 조회할 수 있으며 `closed` 상태를 유지한다.
- 날짜만 있는 마감에 임의 시각을 만들지 않는다. 마감 경과/신선도 판단은 기존 공고 수명 정책과 같다.
- 미승인 새 버전의 서류·설명은 공개하지 않는다. 공개 포인터가 제거되거나 비공개인 공고는 404다. 검수 전 새 버전이 있어도 현재 공개 버전의 자료만 반환한다.

## 요청과 보안 경계

이 경로는 로그인·AI 동의·Redis·모델 없이 조회할 수 있다. 응답에 세션 쿠키를 발급하지 않고 `Cache-Control: no-store`와 서버 요청 ID를 붙인다. DB가 없거나 저장된 계약이 깨졌으면 고정 503 오류를 반환한다.

이 API는 LLM을 호출하거나 원문의 지시를 실행하거나 외부 URL을 요청하거나 리다이렉트하지 않는다. URL은 기존 HTTPS 계약으로 다시 검증한다. 공식 출처/경로의 진위와 허용 목록은 수집·운영자 검수에서 책임진다. HTTPS 형식 검사를 공식 기관 인증으로 해석하지 않는다. 프론트엔드는 안내문·서류를 일반 텍스트로 표시하고 임의 HTML로 해석하지 않는다.

## 검증

`backend`에서 `python -m pytest tests/test_preparation.py -q`를 실행한다. 가상 공고를 실제 SQLite에 저장한 HTTP 시험으로 5가지 접수 방법, 누락/빈/명시 서류, 공개/미승인/숨김 경계, 마감 정밀도·상태, 원문 지시문·스크립트의 비실행, 잘못된 저장 URL과 DB 장애의 거절을 검사한다. 고정 기준일로 시험해 시간 경과로 테스트가 달라지지 않게 한다.

동일한 공개 포인터·접수 방법 시험은 `PERSISTENCE_TEST_DATABASE_URL`이 있는 PostgreSQL에서도 실행한다. 2026-10-18 후속 격리 시험에서 PostgreSQL 16.15에 연결해 해당 시험 23개가 모두 통과했다. 전체 백엔드도 실제 PostgreSQL·Redis와 함께 633개 통과·건너뜀 없음으로 확인했다. 실제 기관 접수, 배포 DB, 프론트엔드 #71·#86 통합 사용성은 별도 검증이 필요하다. 외부 기관에 신청서를 전송하지 않았다.

관련 KISA 보안약점은 부적절한 인가(SEC-02), 크로스사이트 스크립트(INP-02), 신뢰되지 않은 URL 주소로 자동접속 연결(INP-05), 오류 메시지 정보노출(ERR-01)이다. 공격 표본은 의도한 테스트 데이터이며 실행 지시가 아니다.
