# 맞춤 공고 후보와 추천 (W08-06/07 · #63 · #64)

후보 계산은 공개 포인터가 가리키는 승인본만 읽는다. 모집 중·마감 전·공고별 마지막 정상 확인 48시간 이내인 공고만 대상으로 하고, 미래 확인 시각·중요 변경 검수 대기는 제외한다. 48시간 경계는 포함한다. 제목·설명만 바뀐 새 검수본은 보류 사유가 아니며 중요 변경 목록은 Plan/02 §6을 따른다. 검수 대기 중인 종료 방향 변화도 추천을 보류한다.

지역은 확정 프로필의 희망 지역과 선택 필터를 모두 충족해야 한다. 시·도 전체 선택은 그 안의 시·군·구를 포함하지만 세부 지역 선택에 미확인 구를 임의로 넣지 않는다. 원격 가능이 명시적으로 `true`인 공고는 지역 제한을 적용하지 않는다. 활동 유형·유급 선호와 선택 필터는 교집합으로만 적용하며 미확인 유급은 명시적 유/무급 선택에 맞지 않는다.

체험에서 제외한 역할 중 하나라도 복합 역할 공고의 `role_tags`와 겹치면 그 공고 전체를 제외한다. 일반 공개 검색은 이 개인 선택이나 추천 신선도 필터로 좁히지 않는다. 자격은 공통 평가기로 전체 AND/OR를 계산해 `not_satisfied`만 제외한다. OR의 일부 조건 실패로 전체 충족 후보를 빼지 않는다. `unknown`과 검수된 필수조건 없음은 구별해 유지한다. 구조 오류는 정상 판정으로 바꾸지 않는다.

SQL 조회는 조건에 맞는 승인본 5,000개까지 처리하며 초과하면 503으로 중단한다. 앞부분만 임의 추천하거나 필수조건을 완화하지 않는다.

## 계산과 HTTP

`POST /api/v1/recommendations`는 CSRF·세션·일반 API 한도와 최신 확정 프로필 소유권을 검사한다. `saved` 참조는 실제 회원 저장본 인증 구현 전 401이다. 미확정 초안은 409이며 수정 중에는 마지막 확정본으로 계산하고 `based_on_previous_confirmed=true`를 표시한다. 재확정 뒤 옛 참조는 409다. AI·외부 요청·추천 결과 저장·개인 캐시는 사용하지 않는다.

태그의 공백·대소문자를 정규화하고 역할 사전의 명시적 별칭만 동등하게 처리한다. 역할 간 별칭이 다른 정식 태그로 충돌하면 503으로 중단한다. 역량 점수는 프로필/경험 역량 집합과 공고 역량 집합의 Jaccard이며 키워드는 확정 경험 설명·기간·역량의 두 글자 이상 공백 토큰 집합으로 계산한다. 공고 제목·공식 설명·역할 ID/사전 이름·역량에서 정확한 토큰으로 대조한다. 설명이 없으면 추정하지 않는다.

점수는 `0.7 × 태그 점수 + 0.3 × 일치 키워드 수 / 프로필 키워드 수`이며 유리수로 계산해 동점이 부동소수 오차로 바뀌지 않게 한다. 빈 분모는 0이다. 0점이거나 경험별 실제 태그/토큰 근거를 만들 수 없는 공고는 제외한다. 전역 역량만 맞는 경우 임의 경험 ID를 연결하지 않는다. 근거 태그는 원래 프로필 값을 보존하고 역할 근거도 사전의 경험 연결 규칙을 통과한 경우에만 넣는다. 50자를 넘는 단일 토큰도 계산에는 포함하지만 공개 `matched.keywords`의 50자 한도 때문에 표시 목록에서는 생략한다. 경험 ID 연결은 유지한다.

점수 내림차순, 한국 마감 날짜/알려진 시각, 공고 ID 순으로 상위 5건을 반환한다. 같은 날 날짜만 있는 마감은 정확한 시각이 있는 공고 뒤에 두고 시각을 만들어 응답하지 않는다. 마감 미확인 후보는 동점에서 마지막이다. 응답은 내부 점수 없이 순위·실제 확정 경험 ID·공개 공고 버전·전체 자격/확인 필요 조건 수를 담는다. 0건이어도 조건을 완화하지 않는다.

반환 직전 공고 공개 상태/버전·체험 수명/소유권·확정 버전·제외 선택 리비전을 재검사해 계산 도중 바뀌면 결과를 버린다. DB/Redis 전체의 분산 트랜잭션을 제공하는 것은 아니며 실제 배포·기관 공고 품질·브라우저/기기 검증 완료를 뜻하지 않는다.

`test_recommendation_filters.py`는 필수 필터·정확한 신선도 경계·지역 미확인·선택 필터 교집합·복합 역할 제외·OR 전체 판정을 검사한다. SQLite/PostgreSQL에서 공개 포인터와 중요 변경 보류를 함께 확인했다. 2026-10-18 격리된 Redis 7.0.15·PostgreSQL 16.15에서 전체 백엔드 848개 통과, 건너뜀 없음이다.

`test_recommendations.py`는 정확한 계산값·별칭·무근거 제외·날짜 동점·상위 5건·계산 도중 상태 변경을 검사한다. 실제 Redis와 SQLite/PostgreSQL을 연결한 HTTP에서 미확정·CSRF·타인 참조 차단, unknown 유지, 제외 반영, 수정 중 확정본 표시와 재확정 후 구 참조 거절을 확인한다. 프론트 계약 시험은 실제 ASGI 응답 전체를 원본 OpenAPI와 대조하고 점수 필드의 외부 노출을 거절한다. 이 계약 시험의 프로필 저장소는 메모리 시험 구현이며 실제 Redis 증거는 백엔드 통합 시험이다.

2026-10-18 최종 회귀: 실제 Redis/PostgreSQL 전체 백엔드 859개 통과·건너뜀 없음, 프론트 계약 15개·lint·API 타입 대조·빌드 통과. 시험 서버는 종료했다. 기관별 검수 실제 공고×페르소나 평가는 #65에서 수행해야 한다.

관련 KISA 보안약점은 보안기능 결정에 사용되는 부적절한 입력값(INP-15), SQL 삽입(INP-01), 오류 메시지 정보노출(ERR-01)이다.
