# 자료 참조 읽어주기

`POST /api/speech`는 OpenAPI의 참조와 부분 번호만 받는다. 자유 문장·화자·모델·URL·소유자 입력은 거절한다. 공개 공고도 현재 서버 AI 처리 동의가 필요하다.

- 공개 공고의 최신 버전과 허용 필드, 소유 체험의 AI 질문 ID, 소유 임시 지원서의 정확한 리비전/필드만 해석한다. 사용자 발화 ID는 읽지 않는다. 저장 지원서는 회원 인증·저장소 구현 전까지 401이다. 프로필 참조는 계약에 없다.
- 서버 원문을 최대 2,000 Unicode 문자씩 나누고 공백뿐인 조각은 제외한다. 범위를 벗어난 부분과 빈 필드는 422이며 모델을 호출하지 않는다. 응답은 WAV와 `X-Speech-Segment-Count`다.
- 내부 고정 음성 어댑터와 공통 추론 제한을 사용한다. 실제 모델 서버가 없으면 503이며 외부 서비스로 우회하지 않는다. 런타임 경계는 [프로토콜](../../speech/PROTOCOL.md)을 따른다.
- 생성 뒤 자료를 다시 읽고, Redis 원자 완료에서 세션 수명·AI 동의 버전 및 최초 부여 시각·체험 소유권/세대/수명/리비전·지원서 원문을 확인한다. 같은 버전 동의를 철회 후 다시 부여해도 이전 작업의 결과를 반환하지 않는다.
- 완료는 실행 저널만 바꾼다. 체험 리비전·지원서/프로필 본문·승인·체험 유휴 시각/TTL은 변경하지 않는다. HTTP 사용자 활동에 따른 세션 처리는 기존 세션 정책을 따른다.
- 음성은 Redis/파일에 저장하지 않는다. 완료 키 재사용은 409이며 다시 들을 때 새 키를 사용한다. 생성 중 변경·종료·동의 철회 결과는 폐기한다. 공개 SQL 자료 변경은 생성 후 재조회로 검사하며 Redis와 분산 트랜잭션을 구성하지 않는다.

공고·실제 응답으로 받은 AI 질문·서버에 반영한 초안에 읽기 버튼을 연결했다. 편집 중 초안은 읽지 않으며 항목 변경 시 이전 플레이어와 요청을 정리한다. 대화 새로 고침에서 서버 질문 ID를 얻지 못한 경우 ID를 만들어 전송하지 않는다. 실제 시작 화면에서 초기 질문 ID를 전달하는 작업은 #81과 함께 남아 있다.

검증: 실제 Redis/PostgreSQL 전체 1,025개 시험(건너뜀 없음). TTS API 17개는 권한·버전·분할·동의 재부여·생성 중 수정/삭제·멱등 완료 및 읽기 후 리비전/본문/TTL 불변을 검사한다. 모델 전송은 시험 모형이며 실제 한국어 음질·고정 화자·EC2/GPU 성능·모바일 재생을 검증한 결과가 아니다. 운영 동의 정보 미정으로 실제 시작은 계속 비활성이다. #35의 안전한 자동 1회 재시도는 아직 구현하지 않았다.
