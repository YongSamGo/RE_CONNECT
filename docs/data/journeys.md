# 익명 체험 생성·수명 (W05-01 · #36)

`POST /api/v1/journeys`는 현재 AI 처리 안내문에 동의한 익명 세션의 체험을 만든다. 요청/응답은 [OpenAPI](../api/openapi.yaml)의 `JourneyCreate`·`Journey`·`Message`를 따른다. `Idempotency-Key` UUID와 CSRF 토큰·허용 Origin이 필요하다. 체험 ID·초기 메시지 ID·생성 시각·리비전은 서버가 만든다.

## 동의와 초기 상태

현재 안내문이 설정되지 않았거나 현재 버전의 AI 동의가 없으면 생성하지 않는다. 수락 여부를 서비스에서 검사하고 실제 Redis 생성 직전에도 같은 세션의 주체·수명·현재 동의를 다시 검사한다. 헤더·본문의 회원 ID를 권한으로 사용하지 않는다.

초기 리비전은 1, 확정본은 `null`이다. 첫 질문은 계약의 고정 문구인 “지금까지 해 오신 일 가운데 기억에 남는 일을 한 가지 들려주세요.”다. 이 단계에는 LLM 호출이나 프로필 승인·영구 저장이 없다. 대화에서 실제 추출하는 #37과 구분한다.

회원 인증과 자기 저장 프로필 가져오기는 #42·#73에서 연결한다. 현재 공개 라우터는 익명 세션만 처리하므로 `saved_profile`이 있으면 401이다. 사용자 입력으로 저장 프로필을 확정본처럼 복사하지 않는다.

## 생성 멱등성과 한도

Redis 단일 스크립트가 세션/동의 검사, 최초 생성, 초기 상태, 생성 결과 참조 저널, 주체 하루 집계를 함께 확정한다. 외부 모델 실행·DB 트랜잭션을 이 스크립트 안에서 수행하지 않는다.

- 동일 주체·같은 키·같은 입력의 재전송은 같은 살아 있는 체험을 반환하며 추가 생성·한도 차감이 없다. 편집 후 재전송하면 해당 체험의 현재 리비전과 수명을 반환한다.
- 다른 입력으로 키를 재사용하면 409다. 저널은 최초 생성부터 최대 24시간이며 재조회로 연장하지 않는다. 이미 삭제/만료된 체험을 같은 키로 재생성하지 않는다.
- 일반 API의 주체/IP 분당 한도를 먼저 적용한다. 위조 전달 헤더가 아닌 신뢰 처리 후 연결 IP를 사용한다.
- 익명 체험 생성은 기존 생성·전사 정책과 같은 IP별 하루 60회 집계를 사용한다. IP는 서버 HMAC 식별값으로 집계하며 원 IP를 Redis 한도 필드에 저장하지 않는다.
- 고정 첫 질문에는 실제 추론이 없어 전역 **추론 실행** 500회 집계와 GPU 슬롯을 소비하지 않는다. 기존 진행 중 GPU 작업/슬롯을 해제하거나 바꾸지 않는다.
- KST 날짜가 바뀌면 기존 추론 제어 정책과 같은 규칙으로 일일 집계를 교체한다. 운영 제어 epoch·식별키·비만료 해시가 없거나 맞지 않으면 503이다. 앱 시작에서 제어 해시를 자동 초기화하지 않는다.

회원 계정별 정책은 인증된 `InferenceIdentity`의 기존 예산 계산에 있으나 현재 체험 HTTP에서 회원을 인증했다고 주장하지 않는다. 새 경로를 회원 인증에 연결할 때 익명 IP 한도로 대신하지 말고 실제 인증 계정의 예산과 저장본 소유권을 함께 적용해야 한다.

## 수명과 후속 결과 경계

체험 상태는 기존 요청 제어 자원의 `g:1` 리비전과 수명 메타데이터에 결합한다. 메타데이터에는 최소 소유 주체·세션 digest·체험 세대·안내문 버전·초기 메시지 ID·생성/마지막 활동 시각만 기록한다. 초기 질문 본문은 고정 문구라 보관하지 않는다.

생성 후 절대 수명은 2시간이며 유휴 수명은 30분이다. 실제 키 TTL은 유휴/절대 수명 중 짧은 쪽이다. `JourneyService.load(..., user_activity=False)`는 읽기만 하고 TTL을 갱신하지 않는다. 실제 사용자 행동의 업무 경로에서만 `user_activity=True`로 마지막 활동을 갱신하며, 절대 수명은 늘리지 않는다. 세션 수명 갱신도 해당 업무 라우터에서 `require_session(..., user_activity=True)`로 처리해야 한다.

조회는 세션·체험·동의·소유권을 재검사하고 실패하면 같은 404/동의 오류로 거절한다. `load`는 후속 업무 서비스용이며 계약에 없는 공개 `GET /journeys/{id}`를 추가하지 않았다. 반환된 내부 `JourneyRecord.guard`는 #27의 원자 완료 검사와 호환된다. 리비전 검사는 클라이언트가 보낸 승인 여부를 신뢰하지 않는다.

## 종료·삭제 (#43)

`DELETE /journeys/{id}`는 CSRF·세션·일반 API 한도 뒤에 현재 주체/세션 소유 자원만 지운다. 삭제에는 AI 처리 동의를 요구하지 않는다. 없는 체험·이미 만료된 체험·다른 주체의 같은 ID도 동일한 204이며 타인의 자원에는 영향을 주지 않는다. 남아 있는 만료 메타도 소유권을 확인해 정리한다. 삭제와 요청 완료가 경합해도 원자 Redis 스크립트의 실행 순서와 무관하게 삭제가 끝난 뒤 자료가 남거나 다시 생기지 않는다.

하나의 Lua 실행에서 리비전 키·수명 메타 해시(초안·불변 확정본·역할 제외 포함)·최대 256개 연결 요청 저널·인덱스를 삭제한다. 삭제가 세션 전체나 다른 체험을 지우지는 않는다. 생성 멱등 저널은 24시간 이내 참조/해시만 유지해 같은 생성 키의 늦은 재전송으로 삭제 자료가 다시 생기지 않게 한다. 새 체험은 새 생성 키/새 ID로 시작하며 이전 확정본을 이어받지 않는다.

프로필 화면의 `종료하고 삭제`는 사용자가 확인한 후 실제 DELETE를 호출한다. 실패하면 편집 내용을 유지하고, 204 뒤에만 화면 메모리·진행 요청을 정리해 시작 화면으로 이동한다. 단순히 화면 입력을 닫는 버튼과 구별한다. 브라우저 종료 감지를 서버 삭제 보장으로 사용하지 않으며 TTL을 계속 적용한다. 새로고침 시 자동 복원/대화 조회 경로는 추가하지 않았다. 전체 시작·재진입 정책과 모든 후속 체험 화면의 종료 연결은 #81/#89에서 완성해야 한다.

현재 Redis 메타 해시 밖에 실제 음성/전사/지원서 본문을 쓰는 기능은 아직 연결하지 않았다. 후속 저장 경로는 같은 원자 경계에 결합하고 이 DELETE에도 정리를 추가해야 한다. 동의 철회·회원 영구 자료 삭제는 #78의 별도 범위다.

`test_journey_end.py`는 실제 Redis HTTP의 CSRF·소유권·204 멱등·전체 키 삭제·같은 생성 키 재생성 차단·새 체험 분리, 실제 동시 완료와 삭제 4회, 만료/동의가 없는 상태의 소유 자료 정리를 검사한다. 2026-10-18 실제 Redis/PostgreSQL 전체 백엔드 864개 통과·건너뜀 없음이며 시험 서버를 종료했다.

## 검증과 남은 조건

2026-10-18 후속 격리 검증에서 Redis 7.0.15·PostgreSQL 16.15를 실제 실행해 전체 백엔드 633개가 통과했고 건너뛴 시험은 없었다. 이 결과에는 체험 생성·공유 한도·동시 요청·유휴/절대 수명과 수동 편집의 실제 Lua 시험이 포함된다. 시험 후 서버를 종료했다. Docker 배포 빌드·EC2·실제 회원/브라우저 흐름 검증은 별도다.

### 직접 프로필 작성·편집 (W05-04 · #39)

`GET/PATCH /api/v1/journeys/{journey_id}/profile`은 현재 미확정 초안을 조회/전체 교체한다. `ProfileContentInput`의 공통 필드·지역·요일·시간·문자열/목록 범위를 그대로 검증한다. 입력 본문은 `draft`와 `base_revision`만 받으며 소유자·확정 상태·권한을 받지 않는다.

직접 조회/편집에는 모델 호출이 없어 **AI 동의를 요구하지 않는다**. 기존 체험의 세션 소유권과 유휴/절대 수명은 매번 검사한다. AI 안내문 폐기 자체가 수동 편집 권한을 새로 만들지는 않으며 세션/체험이 없으면 404다. 실제 AI 동의 철회 API가 연결될 때는 계약대로 체험을 삭제하므로 삭제 이후 편집도 거절돼야 한다.

새 경험은 요청의 `id=null`에 대해 서버가 UUID를 부여한다. 기존 경험 ID는 현재 해당 체험 초안에 있는 것만 보존할 수 있다. 다른 체험·삭제한 경험의 ID나 중복 ID를 끼워 넣으면 거절한다. 입력에 없는 기존 경험은 초안에서 제거된다. 이전 확정본을 덮어쓰지 않는다.

세션/체험 검사·기준 리비전 CAS·초안 JSON 쓰기·리비전 증분·실제 활동의 유휴 갱신을 한 Lua 스크립트에서 수행한다. GET은 TTL을 갱신하지 않는다. PATCH만 유휴 시간을 갱신하며 절대 2시간은 연장하지 않는다. 별도 읽기 뒤 Python에서 만든 경험 ID는 같은 기준 리비전이 여전히 유효할 때만 저장된다.

수동 교체는 기존 AI 추출 근거를 빈 목록으로 지워 수정된 항목에 오래된 근거를 붙이지 않는다. 확정본이 있다면 이를 유지하고 `has_unconfirmed_changes=true`로 표시한다. 초기 초안에서는 확정본이 `null`이며 추천에 부족한 경험·지역·활동 유형을 계산한다. 확정 API와 버전별 스냅샷 생성은 #40에서 연결한다. `ConfirmedVersion` 계약은 `version`과 `confirmed_at`이며 별도 ID로 바꾸지 않는다.

`test_manual_profile.py`는 AI 미동의 직접 편집·서버 ID·ID 보존/삭제·타인/중복 ID 거절·낡은 리비전·이전 확정 상태·HTTP CSRF/소유권·공통 필드/지역 검증을 검사한다. 실제 Redis 전용 시험에는 AI 동의 필드가 없는 수동 편집, 자동 조회 TTL 비갱신, 동시 CAS 승자 한 명, 읽기 이후 삭제와 쓰기 경합을 포함한다. 가짜 저장소 시험을 실제 Redis 경합 통과로 표시하지 않는다.

`backend`에서 `python -m pytest tests/test_journeys.py -q`로 실행한다. 가짜 저장소를 쓰는 HTTP 시험은 정상 생성·재전송·서버 질문/ID/시간·현재 동의·CSRF·멱등키·회원/승인 사칭 거절과 연결 IP 예산 선택을 검증한다. 가짜 저장소의 성공을 Redis 원자성 증거로 사용하지 않는다.

실제 Redis 시험은 `PERSISTENCE_TEST_REDIS_URL`에서만 실행하며 생성 멱등/공유 한도, 80개 동시 요청의 60개 승자, 자동 조회 TTL 비갱신·활동 시 절대 수명 상한, 삭제 후 재생성 차단, 타 주체/세션 폐기, #27 결과 완료와의 호환을 검증한다. 로컬에서 건너뛴 항목은 통과로 세지 않는다. 실제 Redis/EC2·회원 로그인·저장본 복사·#37 대화/본문 쓰기·#43 종료/철회 자료 정리는 아직 별도 검증이 필요하다.

관련 KISA 보안약점: 부적절한 인가(SEC-02), 크로스사이트 요청 위조(INP-11), 경쟁조건: 검사시점과 사용시점(TOCTOU, TIM-01), 오류 메시지 정보노출(ERR-01).
