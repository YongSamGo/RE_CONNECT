# 공고 마감·신선도·수집 상태 (W06-05)

관련 이슈: #48. 순수 규칙 구현·로컬 시험 단계다. DB 버전 관리(#47)·수집 실행(#49)·
공개/추천 API(#50/#63) 연결과 실제 공고 검증은 남아 있어 이슈를 종료하지 않는다.

`backend/app/modules/opportunities/lifecycle.py`는 공통 공고 계약을 받아 시간·모집 상태를
평가한다. 외부 통신·저장·로그·LLM·시계 조회가 없고 `now`를 명시적으로 받는다.

| 입력·상태 | 처리 |
| --- | --- |
| 날짜만 있는 마감 | 해당 한국 날짜가 지나면 종료. 마감 당일은 정확한 시각 미확인 표시 |
| 공식 마감 시각 | 시각에 도달하면 종료(이 구현은 마감 시각을 배타적 경계로 해석) |
| 출처에서 종료 확인 | 미래 마감·새 확인 시각으로 다시 열지 않음 |
| 모집 상태 미확인 | 확인 시각이 새로워도 자동으로 모집 중으로 바꾸지 않음 |
| 공고 자체의 마지막 확인 후 48시간 초과 | 모집 상태를 유지하고 추천 보류 |
| 정확히 48시간 | 시간 지연만으로 보류하지 않음(Plan/05 §3의 '초과') |
| 확인 시각 없음·미래 확인 시각 | 추천 보류 |
| 수집 실패·일시 누락 | 공고 종료/삭제·확인 시각 갱신의 근거로 쓰지 않음 |

날짜·시각 동시 입력의 한국 날짜 불일치는 기존 `OpportunityContent` 계약이 거절한다.
시간대 없는 현재 시각과 확인 시각도 거절한다. 정확한 마감 도달 경계는 이 구현의 결정이며
출처가 포함 경계를 별도로 명시하면 정규화 계약과 함께 재검토해야 한다.

`record_collection_attempt`는 마지막 시도와 마지막 성공을 분리한다. 실패해도 마지막 성공을
보존하며, 이전·중복 시도로 새 상태를 덮어쓰지 않는다. 출처 전체 수집의 성공이 개별 공고의
재확인을 의미하지 않으므로 실제 관측하지 못한 공고의 확인 시각은 갱신하지 않는다.
저장소의 동시 실행 CAS·요청 ID 검증은 이 함수가 대신하지 않는다.

추천 가능 결과는 이 모듈의 시간·모집 상태 조건만 통과한 것이다. 공고 승인, 공식 경로,
중요 변경 보류, 프로필 자격, 지역·활동 유형을 후속 서비스가 별도로 확인해야 한다.
공개 목록에서 신선도가 떨어진 이전 승인본을 보여줄지는 공개 서비스가 안내 문구와 함께 처리한다.

시험은 KST 자정 전후·정확한 시각의 전/동일/후, 48시간 ±1마이크로초, 수집 첫 실패·연속
실패·성공 후 누락, 오래된 수집 결과·시간대 누락·성공 불리언 형식을 포함한다.
기준은 Plan/02 §3·§6, Plan/04 F05, Plan/05 §3이다. 이 시간·보관 정책은 공식 보안 가이드의
기준으로 설명하지 않는다. Security/INDEX.md를 검토했고 이 변경에 직접 대응하는 독립 보안약점은 없다.
