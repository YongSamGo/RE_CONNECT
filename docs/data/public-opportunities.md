# 공개 공고 조회 API (W06-07)

`GET /api/v1/opportunities`, `GET /api/v1/opportunities/{id}`를 DB에 연결했다.
세션·동의·Redis·모델 호출 없이 동작하며 쿠키를 발급하지 않는다. DB 장애는
고정 503, 비공개/없는 상세는 같은 404, 잘못된 UUID/검색 조건은 422다.

## 공개 경계

조회는 `opportunity_publications`가 가리키는 **승인된** 버전으로 한정한다.
임의 최신 버전을 선택하지 않으며 출처가 같다는 이유로 검수 대기 자료를 공개하지
않는다. 새 pending에 중요 변경이 있으면 기존 공개본과 `change_pending=true`만
반환하고 대기 원문은 반환하지 않는다. 중요 필드는 [공통 버전 규칙](ingestion-versions.md)을
따른다. 제목만 수정한 pending은 보류하지 않는다. 숨김은 공개 포인터 제거 후 상세와 목록에서 모두
사라진다. 숨김/반려/대기 버전만 있는 공고는 조회할 수 없다.

목록은 open/unknown을 포함하고 closed를 제외한다. 현재 시각이 공식 마감 시각에
도달했거나 날짜만 있는 마감의 한국 날짜가 지났어도 목록에서 제외한다. 상세는
승인된 종료 공고도 보여 주며 #48의 같은 수명 규칙으로 closed를 반환한다. GET이
DB 상태를 변경하지 않는다. 48시간 확인 지연은 추천 보류 기준이며 공고 목록을
임의로 숨기거나 종료로 바꾸지 않는다.

응답은 계약 필드의 허용 목록이다. `source_id`, `external_id`, `content_hash`,
`review_status`를 내보내지 않는다. `source_url`, `application_url`, 원문 일반
텍스트·잘림 표시, 확인·검수 시각을 제공한다. HTTPS/URL 계약을 다시 검증하며
출처별 **공식 호스트/경로 승인**은 수집 설정·운영 검수(#44/#54)의 책임이다.
이 API가 임의 HTTPS 링크의 공식성을 자동 인증하는 것은 아니다.

## 검색·정렬·응답

- `q`: 1~100자. 제목·기관·설명·역할 ID/이름·역량 태그를 검색한다. JSON 배열의
  각 실제 문자열을 조회하여 JSON 구문 문자 자체에 일치시키지 않는다.
- 모든 조건은 SQLAlchemy 바인딩이다. LIKE의 `%`, `_`, `\`도 문자 그대로
  검색한다. 쿼리·테이블·정렬 SQL을 사용자 문자열로 만들지 않는다.
- province/district는 공통 지역 목록, activity_type은 공통 열거형으로 검증한다.
  district 단독 입력의 오류는 `province: required_with`다. 정의하지 않은 필드도
  422로 거절한다. 지역 미상 공고는 지역 필터에 일치하지 않는다.
- 페이지 기본 1, 크기 기본 20/최대 20. DB에서 count/offset/limit을 수행하며
  모든 본문을 메모리로 불러와 거르지 않는다. 전체 범위 밖 페이지는 빈 items와
  total을 반환해 큰 페이지 번호를 DB offset 정수로 넘기지 않는다.
- 정렬은 한국 날짜가 가까운 순이다. 같은 날에 정확한 시각이 있으면 시각순,
  날짜만 있는 공고는 그날의 정확한 시각 공고 뒤에 둔다. 같은 마감은 UUID순,
  마감 자체가 없으면 맨 뒤다. 정렬을 위해 만든 임의 마감 시각을 응답하지 않는다.
- 공개 철회 후 캐시에 본문이 남지 않도록 현재 응답은 `Cache-Control: no-store`다.
  화면은 원문을 HTML로 해석하지 않고 텍스트로 표시해야 한다(#85).

## 검증·남은 연결

SQLite와 CI의 실제 PostgreSQL에서 공개 포인터·마감 경계·검수 대기/숨김/반려,
리터럴 검색·SQL 공격 문자열·JSON 태그/역할 이름, 필터·페이지·동일 마감 정렬을
검증한다. 같은 실제 DB 저장소를 HTTP 경로로 호출하여 Redis/AI가 미설정이어도
200이며 비공개는 404인 것을 확인한다. 정상 공고를 가상 시험 데이터로 심었으며
실제 모집 공고를 확보했다고 주장하지 않는다.

생산 데이터 수집·승인/숨김 API·수집 갱신은 #44~#49/#51/#54에 남아 있다.
실제 출처와 운영 배포 증거까지 확인한 것으로 작업 상태를 통과 처리하지 않는다.
