# 체험 지원서 생성 (#67 부분 구현)

POST /journeys/{id}/drafts는 실제 세션/CSRF/HTTP 한도 뒤에 자기 체험의 최신 확정 프로필 참조와 현재 공개 공고 버전을 검사한다. 미확정·과거 확정 참조·종료·비공개·변경 검토 중·모집 미확인·마지막 정상 확인 48시간 초과/미래 공고를 거절한다. 날짜만 있는 마감의 당일과 정확 시각 마감은 공통 lifecycle 규칙을 따른다. 기존 초안을 생성 입력의 확정 사실로 사용하지 않는다.

manual은 빈 자기소개/지원동기·미승인 revision1을 만들며 모델/AI 동의를 요구하지 않는다. generate는 현재 AI 동의와 서버 추론 주체를 바인딩한 ControlledLLMAdapter의 공통 슬롯/한도를 적용한다. 확정 프로필 사실과 공고 ID/버전·제목·설명은 비신뢰 입력으로 전달한다. 모델은 사실 ID만 선택하고 서버는 허용한 확정 사실의 고정 문구를 자기소개로 조립한다. 공고 설명/모델 자유 문장을 개인 사실로 추가하지 않는다. 지원동기는 추정하지 않고 빈칸과 직접 작성 안내를 반환한다. 길이를 넘는 사실은 문구를 임의 절단하지 않고 제외 안내를 준다. 결과는 자동 승인·회원 저장·외부 신청이 아니다.

from_saved는 저장 문서 ID/버전을 요구하는 계약만 검증하며 실제 회원 인증·암호화 저장본 소유권 연동 전에는 401이다. 다른 모드의 saved_document나 owner/approved 필드를 요청으로 받지 않는다. #67 전체 통과로 기록하지 않는다.

별도 RedisDraftStore는 본문/생성 저널을 소유 체험의 lifecycle 해시 안에 둔다. 세션 주체·세션 수명·해시 소유자/세션 digest·체험 수명/현재 자원·동의(생성 모드) 검사를 Lua에서 원자 수행한다. 예약 토큰과 생성기·확정 버전·체험 revision을 완료 직전에 재검사하고 그 뒤 본문/미승인 초안/완료 재생 응답을 함께 쓴다. 생성 도중 편집·재확정·철회·만료·삭제·세대 교체가 일어나면 저장하지 않는다. #43 삭제와 TTL 만료는 본문·저널을 함께 제거하며 다른 저장 위치에 음성/본문 파일을 만들지 않는다.

같은 키/입력 완료 재생은 원래 응답으로 추론·체험 TTL 갱신을 반복하지 않는다. 현재 확정 버전/공고의 유효성은 재생 전에도 검사하므로 재확정·공고 종료 후에는 이전 생성 요청 재생이 거절될 수 있다. 키의 입력이 다르면409, 처리 중은409+Retry-After, 실패/취소된 키는 새 키로 재시도한다. 한 체험에 초안32개·생성 예약128회 상한을 둔다. 생성은60초 제한이며 timeout/연결 취소 자체를 실제 런타임 종료 확인으로 간주하지 않는다. 모델 슬롯이 남아도 수동 초안을 만들 수 있다.

완료 직전 공고를 SQL에서 다시 읽는다. SQL/Redis 분산 트랜잭션은 아니므로 두 저장소의 완전한 동시 스냅샷을 보장하지 않는다. 편집/승인/저장 전 유효성 검사는 #68/#69/#76에서 각각 연결해야 한다. 현재 지원서 생성에 자격 충족/선발 보장을 붙이지 않는다.

## 편집·명시 승인 후속 (#68)

PATCH /journeys/{id}/drafts/{draft_id}는 자기 체험의 지원서 본문 전체를 바꾸고 개별 지원서 revision을 올리며 approved_at을 반드시 null로 돌린다. 체험/프로필 리비전을 편집 기준으로 사용하지 않는다. 원래 profile_version/opportunity/mode/draft_id는 유지한다. 근거 공고가 닫혀도 사용자가 적은 내용을 편집할 수 있으나 승인은 현재 근거가 유효할 때만 가능하다. 수동 편집·명시 승인은 AI 호출/동의를 요구하지 않는다.

POST .../approve는 현재 지원서 base_revision을 요구하고 원래 확정 참조가 최신인지, 공고가 동일 공개 버전이고 이용 가능한지 다시 검사한다. Lua는 세션/소유 체험 수명과 현재 저장된 원문 CAS, 프로필 확인 시점의 체험 revision/확정 버전을 검사한 뒤에만 서버 승인 시각과 새 지원서 revision을 저장한다. 두 편집 중 하나만 반영되고 오래된 편집/승인은409다. 사용자 본문은 자동으로 다시 쓰지 않는다. 생성 멱등 재생 응답은 원래 revision1 생성 결과이며 편집된 최신 본문을 덮어쓰지 않는다.

실제 PostgreSQL/SQLite HTTP 편집·승인·승인 해제/CSRF/소유권, 두 편집 동시 CAS, 최종 Lua 직전 편집/재확정/삭제/만료/세션 폐기, 이전 확정 참조·공고 종료/비공개/공개 버전 교체, 타 체험 draft ID 거절13건을 추가했다. 실제 Redis/PostgreSQL 전체930건/0skip/22.20초 통과. 기존 경고1건. API 설명/타입 동기화·프론트 빌드·기존 HTTP 계약15건도 통과했다. 제품 프론트 동작 변경은 없다.

승인은 영구 저장을 수행하지 않는다. 저장/저장 대기/복사 연결 시 승인된 정확한 리비전과 변경 근거를 다시 확인하는 #76 등의 후속 구현이 필요하다. 읽기용 재검토 사유 표시는 #69에서 연결한다. 따라서 편집/승인 API 검증을 회원 저장 전체 여정의 성공으로 간주하지 않는다.


## 현재 근거의 재검토 표시 (#69)

GET /journeys/{id}/drafts/{draft_id}를 계약/라우터에 추가했다. 자기 유효 체험의 특정 지원서를 읽으며 목록·이전 세션 복원·체험 수명 연장을 제공하지 않는다. 원래 profile_version/opportunity/본문/approved_at/revision은 그대로 두고 현재 profile_changed/opportunity_changed/opportunity_closed를 응답에 투영한다. 프로필은 재확정한 경우에만 변경 사유가 생기며 편집 중에는 원래 확정본 기준 안내를 준다.

공고는 공개 버전 교체·중요 변경 검토 중이면 변경, 마감·비공개면 종료 사유를 준다. 공개 버전이 아직 같은 제목만 바뀐 미검수본은 중요 변경으로 판정하지 않는다. 확인 시각 지연·모집 미확인은 변경을 단정하지 않고 최신 상태 확인 안내를 준다. 새 생성/승인은 기존의 이용 가능 검사로 제한한다. 변경 사유가 있는 이전 승인 시각도 임의 삭제하지 않으며 그 시각만으로 복사/저장을 허용해서는 안 된다. 새 근거로 생성·확인·승인해야 한다.

조회는 저장 본문과 프로필 근거를 마지막에 재검사해 조회 중 편집/삭제/재확정을 감지한다. PATCH 응답에도 현재 재검토 사유를 표시하되 저장 본문/원래 참조를 자동 재생성하지 않는다. 이 표시를 계산하는 SQL 조회가 실패하면 편집 저장 전에 오류를 반환해 기존 승인 본문을 보존한다. 표시용 경고와 사유는 저장 원본을 고치지 않는다. SQL/Redis 분산 트랜잭션의 한계는 계속 적용된다.
