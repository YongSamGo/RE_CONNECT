# 역할 사전 초안 (W08-04)

> 기준일: 2026-10-22 · 담당: B(AI·데이터) · 관련 이슈: #61 · 형식: #172의 `CatalogRole` · 데이터: [role-catalog.json](role-catalog.json)

역할 후보(`GET /journeys/{id}/roles`)와 공고 `role_tags`가 함께 쓰는 사전의 초안이다. #172의 초기 마이그레이션에는 역할이 2개뿐이라 W01-07 평가 페르소나 8명 모두 후보가 0개였다. 이 초안은 그 2개를 그대로 두고 11개를 더해 13개로 만들었다. 11개는 마이그레이션 `0009_role_catalog_draft`로 DB에 들어간다. 이 파일을 고치면 마이그레이션을 새로 추가해야 하고, 그러지 않으면 백엔드 시험이 실패한다.

`0003`·`0009`는 같은 ID가 이미 있으면 건너뛴다. 그래서 새 마이그레이션도 같은 방식으로 쓰면, 빈 DB에서는 시험이 통과하지만 이미 `0009`를 적용한 스테이징·운영 DB의 역할은 바뀌지 않는다. 사전을 고칠 때는 다음을 따른다.

- **새 ID 추가**: 지금처럼 INSERT하고, 같은 ID가 있으면 건너뛴다.
- **기존 ID 수정**: 행이 이전 시드 값과 같을 때만 UPDATE한다. 운영자가 고친 행은 그대로 둔다.
- **시험**: `test_seeded_catalog_matches_reviewed_draft`는 빈 DB에서만 돌아 이 차이를 잡지 못한다. 기존 ID를 고치는 마이그레이션에는 직전 리비전까지 올린 DB에 적용하는 시험을 함께 넣는다.

## 1. 원칙

- **경험 태그에 근거가 있는 역할만 넣는다.** 역할마다 `skill_tags`는 페르소나 기대 프로필의 실제 경험 태그나 실제 공고 분류(1365 `srvcClCode`, 노인 구인정보 직종)에서 가져왔다. 희망만 있고 경험이 없는 역할(예: P03의 "말벗 봉사", P02의 "아파트 경비원")은 근거 태그가 없어 넣지 않았다.
- **별칭은 같은 뜻의 다른 표현만** 적는다(`공부 지도`→`학습 지도`, `간병`→`환자 돌봄`). 별칭으로 경험의 범위를 넓히지 않는다.
- `experience_rules`는 비워 두었다. 그러면 사전 태그 하나만 맞아도 그 경험이 근거가 된다. 두 태그가 함께 있어야 하는 역할이 생기면 `all` 규칙을 더한다.
- 역할 이름·설명은 사용자에게 그대로 보이므로 쉬운 말로 쓰고, 자격·보수·합격을 약속하는 표현을 넣지 않는다.

판단이 필요했던 것:

- `digital_guide`에 `소프트웨어 개발`을 근거 태그로 넣었다. 개발 경력이 곧 기기 안내 경험은 아니지만, 후보는 사용자가 고르는 제안이고 근거 경험이 화면에 함께 보이므로 받아들였다. 검수에서 빼면 P05는 후보가 0개가 된다.
- `visitor_guide`는 P02(민원 처리)와 P08(고객 응대) 모두에게 나온다. 두 사람의 희망 역할에는 없지만 실제 경험에 근거가 있어 기대값에 넣었다.

## 3. 검증

```bash
python eval/check_role_catalog.py
```

- 형식: #172 `CatalogRole` 검증을 옮겼다(id 형식, 계약 `text()`와 같은 길이·숨은 문자·공백뿐인 값 거절, 정규화 후 태그 중복, 별칭 양쪽 값·대상·중복, 규칙 태그 1~20개·중복·사전 태그 여부). 서비스 코드를 가져오지 않고 표준 라이브러리로 다시 쓴 것이라, #172가 이 JSON을 시드로 읽을 때 `CatalogRole`로 한 번 더 검증하는 시험을 두는 것이 안전하다.
- 후보: #172 `match_roles`를 옮겨 페르소나 8명의 후보를 계산하고 `eval/personas/P*.json`의 `expected_role_ids`와 대조한다. 지금은 8명 모두 기대와 같다.

## 4. 남은 일

- #172의 마이그레이션이 이 JSON을 읽어 넣도록 바꾼다(데이터 원본은 이 파일 하나).
- 운영자가 공고 `role_tags`를 고를 때 쓸 분류 대응표: 1365 `srvcClCode`(샘플에서 확인한 값은 `교육`·`환경ㆍ생태계보호`·`문화ㆍ체육ㆍ예술ㆍ관광`·`기타`뿐이다. `교육`→`learning_mentor`·`reading_mentor`처럼 대응시키고, 돌봄 분야 이름은 실제 응답에서 확인한다)와 노인 구인정보 직종. 실제 공고 검수(#51)에서 만든다.
- 실제 사용자 경험 태그는 #166 추출이 원문 표현 그대로 만들어서 페르소나 기대 태그보다 형태가 다양하다. #65(실제 공고 추천 평가)에서 별칭을 늘린다.
