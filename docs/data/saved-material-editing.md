# 저장 자료 조회와 재편집 (#77)

저장 자료 화면에서 자기 저장 프로필을 새 체험 확정본1번으로 가져와 편집한다. 기존 대화·준비 체크는 복원하지 않는다. 변경 내용을 임시 초안에 반영하고 재확정한 뒤 별도 회원 저장 버튼을 눌러야 SQL의 새 저장 버전을 만든다. 시작할 때 조회한 저장 버전을 base로 사용해 다른 편집의 변경을 덮어쓰지 않는다.

자기 저장 지원서의 정확한 문서·버전을 새 임시 지원서로 복호화한다. 현재 회원·현재 AI 동의·소유권을 User 행 잠금에서 검사하고 Redis 생성·최종 세션 확인까지 유지한다. 새 초안은 새로운 ID, revision1, 미승인 상태다. 기존 지원서의 승인 시각은 가져오지 않는다. AI 추론을 호출하지 않는다.

가져오기는 같은 공고의 현재 공개 버전과 현재 체험 확정 프로필을 사용한다. 이전 근거와 다르면 경고하고 사용자가 사실·조건에 맞게 직접 수정한다. 기존 본문은 자동으로 바꾸지 않는다. 공고가 비공개·마감·재검수 중이면 새 가져오기와 승인을 제한한다. 이후 근거 변경도 기존 조회·승인·저장 검사를 거친다.

입력 중 네트워크 자동 저장은 없다. 임시 초안 반영(PATCH), 재승인(POST approve), 회원 저장(POST drafts)을 구분한다. 기존 문서와 base_document_version을 지정한 명시 저장만 SQL 새 버전을 만든다. 원래 버전은 보존하며 다른 편집과 충돌하면 재조회가 필요하다.

저장 실패 시 화면의 편집 본문과 승인한 임시 자료는 유지한다. 지원서·프로필 모두 복사와 명시 재시도를 제공한다. 같은 승인 자료의 재시도는 같은 멱등 키를 사용한다. 화면 종료·새로고침·세션 종료를 넘어 편집 복원을 약속하지 않으며 본문을 localStorage/URL/로그에 저장하지 않는다. 페이지 종료와 bfcache 복원에서는 메모리를 지운다.

운영 동의 안내문·운영 키·실제 카카오 왕복·EC2는 별도 검증이다. 화면은 새로운 동의를 임의로 부여하지 않는다. 운영 정보 미정이면 실제 동의는 비활성 상태를 유지한다. 삭제·철회·탈퇴(#78)와 통합 경합 점검(#79)은 후속 작업이며 동일 User 잠금과 세션 무효화 경계를 사용해야 한다.
