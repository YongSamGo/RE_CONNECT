# 전면 개편 1차 구현 기록

2026-10-28. 기준: [개편 계획](../Plan/07_Frontend_Redesign_Plan.md). 전체 개편 완료가 아니라 대화와 내 경험 확인 과업의 첫 구현이다.

## 변경 범위와 보존

- 기존 미커밋 변경 위에 필요한 부분만 수정했다. 브랜치 전환·커밋·push·기존 변경 되돌리기는 하지 않았다.
- UX01 `/`, UX02 `/start` (`/consent` 호환), UX07 `/opportunities/:id`를 보존한다. 개발 목록의 순번은 UX ID와 다르다. 현재 개발 목록에서 대화는 3번, 내 경험 확인은 4번, 공고 상세는 7번이다.
- 첫 구현을 마친 시점에는 Home.tsx, home.css, StartJourney.tsx, PublicOpportunityDetail.tsx, catalog.css, index.css, App.css의 SHA-256이 작업 전후 일치했다. 이후 큰 패널 통일 요청에 따라 전역 패널 스타일 파일을 의도적으로 수정했다.
- 공통 ServicePage에는 선택적 className과 설명 생략만 추가했다. 기존 화면의 설명은 그대로 렌더링한다. 새 스타일은 `.conversation-task`, `.profile-task` 아래로 제한한다.
- 사용자의 추가 요청에 따라 대화 영역의 ‘잇’ 및 ‘다시잇다 AI’ 표시는 제거했다.

## 과업과 주소 대응

| 과업 | 현재 구현과 호환 주소 | 이번 범위 |
|---|---|---|
| 대화·음성 확인 | `/journeys/:journeyId/conversation`, `/voice`·`/transcription`은 기존 대화 진입 유지 | 질문과 글/음성 입력을 한 화면에 배치. 전사 확인·기존 글 교체 확인 유지 |
| 내 경험 확인 | `/journeys/:journeyId/results`, `/journeys/:journeyId/profile` | 두 주소 모두 JourneyProfile 렌더링. 요약→같은 화면 편집→초안 반영→명시적 확정 |
| 자료 없는 경험 확인 | `/results` → `/profile/review` | 중복 빈 화면 통합. 이용 안내에서도 하나의 항목으로 표시 |
| 추천·공개 목록 | 기존 추천/공개 공고 주소 | 공통 목록 통합은 후속 작업 |
| 공고 상세·자격 대조 | 기존 상세·추천의 대조 패널 | 검수된 상세 보존. 추가 통합은 후속 작업 |
| 신청 준비·지원서 | 기존 공고별 준비 경로 | 후속 작업 |
| 저장·내 자료 | 기존 동의·인증 복귀·저장 경로 | 후속 작업. 저장 성공이나 동의 경계 변경 없음 |

URL 개수와 독립 과업 화면 수를 혼동하지 않는다. 개발용 목록은 현재 19개 진입점이며 전체 사용자 화면 수는 후속 통합 뒤 확정한다.

## 화면 구성

기존 S-Core Dream, 본문 18px, 주요 버튼 최소 56px를 유지한다. 색은 기존 본문 #182b38, 보조 본문 #405665, 바탕 #f4f7f9, 청색 #245a78, 구분선 #cfdce2를 사용한다. 새로운 장식이나 테마를 추가하지 않는다.

```text
대화:          제목
               질문 라운드 상자 | 내 답변·완료하기
               말하기·글로 답하기

내 경험 확인:  제목
               경험·희망 활동  | 수정·확정·저장 구분 안내
               추가 정보·자료 관리
```

넓은 화면은 왼쪽 정렬과 구분선으로 과업을 나누고, 900px 이하에서는 읽는 순서대로 세로 배치한다. 글자 축소·내용 잘라내기·카드 내부 스크롤로 화면을 맞추지 않는다. 긴 편집 양식은 페이지 스크롤을 사용한다. 확정본이 최신일 때 주 행동은 추천 공고 확인이다.

## 유지한 처리 경계

- 말하기가 기본 입력이며, 녹음을 마치면 STT를 요청해 답변 칸에 자동으로 넣는다. 글 입력도 선택할 수 있고, 답변 전송은 확인 팝업에서 사용자가 승인한 뒤 진행한다.
- 대화 멱등 요청·불명확한 응답 재확인·세션 만료·이탈 후 응답 폐기 로직은 변경하지 않았다.
- 초안 반영과 프로필 확정은 별도 API이다. 미반영 수정이 있으면 확정할 수 없다. 역할 제외·확정 버전·회원 저장 조건은 기존 로직을 유지한다.
- 종료·삭제·입력 폐기의 기존 확인 절차를 유지한다.

## 이번 확인 결과

- `npm run typecheck` 통과. 변경한 TS/TSX 파일 대상 oxlint 통과. 관련 추적 파일 `git diff --check` 통과.
- 사용자 지시에 따라 단위 테스트, 전체 테스트, E2E, 빌드는 실행하지 않았다.
- 내장 브라우저에서 실제 `innerWidth/innerHeight`를 읽어 1280×650 CSS px로 보정했다. 대화의 질문·입력·보내기, 음성 입력의 녹음 시작, 내 경험 확인의 경험·희망 지역/유형·확정 행동이 첫 화면에 보인다. 기본 대화 보내기 버튼 아래 좌표는 약 524 CSS px였다.
- 프로필 요약은 1440×800, 1920×1080 CSS px에서도 확인했다. 두 화면 모두 320×800 CSS px에서 세로 배치되고 문서 가로 넘침이 없음을 확인했다.
- 대화: 빈 입력의 보내기 비활성, 글 입력, 음성 전환 후 글 유지, 글 입력 복귀 초점, 예시 답변 전송과 다음 질문, 큰 글씨 보기, Tab 이동 확인.
- 프로필: 빈 진입, 요약, 편집, 미반영 수정 시 확정 비활성, 초안 반영 후 요약 복귀 및 초점 복귀, 확정 실패 시 오류 표시와 초안 유지 확인.
- `/dev/conversation`은 기존 예시 전송을 사용한다. 추가한 `/dev/profile`은 개발 빌드의 명시적 경로에서만 사용하며 예시 조회·메모리 내 초안 반영을 제공한다. 확정·회원 저장·삭제는 성공으로 모사하지 않고 연결 오류를 반환한다. 실제 경로의 실패 응답을 예시 성공으로 대체하지 않는다.

## 남은 확인과 다음 범위

- 실제 서버의 대화·프로필 확정·역할·저장 왕복, 실제 녹음·전사·음성 재생, 인증 복귀는 미검증이다.
- 스크린리더·실제 모바일 기기·브라우저 200% 확대·다수 경험/최대 길이·모든 오류 및 확정 상태의 브라우저 조합은 미검증이다. 서비스의 ‘큰 글씨 보기’는 브라우저 200% 확대 검증과 다르다.
- 보존 화면은 소스 및 전역 스타일 해시를 비교했다. 개편 전후 픽셀 비교나 실제 공고 데이터의 시각 회귀 검증은 수행하지 않았다.
- 기존 테스트의 새 화면 구조·문구에 대한 기대값 검토와 실행이 남아 있다. 타입·린트 통과를 기능 전체 완성으로 보지 않는다.
- 다음 구현은 추천/공개 목록의 공통 구조, 신청 준비의 대표 화면, 내 자료와 저장 단계 통합이다. UX01·UX02·UX07의 검수된 정보 구조·표현은 계속 보존한다.

## 공통 큰 패널 규칙

- 홈 영상 패널, 동의·계정 패널, `ServicePage` 화면, 공개 공고 탐색/검색 결과 패널이 같은 최대 너비 1120px과 24px 모서리 반경을 사용한다.
- 데스크톱 기본 크기는 사용 가능한 화면 높이에 맞춘 16:9 영역으로 통일한다. 내용이 기준 높이보다 길면 패널이 자연스럽게 늘어난다. 모바일은 가로 폭 여백 16px, 모서리 18px로 줄이고 내용을 세로로 배치한다.
- 색상·타이포그래피·안내 내용은 유지했다. 정보 구조를 확인할 수 있도록 홈페이지의 홈 패널과 승인된 동의/공고 상세 흐름은 기존 구성 그대로 둔다.
- 1280×650 CSS px 개발 대화 화면에서 패널 너비 916px, 모서리 반경 24px을 확인했다. 세로 콘텐츠는 패널을 자연스럽게 확장한다. 타입 검사와 변경 파일의 공백 검사를 통과했다.
- 후속 대화 화면은 1280×650 CSS px에서 질문 카드·입력 방식·답변·완료 버튼이 화면 안에 표시되는 것을 확인했다. 완료 버튼은 질문과 답변을 함께 보여 주는 확인 팝업을 연다. 녹음 결과 재생기를 제거하고 전사 완료 뒤 `다시 말하기`·`다음 질문`으로 이어지도록 했다. 실제 마이크·STT 서버 왕복은 실행하지 않았다.
- 서비스 화면 공통 하단 안내 링크와 대화 화면의 하단 보조 링크·관리 영역은 제거했다.
