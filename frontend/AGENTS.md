# 프론트 작업 지침

루트 AGENTS.md의 보안과 협업 규칙을 함께 따른다. AGENTS.override.md는 만들지 않는다.

## 먼저 읽을 기준

1. [스타일 보존 기준](DESIGN_BASELINE.md): 무엇을 유지하고 무엇을 고칠지 판단한다.
2. [완성 계획](../Plan/08_Frontend_Completion_Plan.md): 기능 범위와 완료 조건을 확인한다.
3. [실행 준비서](../Plan/09_Frontend_Execution_Runbook.md): 작업 파일과 의존성, 검사 범위를 확인한다.

## 반드시 지킬 것

- 직접 작성하는 제목과 버튼, 메뉴, 안내에 가운데 점을 사용하지 않는다.
- 한 화면의 핵심 작업과 주요 행동을 먼저 보인다. 제목을 반복하는 설명, 내부 처리 정보, 예시 프로필 설명을 덧붙이지 않는다.
- S-Core Dream, 기존 청색, 흰 패널, 공통 크기와 버튼을 재사용한다. 새 테마나 별도 UI 체계를 만들지 않는다.
- 한 화면에 넣으려고 글자나 조작 영역을 줄이거나 내용을 자르지 않는다. 긴 내용과 확대 상태는 자연스럽게 페이지가 늘어나게 한다.
- 공통 컴포넌트를 먼저 고친다. 같은 선택자를 파일 아래에 반복 추가해 앞의 규칙을 덮는 방식으로 수정하지 않는다.
- 현재 캡처는 출발 상태 기록이다. 가림과 넘침, 예시 자료, 미연결 기능을 승인된 디자인으로 고정하지 않는다.
- 실제 서버 실패를 예시 성공으로 대신하지 않는다. 개발 예시와 실제 기능의 완료 여부를 구분한다.
- 화면 변경 뒤 실제 브라우저에서 배치와 이동을 확인하고 잘못된 부분을 스스로 수정한다. 확인 환경과 남은 제한을 기록한다.
- 관련된 검사만 실행한다. 전체 테스트와 E2E는 명시적 요청 또는 릴리스 검증 단계에서만 실행한다.

## 완료 보고

바꾼 사용자 행동, 실제 연결 여부, 실행한 검사, 브라우저 확인 범위, 남은 조건만 간단히 보고한다. 자료나 환경이 없어 확인하지 못한 성공 상태를 통과로 표시하지 않는다.
