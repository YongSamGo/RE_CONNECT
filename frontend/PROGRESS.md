## 동작과 경계

- 프로필·지원 문장의 `reviewed`는 미리보기 확인 표시다. 서버 확정·저장 동의·지원서 승인과 구분한다. 역할·추천·지원 가능 여부를 임의 생성하지 않는다.
- 경험·희망 조건·지원 문장은 App의 `useMemoryScope`가 소유한다. 화면 왕복에는 유지하고 종료·재시작·새로고침·페이지 이탈·bfcache 복귀에는 비운다. 서버가 확인한 로그아웃 뒤에도 미리보기를 지운다. 영구 저장소에 본문을 쓰지 않는다.
- 녹음은 기기 안에서만 만들고 업로드하지 않는다. 취소·상한 초과·오류·페이지 이탈·언마운트와 취소 뒤 늦은 권한 응답에서 recorder·track·timer·blob·object URL·재생 요소를 정리한다. 브라우저 타이머의 실제 기기/백그라운드 검증과 향후 서버 길이/형식 검증은 남아 있다.
- 복사는 버튼으로 시작하고 실제 성공 뒤에만 완료를 표시한다. 종료가 이미 복사한 시스템 클립보드까지 지운다고 안내하지 않는다. 복사·녹음·재생 내부 오류를 노출하지 않는다.
- 새 `useRequest`는 중복 요청을 차단하고 초기화·종료·언마운트 뒤 성공/오류를 폐기한다. 기존 클라이언트의 same-origin·CSRF·no-store·리다이렉트 거절·제한시간을 사용한다. 자동 재시도하지 않는다.
- 세션의 인증 여부·사용자 존재·UUID·역할 enum·MFA boolean·동의·저장 대기 참조를 런타임 검사한다. 회원 자료는 자기 자료 전용 API로만 요청한다. UI의 역할 확인은 서버 인가·소유권 검증을 대신하지 않는다.
- MFA는 서버 성공 후 `/me`를 재조회한다. 공고 검수는 목록과 일치하는 버전의 상세·공식 원문·변경 내용·메모·검토 선택을 거친다. 버전 충돌은 실패로 표시한다.
- 신고는 공고 참조·유형·설명만 전송한다. 같은 본문의 네트워크 오류 후 재전송에는 같은 멱등 키를 사용한다. 접수 완료는 정상 서버 응답 뒤에만 표시한다.
- 읽어주기는 서버의 AI 처리 동의를 확인한 뒤 표시된 공고 버전의 `SpeechTarget`만 전송한다. 임의 텍스트를 보내지 않는다. 현재 UI는 공고의 계약 허용 필드 중 값이 있는 항목을 선택하고 서버가 알려준 부분 수 안에서 다음 부분을 직접 요청한다. 중지/이탈 시 소리와 URL을 정리하고 실패해도 원문을 유지한다.
- 회원/운영 자료·신고·읽어주기는 실제 API 요청 코드다. 서버가 없으면 오류를 표시한다. 표시 필드와 중요한 참조는 검사하지만 전체 OpenAPI 런타임 검증기를 구현한 것은 아니다.

## 후속 순서와 선행 조건

1. 운영 동의문의 주체·문의처·리전·보관/삭제·버전과 백엔드 실행 기반을 확정한다. 현재 사용자는 둘 다 미확정이라고 답했다. 개발용 임의 동의문으로 실제 처리 동의를 대신하지 않는다.
2. 실제 동의·체험 생성 → 메시지/리비전/멱등 재전송 → 초안 편집·확정/재확정·역할 → 추천·자격 결과를 연결한다.
3. 녹음 업로드·STT와 수정 전사의 메시지 전달, 대화/지원서 TTS 대상·녹음 상호 중지를 연결한다.
4. 공고 준비 체크·AI/수동 서버 초안·승인·재검토 표시, 로그인·저장 대기·별도 저장 동의·기존본 교체·탈퇴를 연결한다.
5. 추가한 구조화 조건 편집과 실제 API, 소유권, 모바일 녹음, 200% 확대·스크린리더, 서버 삭제/만료를 검증한다. 반려/종료/감사는 [운영 검수 기록](src/features/admin/README.md), 등록/기본 정보 편집은 [등록·편집 기록](src/features/admin/EDITOR.md), 신고 종결은 [신고 처리 기록](src/features/admin/REPORTS.md)에 정리했다.

테스트 응답/음성 장치 모형은 테스트 파일에서만 사용한다. 실제 서버·카카오·STT/TTS·모바일 실행 성공은 주장하지 않는다. 인앱 Chromium에서 안내 → 경험 → 프로필 선택/확인 → 지원 문장 작성/확인을 수동 확인했다. 최종 자동 검증 결과는 아래에 기록한다.
