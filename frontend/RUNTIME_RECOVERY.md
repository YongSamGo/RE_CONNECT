# 실행 중 장애 대응 개선 — 2026-10-30

기준: 최신 `origin/develop`의 `55cf6b3c`. 기존 프론트 PR은 병합되어 새 작업 브랜치를 사용한다.

## 현재 대응

API의 고정 오류 문구, CSRF·동일 출처 제한, 중복 제출 방지, 메모리 수명별 요청 취소와 늦은 결과 폐기, 결과가 불명확한 변경 요청의 같은 키·본문 재확인이 구현되어 있다. 녹음 권한 거부·연결 해제·크기 제한과 클립보드 실패 안내도 제공한다.

## 구현 계획

1. 통신이 취소를 무시하거나 JSON·오디오·오류 본문 다운로드가 멈춰도 제한시간 또는 사용자 취소에서 대기를 종료한다. 자동 재전송은 추가하지 않는다.
2. 실제 데이터 라우터와 최상위 오류 경계에 공통 복구 화면을 연결한다. 내부 오류를 출력하지 않고 현재 화면 다시 열기와 시작 화면 이동을 제공한다. 입력 유실·서버 처리 가능성을 안내한다.
3. 질문 음성의 재생 중 오류와 브라우저 음성 합성 실패를 안내한다. 새 재생 요청 전에 기존 소리를 정리하고 늦은 이벤트가 현재 오류를 덮어쓰지 않게 한다.
4. 검증된 서버 재시도 대기 시간을 공통 오류 안내에 표시한다. 자동 재시도나 화면 입력 초기화는 하지 않는다.

## 검증 계획

변경한 API·오류 화면·질문 음성 테스트를 우선 실행한다. 대화·체험 시작·지원서의 멱등 재확인, 계정 실패, 기존 음성·클립보드 실패 테스트로 영향을 확인한다. 타입 검사·린트·빌드를 수행한다. 전체 테스트와 E2E는 실행하지 않는다.

실제 백엔드/프록시 장애 주입, 카카오 왕복, Android Chrome·iPhone Safari의 권한·오디오·bfcache 검증은 별도 통합 검증이 필요하다. 모의 응답 테스트 통과를 실제 서비스 완료로 취급하지 않는다.

## 지속 점검과 CI 후속 수정

- 첫 CI에서 API 계약 테스트 4개가 원본 `Response.url` 유실로 실패했다. 본문을 새 Response로 재구성하던 코드를 복제본의 본문을 먼저 읽고 원본 응답을 전달하는 방식으로 수정했다. JSON·음성의 원본 메타데이터를 유지하며 독립된 취소/제한시간 경계는 유지한다. 원본 응답의 동일성·URL·헤더·JSON 결과 회귀 검사를 추가했다.
- 기존 `npm run lint`에 React 효과 의존성 검사와 Promise `.then()` 체인의 실패 처리 검사를 추가했다. 새 의존성이나 별도 CI 워크플로는 추가하지 않았다. 의존성이 누락된 효과와 catch 없는 체인의 의도적 잘못된 예제로 두 규칙의 탐지를 확인했다. 정상 프론트 소스·설정 182개 파일은 지정된 Oxlint 1.89.0 검사에서 경고/오류 0개였다. 검사 출력과 의도적 잘못된 예제는 커밋하지 않는 `security-reports/`에만 보관한다.
- 로컬 `node_modules` 잠금을 건드리지 않고 `npm exec --yes --ignore-scripts --package=oxlint@1.89.0 -- oxlint ...`로 지정 버전 검사를 수행했다. 전체 의존성 재설치는 반복하지 않았다. 수정한 테스트·계약·빌드의 최종 검증은 실제 PR HEAD의 원격 CI에서 확인한다.
- Codex 개인 환경에 OpenAI 공식 `security-best-practices`와 `gh-fix-ci` 스킬을 설치했다. 설치 경로는 저장소 밖이며 팀원에게 설치를 요구하지 않는다. 프로젝트에는 기존 lint·TypeScript·CodeQL·의존성 취약점/서명 검사·브라우저 회귀·주간 재검사가 이미 있다.
- 사용자는 예약 실행이 아니라 현재 작업에서 점검·수정을 이어가도록 요청했다. 잘못 생성한 매일 점검 예약은 삭제했다. 도구로 검사하고 실제 영향과 실패 원인을 확인한 뒤 수정·관련 검증을 반복한다. 관련 변경은 작업 PR 하나에 묶는다.

## 최종 로컬 검증

검증용 설치본과 원래 작업 폴더에 남은 잠긴 네이티브 파일의 SHA-256이 같음을 확인했다. 같은 파일은 덮어쓰지 않고 검증용 설치본의 누락·다른 의존성 파일만 복사해 원래 폴더의 `node_modules`도 복구했다. 삭제·프로세스 강제 종료·설치 스크립트 실행은 하지 않았고 `npm ls --depth=0`에서 모든 선언 버전이 일치했다.

- 원래 작업 폴더에서 변경 관련 **30개 테스트 파일, 314개 테스트 통과**. 요청/메모리 수명, API, 라우트, 접근성, 음성/대화, 신청 준비, 계정/저장, 프로필/추천, 공개 공고, 운영자 수정·검수·신고를 포함한다.
- API 생성 타입 일치·TypeScript·운영 빌드·기존 강화 lint·`git diff --check` 통과.
- `npm audit --audit-level=moderate`: 취약점 0개. 패키지 서명 150개와 출처 증명 58개 검증 성공.
- 추가 접근성 정적 규칙의 후보는 별도 검토했다. `role=status` 등의 네이티브 요소 권장, 포커스 가능한 읽기 영역, 동적 summary 문구 등은 실제 DOM과 기존 접근성 회귀 결과를 대조하고 기계적으로 일괄 변경하지 않았다. 실제 미디어 자막·기기 접근성의 완료를 주장하지 않는다.
