# 다시잇다 프론트엔드

React·TypeScript·Vite 기반의 첫 화면 구현입니다. 개발 기준은 `Plan/01_UX_Flow.md`, `Plan/03_Architecture_and_Dependencies.md`, `Plan/05_Engineering_Constraints.md`입니다. 과거 README의 외부 AI API 계획보다 `Plan` v1.1의 EC2 자체 추론 명세를 우선합니다.

## 실행

Node.js 24 이상에서 이 디렉터리로 이동해 실행합니다.

```powershell
npm ci --ignore-scripts
npm run dev
```

기본 주소: http://127.0.0.1:5173. 개발 서버는 루프백에서만 수신합니다.

```powershell
npm run lint
npm test
npm run build
npm run preview
```

`build`는 TypeScript 검사 후 `dist/`를 생성합니다. 운영 정적 서버에서는 파일이 없는 화면 경로를 `index.html`로 연결해야 합니다. `/api/*`는 SPA fallback 대상에서 제외합니다. Vite 개발 서버를 운영에 공개하지 않습니다.

## 구현 범위

- 시작 화면, 큰 글씨 전환, 반응형 레이아웃, 본문 바로가기
- 화면 체험 안내 확인 후 한 질문씩 경험·지역·활동 유형 직접 입력
- 프로필 수정·확정, 수정 중 이전 확정본 유지
- 미확정 추천 접근 차단, 종료 확인과 메모리 초기화
- 오류 경계, 404, UX01~UX10에 대응하는 라우트 골격
- 사용자가 선택해 진입하는 가상 예시 공고 3개, 검색·지역·활동 유형 필터와 빈 결과 안내
- 예시 공고 상세, 확인할 조건 안내, 공고별 메모리 전용 준비 체크리스트와 종료 시 초기화
- 확정 프로필을 참고한 자기소개·지원동기 직접 작성, 문장 확인·복사 및 복사 실패 시 수동 선택
- 문장 수정 시 확인 해제, 프로필 재확정 시 기존 지원서 재검토 안내, 공고별 지원서 격리·메모리 유지
- 내 정보에서 현재 확정 프로필·지원서 상태 조회, 이어서 작성, 확인 후 지원서 개별 삭제

| 화면 | 경로 | 상태 |
| --- | --- | --- |
| UX01 시작 | `/` | 구현 |
| UX02 안내 | `/consent` | 화면 체험 안내만 구현, 실제 AI 처리 동의 아님 |
| UX03 대화 | `/conversation` | 직접 입력 3단계, AI·음성 미연동 |
| UX04 전사 확인 | `/transcript` | 준비 상태 |
| UX05 프로필·역할 | `/profile` | 직접 작성 프로필 수정·확정, 역할 API 미연동 |
| UX06 목록 | `/opportunities`, `/recommendations` | 공개 목록에서 예시 체험 선택 가능, 추천 API 미연동 |
| UX07 상세 | `/opportunities/:id` | 예시 상세·확인 항목, 실제 원문·자격·신고 미연동 |
| UX08 신청 준비 | `/preparation/:id` | 예시 체크리스트·직접 작성·확인·복사, AI 생성·공식 접수 미연동 |
| UX09 내 정보 | `/my` | 현재 체험 프로필·지원서 요약/이어서 보기/개별 삭제, 회원 저장·로그인 미연동 |
| UX10 운영자 | `/admin` | 준비 상태, 운영 기능 없음 |

입력은 React 메모리에만 두며 localStorage·sessionStorage·IndexedDB·쿠키에 기록하지 않습니다. API 호출, 음성 녹음, 로그인, 영구 저장, 실제 추천·자격 판단은 수행하지 않습니다. 다시 접속하거나 새로고침하면 새 체험입니다. 서버 세션 삭제·만료를 구현한 것으로 해석하면 안 됩니다.

공고 탐색에서 ‘예시 공고로 화면 체험하기’를 선택하면 가상 기관·활동을 살펴볼 수 있습니다. 모든 예시에 실제 모집 공고가 아니라는 안내를 표시합니다. 예시에는 접수 URL·실제 마감일·자격 충족 결과가 없으며, 준비 체크를 모두 선택해도 신청 완료를 표시하지 않습니다. 체험 종료는 프로필 없이 공고만 살펴볼 때도 제공하며 체크와 예시 선택 상태를 초기화합니다. 실제 공고 API의 응답 타입이나 검수·자격 계약이 확정된 것으로 간주하지 않습니다.

지원서 편집은 경험 프로필을 확정한 뒤 예시의 신청 준비 화면에서 제공합니다. 자기소개·지원동기는 각각 2,000자 이내로 직접 작성합니다(현재 UI의 임시 한도이며 API 계약 확정값 아님). 두 항목을 채우고 사실 확인을 선택한 뒤 문장을 확인해야 복사할 수 있습니다. 복사에는 제목과 현재 편집한 문자열을 사용하며 줄바꿈·공백을 보존합니다. 브라우저 복사가 거부되거나 지원되지 않으면 읽기 전용 텍스트를 선택해 직접 복사할 수 있습니다.

프로필 재확정 때마다 체험 내부 버전을 증가시키고 기존 지원서의 본문은 유지한 채 재검토를 요구합니다. 서버 리비전·소유권 검증을 구현한 것은 아닙니다. 작성·확인 상태 모두 종료·새로고침 시 초기화되며, 사용자가 기기에 직접 복사한 클립보드 내용은 종료로 지워지지 않습니다. 확인은 사실성의 자동 검증이나 영구 저장·제출을 의미하지 않습니다.

‘내 정보’에서는 현재 확정본과 체험 중 작성한 지원서를 모아 보여줍니다. 지원서의 작성 중·문장 확인 완료·프로필 변경에 따른 재검토 상태를 구분하고 해당 공고의 편집 화면으로 연결합니다. 개별 삭제는 현재 체험 메모리의 해당 지원서만 지우며 프로필과 준비 체크는 유지합니다. 확인 창은 취소에 기본 포커스를 두고 Tab 이동·Escape 취소·닫은 뒤 포커스 복원을 지원합니다. 회원 저장 자료 영역은 별도로 미연동 상태를 안내합니다. 로그인이나 서버 저장·삭제를 시뮬레이션하지 않습니다.
