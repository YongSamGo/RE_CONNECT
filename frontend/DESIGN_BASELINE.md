# 스타일 보존 기준

2026-10-29. 화면 수정 시 해석을 반복하지 않기 위한 기준이다. 기능 순서는 [완성 계획](../Plan/08_Frontend_Completion_Plan.md)을 따른다.

## 1. 기준의 우선순위

1. 사용자의 최신 요청
2. 이 문서의 보존 항목과 완성 계획의 완료 조건
3. 현재 공통 토큰과 재사용 컴포넌트
4. 출발 상태 캡처와 소스 기록
5. 과거 UI 개선 문서와 개발 예시

캡처와 코드가 사용자 요구에 어긋나면 요구에 맞게 고친다. 보존할 스타일과 기존 결함을 구분한다. 사용자에게 화면마다 같은 취향을 다시 묻지 않는다. 새로운 정보 구조가 필요한 경우에도 이 기준 안에서 먼저 해결한다.

## 3. 정보와 문구 기준

사용자가 2026-10-29에 제시한 공고 조건 선택 화면을 새 사용자 화면의 시각 기준으로 삼는다. 참고 이미지는 로컬 검수 기록 `security-reports/frontend-review-2026-10-29/user-style-reference.png`에 보관한다. 큰 흰색 라운드 영역 안에서 제목과 지금 할 일을 먼저 보이고, 충분한 여백과 기존 파란색 버튼으로 행동을 구분한다. 내용이 길면 자연스럽게 늘리되, 빈 칸을 채우기 위한 설명이나 중첩 상자를 추가하지 않는다. 화면마다 지도를 넣거나 해당 화면의 고유 배치를 그대로 복제한다는 뜻은 아니다.

- 제목 하나와 현재 작업 하나, 주요 행동 하나를 중심으로 한다.
- 기본 상태의 보조 행동은 두 개 이내를 출발점으로 삼는다. 삭제와 탈퇴처럼 현재 작업과 다른 행동은 설정 안으로 옮긴다.
- 직접 작성한 화면 문구에 가운데 점을 쓰지 않는다. 접속어로 바꾸거나 단어 하나를 고른다.
- 카드마다 제목과 기관, 핵심 정보 2~3개만 우선한다. 긴 조건은 상세에서 읽는다.
- 제목을 설명으로 반복하지 않는다. 부가 정보는 이해나 판단, 동의, 오류 복구에 필요할 때만 쓴다.
- 빈 화면에는 무엇을 시작할지, 오류에는 무엇을 다시 할지 하나를 우선 제시한다.
- API 버전과 리비전, 내부 처리 방식은 일반 사용자 화면의 기본 정보가 아니다. 필요한 근거 확인에서만 제공한다.
- 공식 공고와 게시 안내문은 원문을 보존한다. 자체 화면 문구와 원문을 구분한다.

## 4. 재사용할 구조

| 화면 요소 | 먼저 사용할 코드 | 실행 때 정리할 부분 |

| 바깥 패널과 제목 | src/ui/ServicePage.tsx | 홈, 동의, 계정의 기존 틀도 같은 치수 규칙으로 맞춤 |

| 오류와 로딩 | src/ui/StatusNotice.tsx | 화면별 복구 행동 연결 |

동일 선택자에 뒤늦게 규칙을 계속 추가하지 않는다. 실제 적용 중인 선언을 확인하고 기존 규칙을 통합한다. 한 화면의 조정이 다른 페이지에 미치는 범위를 확인한다.

로컬 기록 위치: ../security-reports/frontend-baseline-2026-10-29/

이 폴더는 공개 저장소에 올리지 않는 도구 출력이다. 새 환경에서 폴더가 없으면 현 코드를 실행해 출발 상태를 다시 기록한다. 자료가 없다고 승인된 화면을 임의로 재디자인하지 않는다.

- source-manifest.json: 출발 코드의 파일 해시와 원본 위치
- source/: 수정 전 프론트 파일 사본

## 7. 비교 절차

1. 변경 전 화면과 소스 상태를 확인한다. 현재 사용자 변경을 덮어쓰지 않는다.
2. 같은 주소, 자료, 화면 크기, 글씨 설정으로 비교한다. 움직이는 영상은 같은 시점의 정지 프레임이나 정적 표지를 이용해 비교하되 제품 재생 기능과 구분한다.
3. 폰트 로딩과 화면 상태가 준비된 뒤 캡처한다. 개발 메뉴의 유무를 기록하고 제품 영역을 가리는 경우를 놓치지 않는다.
4. 전체 스크린샷뿐 아니라 제목과 버튼, 입력의 경계와 박스 치수를 확인한다.
5. 문구 기준과 실제 이동, 정상과 오류 상태를 함께 확인한다.
6. 잘못된 부분을 스스로 수정하고 직접 영향을 받은 화면만 다시 확인한다.
7. 기준 이미지를 덮어써 차이를 없애지 않는다. 요구에 맞게 의도적으로 바꾼 근거와 전후 이미지를 함께 남긴다.

자동 이미지 비교만으로 '심플함'과 가독성을 판정하지 않는다. 원본 영상의 움직임과 스크롤 상태, 글꼴 로딩 차이도 구분한다.
