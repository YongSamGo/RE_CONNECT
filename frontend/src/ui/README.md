# 공통 UI·메모리 경계 — W11-01.a / #80

역할 A의 #80을 검토 가능한 첫 단위로 구현했다. #118·#119 위에 쌓는 초안이며 선행 #13·#19가 아직 통과하지 않았으므로 #80 전체를 완료로 표시하지 않는다. 실제 API·음성·회원 저장 기능을 새로 연결하지 않는다.

## 공통 조작과 폼

- `Button`: 기본 type은 `button`이다. 제출 버튼만 `type="submit"`을 명시한다. `pending`은 native disabled·aria-busy와 처리 중 레이블을 적용해 중복 클릭을 막는다.
- `TextAreaField`·`CheckboxField`: 레이블, 힌트, 오류를 고유 ID로 연결한다. 오류는 색 외에 `오류:` 문구와 aria-invalid로 표시한다. 공통 본문은 18px, 주요 버튼·링크·체크박스 레이블 영역은 44px 이상이다.
- `FormErrorSummary`: 실패 시 요약에 포커스하고 키보드로 오류 항목 링크를 열면 해당 필드에 포커스를 준다. 부모 폼이 검증하고 필드와 일치하는 명시적 ID·고정 오류 문구를 넘긴다. 원본 입력을 오류에 복제하지 않는다.
- `StatusNotice`: 일반 안내는 live region 없이, 처리 중은 status, 실패는 alert로 표시한다. 취소·복귀 같은 조작은 live region 밖에 둔다. 렌더링만으로 네트워크 요청·자동 재시도를 시작하지 않는다.
- `RequestError`: 기존 API 클라이언트의 ApiError는 고정 안내를 사용하고 알 수 없는 예외는 일반 문구로 처리한다. 의도적 취소는 오류로 표시하지 않는다. 세션 만료·버전 충돌·일일 한도에 필요한 회복 행동은 호출 화면이 결정한다.

시작 안내의 선택·시작 버튼, 경험 입력, 종료 버튼과 미연동 안내가 공통 컴포넌트를 사용한다. 오류 요약·실제 로딩 UI는 서버 기능이 연결될 때 각 폼에 적용한다. 현재 안내 선택은 운영 동의가 아니며 입력은 가상 미리보기다.

## 메모리 수명과 비동기 작업

`useMemoryScope`는 컴포넌트 인스턴스마다 상태·세대 번호·AbortController 집합을 소유한다. 전역 singleton, localStorage, sessionStorage, IndexedDB, Service Worker나 별도 캐시를 만들지 않는다. 공개 지역 목록과 개인 자료를 같은 영구 캐시에 넣지 않는다. 현재 API 클라이언트의 개인 요청은 `cache=no-store` 정책을 유지한다.

```tsx
const scope = useMemoryScope(() => ({ text: '' }))
// 작업 함수는 요청만 수행한다. 상태 변경은 두 번째 callback에서 한다.
const outcome = await scope.run(
  (signal) => api.GET('/me', { signal }),
  ({ data }) => {
    // 현재 수명에 속한 응답인 경우에만 적용된다.
    // 실제 화면의 모델에 맞춰 처리한다. 원본 응답을 로그·영구 캐시에 넣지 않는다.
    if (data) setAuthenticated(data.authenticated)
  },
)
if (outcome.status === 'discarded') {
  // 이전 화면/체험의 완료·오류를 표시하지 않는다.
}
// 종료·새 체험·로그아웃·삭제 시 실제 서버 작업과 별도로 호출한다.
scope.clear()
```

`clear()`는 세대를 바꾸고 진행 중 요청의 signal을 취소한 다음 초기 상태로 바꾼다. 작업 함수가 취소를 무시하고 늦게 성공하거나 실패해도 이전 결과를 적용하지 않는다. 유효성 확인과 적용 callback을 같은 동기 실행 구간에서 수행하고 원본 결과를 반환하지 않으므로, 호출자가 추가 await 뒤 이전 응답을 적용하는 실수를 줄인다. callback 자체는 동기 상태 갱신으로 사용하고 비동기 작업을 다시 시작하지 않는다.

언마운트·전체 페이지 이탈(pagehide)·bfcache 복귀(persisted pageshow)에서도 수명을 폐기한다. 일반 pageshow에서는 진행 중 입력을 지우지 않는다. React StrictMode의 effect 정리·재등록을 지원한다. 취소 이벤트에서 즉시 작업을 재시작하려는 경우에도 폐기 처리 중에는 실행하지 않는다.

정상 수명 중 요청 실패는 호출자에게 전달하고 입력을 유지한다. 화면은 RequestError로 안전한 메시지를 표시한다. 종료 후의 실패는 폐기한다. `scope.run`에 전달한 작업 내부에서 직접 상태를 바꾸거나 외부 캐시에 기록하면 수명 검사를 우회하므로 그렇게 사용하지 않는다.

현재 체험 미리보기는 이 hook으로 상태를 보유하고 종료·새 체험에서 초기화한다. 실제 서버 삭제·로그아웃은 연결하지 않았으며 **요청 취소가 서버 처리 취소·삭제를 보장하지 않는다**. 서버 소유권·만료·늦은 결과 저장 차단은 별도 선행 구현이다. 메모리 참조 제거는 메모리의 물리적 완전 소거를 뜻하지 않는다.

## 검증과 남은 항목

단위/DOM 시험은 키보드로 오류 요약 → 입력 이동, 레이블·설명·오류 연결, 중복 제출 차단, 안전한 오류 출력, 인스턴스 격리, 종료·페이지 이탈·복귀·언마운트 시 취소, 늦은 성공/실패 폐기, 새 체험에 이전 결과가 덮어쓰지 못하는 경계를 확인한다. 기존 App의 입력/수정/종료 흐름과 API 통신 검증도 함께 수행한다.

실제 Android Chrome·iPhone Safari·PC Chrome의 스크린리더, 200% 확대와 터치 조작, 실제 bfcache, 서버 삭제·세션 전환은 미검증이다. CSS/DOM 테스트만으로 접근성이나 서비스 전체 통과를 주장하지 않는다. 전 화면의 실제 API 연결은 #19 및 각 기능 작업이 완료된 뒤 진행한다.

# 2026-10-17 W11-01.b / #80 보완

TextAreaField와 CheckboxField는 호출자가 지정한 `aria-invalid`와 외부 오류 설명을 유지하며, 컴포넌트의 `error`가 있으면 `aria-invalid=true`를 우선한다. 도움말·글자 수·필수 표식은 18px로 표시한다. UI의 오류 상태 보존·설명 연결·자체 오류 우선 회귀 시험을 추가했다. 실제 기기·스크린리더 검증과 #80 전체 완료는 별도다.
