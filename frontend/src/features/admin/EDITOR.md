# 운영자 공고 등록·조건 편집

## 구조화 조건 후속 단계

PR #134를 기반으로 조건별 원문·종류·비교 방법·값·기준일·묶음을 직접 편집한다. `Plan/02_Data_Design.md` §4와 고정 OpenAPI `Requirement` 표의 조합만 허용한다. 날짜/알 수 없는 값으로 지원 가능 여부를 추정하지 않는다.

- 조건 편집은 적용/취소로 구분하고 적용 전에는 공고 저장을 막는다. 기존 ID와 변경하지 않은 값·시군구·기준일은 유지한다. 목록의 공백/줄바꿈을 값 편집 없이 임의로 재해석하지 않는다.
- 변경한 조건은 확인 필요로 돌아간다. 원문·규칙·묶음·기준일을 별도로 대조한 경우에만 명확 표시를 보낸다. `other`는 항상 null 연산/값과 확인 필요로 남긴다. 원문 줄 단위 빠른 추가도 확인 필요로 등록한다.
- 새 묶음 ID는 사용자의 생성 선택에만 발급한다. 묶음의 AND/OR 변경은 구성원 전체에 적용하고 다른 구성원의 대조를 해제한다. 구성원을 이동/추가/삭제하면 영향을 받은 묶음의 다른 구성원도 확인 필요로 돌아간다. 중첩 그룹을 임의로 만들지 않는다.
- 삭제는 대상 원문과 영향을 표시한 뒤 명시적으로 적용한다. 마지막 조건 삭제 후에는 원문에 필수조건이 없다는 별도 확인이 필요하다.
- 검수 화면은 현재본/공개본의 원문뿐 아니라 비교 방법·값·기준일·명확 여부·묶음 관계도 표시한다. 잘못된 응답 조합은 오류로 처리한다.
- 원문은 React 텍스트/폼 값으로만 표시하고 입력·임시 편집은 메모리에 둔다. 보안 근거는 아래 XSS(제2장 제1절4, PDF28~34)·인가(제2장 제2절2, PDF78~80)·CSRF(제2장 제1절11, PDF54~60)·오류 원문을 재사용한다. 조건 의미와 확인 해제 정책은 프로젝트 계약/기술 판단이며 공식 보안 가이드의 세부 규정이라고 주장하지 않는다.

후속 로컬 검증: 21개 파일·273개 시험, 린트·계약 비교·타입 검사·빌드. 잘못된 조합/중복 ID/그룹 충돌·최소 PATCH·적용 전 저장 차단·범위 오류 포커스·원문 재확인·명시적 삭제·마지막 조건 확인·그룹 전체 수정·정확한 값/ID/기준일 보존·XSS·이탈 시 임시 상태 제거를 검증한다. 실제 백엔드 응답·인가·지역 코드 대조와 모바일/스크린리더는 대기 중이다.

선행 PR #132의 운영자 역할/MFA 확인 뒤에만 접근한다. 신규 등록은 POST, 수정은 선택한 ID/버전의 상세를 명시적으로 조회한 뒤 PATCH한다. 현재 실제 백엔드·운영 동의문은 미확정이며 정상 응답은 테스트 모형으로 검증했다. 생성 API 타입·계약 원문·의존성은 변경하지 않았다.

## 범위

- 제목·기관·유형·공공일자리/원격/보수 여부·지역·장소·일정·주당 시간·마감·원문·접수 안내·필요 서류를 입력한다. 미확인 boolean·지역·서류는 null로 구분하고, 확인한 빈 서류는 빈 배열로 구분한다. 주당 0시간을 누락으로 바꾸지 않는다.
- 신규 조건은 원문을 한 줄에 하나씩 추가하고 모두 `field=other`, `clarity=needs_review`로 등록한다. 연령·요일 등을 자동 추출하거나 지원 가능으로 판정하지 않는다. 새 등록에 조건이 없다면 원문에 명시 조건이 없다는 확인을 따로 받는다.
- 기존 구조화 조건·묶음·기준일·역할/기술 태그·시군구·초 단위 마감 시각은 사용자가 변경하지 않은 경우 보존한다. 기존 구조화 조건은 명시적 편집/적용·삭제 검토로 변경하며 역할 태그 편집은 제공하지 않는다. 지역을 바꾸면 시도 전체로 바뀐다는 안내를 제공한다.
- 수정은 바뀐 필드만 `changes`로 보낸다. 입력된 마감 시각의 표시가 분 단위라도 기존 초/밀리초를 임의로 잘라 보내지 않는다. 수정 전 공개본을 로컬에서 덮어쓰거나 새 내용을 공개 완료로 표시하지 않는다.
- 저장 전 필수 항목·길이·목록·숫자·날짜·HTTPS 형태·원문 비교 확인을 검사한다. 메타데이터의 타입/enum/상한과 추가 필드를 분리해 검증·투영한다. 필수조건의 연산/값 조합·중복 ID·충돌하는 그룹 정의도 검사한다. 출처 신뢰성·지역 목록 등 최종 검증과 인가는 서버가 수행해야 한다.

## 요청·수명

- 등록에는 `Idempotency-Key`가 필요하다. 같은 입력의 네트워크 오류 후 재전송은 같은 키와 조건 ID를 재사용한다. 새 입력에는 새 키를 사용하고 자동 재시도하지 않는다.
- 수정에는 `base_version`을 전달한다. 충돌 시 편집 내용을 유지하고 저장을 잠근 뒤 최신 목록/버전을 선택하도록 안내한다. 서버 저장이 끝난 뒤 응답이 유실될 수 있으므로 네트워크 오류를 롤백 완료로 해석하지 않는다.
- 응답의 ID·버전·검수 상태·본문을 검사한다. 새 등록은 버전 1, 수정은 같은 ID의 더 높은 버전, 둘 다 `pending`일 때만 검수 대기 저장 안내를 표시한다. 공개 승인은 별도 검수 화면의 작업이다.
- 입력·원본·오류·요청은 기존 메모리 수명으로 관리한다. 등록 키와 입력 비교 지문도 페이지 이탈·bfcache 복귀·언마운트에 제거한다. 저장 중 중복 클릭, 페이지 이탈 뒤 늦은 성공/오류를 차단한다. 영구 저장소에 본문을 쓰지 않는다.
- URL은 HTTPS 형태·길이·공백/자격정보 등을 검사하지만 안전한 공식 출처라고 인증하지 않는다. URL을 자동 조회·이동하지 않는다. 실제 서버의 출처 허용 목록과 SSRF 검증을 대체하지 않는다.
