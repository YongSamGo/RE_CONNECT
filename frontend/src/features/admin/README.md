# 운영 검수 후속 · 반려/종료/감사

선행 PR #131의 서버 역할/MFA 확인 뒤에만 이 화면을 제공한다. 백엔드·운영 동의문은 아직 미확정이며, 이 변경은 API 계약에 맞춘 UI와 모형 응답 시험이다. 실제 운영 검증이나 W11-09 전체 완료를 의미하지 않는다.

## 공고 처리

- 목록과 버전이 일치하는 상세를 명시적으로 불러온 뒤 공식 원문과 공개본을 비교한다. API 계약 원본은 기존 고정 커밋의 `docs/api/openapi.yaml`이며 생성 타입을 수정하지 않았다.
- 반려는 `pending` 버전에만 제공한다. 사유를 기본 선택하지 않으며 `other`에는 메모가 필요하다. 반려 버전을 재공개하려면 새 편집 버전으로 검수를 거쳐야 한다.
- 모집 종료는 공식 종료·마감 경과·기관 공지·신고 확인·기타 중 확인한 근거를 직접 선택한다. 수집 실패·일시 누락은 종료 선택지로 제공하지 않는다. 기타에는 메모가 필요하다.
- 메모와 사유 변경 시 검토 확인을 해제한다. 공유 메모 길이는 승인/비공개/반려/종료 계약의 500자 상한에 맞춘다.
- 각 요청은 `base_version`을 전달한다. 성공 응답의 ID·버전·검수 상태·검수 시각을 검사하고 반려가 다른 상태로 응답되면 성공 안내를 하지 않는다. 종료가 새 버전을 만들 수 있는 경우를 구분하며, 승인/반려/비공개 응답은 선택한 버전과 일치해야 한다.
- 처리 중/성공 후 다른 처리를 차단한다. 버전 충돌·허용되지 않은 상태 전이에서는 최신 목록/상세 재조회를 요구하고 같은 화면에서 추가 변경을 차단한다. 자동 재시도하지 않는다. 서버 처리 뒤 네트워크가 끊긴 경우 성공 여부를 추정하지 않는다.

## 감사 조회

- 조회 버튼 전에는 API 요청하지 않는다. 한국시간 시작/종료를 검증해 명시적인 `+09:00` date-time 쿼리로 전송한다. 종료는 시작 이후, 범위는 최대 30일이다. 실제 유효 날짜·페이지·행동/역할/결과 enum·UUID·시각 범위·추적 번호를 검사한다.
- 표시 상태에는 시각·행동·역할·결과·대상 종류·추적 번호만 투영한다. 실행자/대상 ID·개인 본문·OTP·알 수 없는 추가 필드를 복제하거나 화면에 출력하지 않는다.
- 페이지는 마지막 제출 범위로 조회한다. 범위 수정 시 이전 결과를 비우고, 취소/이탈/권한 오류 뒤에는 이전 응답을 복원하지 않는다. 표는 한국시간과 상태 문구를 사용하고 가로 스크롤을 키보드로 조작할 수 있다.
- 기존 `useRequest`와 API 클라이언트의 same-origin·CSRF·no-store·취소·고정 오류 안내를 재사용한다. 브라우저의 운영자 게이트는 서버의 역할/MFA 통제를 대신하지 않는다.
