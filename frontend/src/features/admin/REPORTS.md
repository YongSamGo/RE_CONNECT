# 운영자 신고 처리·종결

선행 PR #133의 서버 역할/MFA 게이트 안에서 신고 목록을 조회하고 신고를 선택한다. 접수 → 처리 중 → 해결로 종결 또는 조치 없이 종결 순서이며, 공고 수정·모집 종료는 별도 작업이다. 실제 서버·운영 동의문은 아직 미확정이다.

- 목록에서 받은 신고 ID/버전·공고 참조·유형·설명·처리 메모·시각만 검증해 화면 상태로 투영한다. 알 수 없는 추가 필드를 복제하지 않는다. 원문은 React 텍스트로 표시한다.
- 접수 상태에서는 처리 시작만 제공한다. 처리 시작의 메모는 선택이며, 서버가 돌려준 새 버전으로 후속 종결을 요청한다. 해결/조치 없이 종결에는 500자 이내의 사유가 필요하다.
- 매 변경에 신고/처리 근거 확인을 요구하고 메모 수정 시 확인을 해제한다. 이미 종결된 신고의 추가 상태 변경은 제공하지 않는다.
- PATCH에는 `base_version`을 전달한다. 응답의 신고 ID·공고 ID/버전·유형·증가한 처리 버전·요청한 상태를 확인한다. 종결 응답의 사유가 비어 있거나 참조가 다르면 성공으로 표시하지 않는다.
- 버전 충돌·상태 전이 오류에서는 작성 메모를 유지하고 추가 변경을 잠근다. 최신 목록을 다시 조회해 재검토한다. 처리 중 중복 전송과 언마운트 뒤 늦은 결과를 폐기하며 자동 재시도하지 않는다.
- 메모와 처리 결과는 기존 `useMemoryScope`/`useRequest`의 메모리 수명 안에만 둔다. 서버 권한/MFA·상태 전이 검증을 화면 검사로 대신하지 않는다.
- 신고 설명과 처리 메모는 API 계약의 500자 상한을 따른다. 공개 신고 입력도 500자로 맞췄으며 초과 입력은 요청 전에 거절한다. 실제 개인정보·인증 정보는 적지 않도록 안내한다.
