# 체험 신청 준비·지원서 (#70/#71/#86 후속)

`/journeys/:journeyId/opportunities/:opportunityId/preparation`는 추천에서 들어오는 서버 체험 전용 화면이다. GET /me·소유 프로필·공개 preparation으로 실제 확정 버전과 공고 버전을 읽는다. 미확정이면 생성하지 않는다. 기존 가상 작성 미리보기는 별도로 유지하고, 운영 안내가 미정이므로 #81 실제 동의/체험 시작도 활성화하지 않는다.

공식 서류/접수 절차·원문·신청 안내와 임시 준비 체크는 기존 공개 준비 컴포넌트를 재사용한다. 새 조회/이탈/pagehide 시 체크를 버린다. null과 빈 서류 목록을 구분하고 임의 서류를 추가하지 않는다. 최신 공개 안내를 다시 읽기 시작하면 이전 안내를 내리고, 공고가 비공개가 되어도 직접 쓴 편집은 지우지 않는다. 외부 링크는 신청 완료로 기록하지 않는다.

생성과 직접 작성은 실제 POST drafts의 generate/manual로 보낸다. 생성 실패는 기존 편집기를 남긴다. 새 생성 중에는 기존 본문을 덮어쓰지 않으며, 결과를 포기하고 기존 본문을 계속 편집하거나 별도 빈 초안을 만들 수 있다. 처리 여부가 불분명하면 같은 키/본문으로 확인한다. 확정된 실패는 새 키로 재시도한다. 새 초안 생성에 따른 이전 서버 초안은 체험 종료/만료 때 함께 지워진다. 응답 기다리기 중지를 런타임/GPU 종료 성공으로 표현하지 않는다. 수정 중인 화면 입력은 먼저 반영하거나 명시적으로 버려야 새 초안을 만든다.

PATCH는 현재 자기소개·지원동기의 전체 본문과 지원서 revision을 보낸다. 성공 응답이 동일 본문·다음 revision·승인 해제인지 검사한다. 서버 NFC/개행 정규화와 일치하도록 전송한다. 확인 체크와 승인 POST는 별개이며, 미반영 편집/미확인/재검토 사유가 있으면 승인을 막는다. 수정은 이전 승인의 적용을 즉시 중지한다. 서버 본문 재조회로 편집을 교체할 때는 버튼에서 버리는 대상을 명시한다. 충돌/AI/통신 오류에는 입력을 유지하며 승인·저장 성공을 만들어 표시하지 않는다.

복사 버튼은 GET draft·GET 소유 프로필·GET 최신 공개 상세를 다시 읽어 화면과 같은 승인 리비전/본문/원래 참조인지 확인한다. 현재 재검토 사유·프로필 재확정·다른 공고 버전·모집 종료/변경 검토·마지막 원문 확인 지연이면 복사하지 않는다. 확인 시각48시간은 표시/복사 편의를 위한 브라우저 시계 검사이며 서버 인가나 영구 저장 검사를 대신하지 않는다. 클립보드 쓰기 직전에 취소 신호도 검사한다. Clipboard API가 거절하거나 비동기 서버 확인 후 브라우저의 사용자 활성화가 만료되면, 방금 검증한 정확한 본문을 보여 주고 전체 선택을 제공한다. 성공을 가장하지 않는다. 읽기·자동 외부 제출·백그라운드 복사는 없다. 기기 클립보드는 체험 종료 후 남을 수 있음을 안내한다.

모든 편집/응답/복사/키/오류/체크는 메모리다. 접근 상실 시 편집기뿐 아니라 요청 훅의 사적 결과 캐시도 지운다. pagehide/unmount/취소 후 늦은 결과와 늦은 복사 상태를 적용하지 않는다. 공통 JourneyRoute의 같은 URL reload/back_forward·BFCache 시작 복귀 경계를 사용한다. 실제 DELETE 204 뒤에만 체험 내용을 비우고 시작으로 이동하고, 삭제 실패에는 편집을 남긴다.

신규 화면/파서20건을 포함한 프론트408건·lint·타입/빌드 통과. 생성/편집/명시 승인/정확한 복사, 생성 실패 입력 보존, 같은 키 재확인/중복, 충돌 명시 재조회, 미확정 차단/체크 임시 상태, 변경 5종 복사 차단, Clipboard 실패 선택, 비공개 편집 보존, 이탈 늦은 생성/복사 폐기, 삭제 오류/204, 대기 결과 포기 후 기존 편집, 세션 만료, 재진입·파서·axe 구조를 검증했다. 실제 ASGI 서비스의 생성/PATCH/승인/GET 응답도 OpenAPI와 프론트 파서에 대조했다(기존 계약15건). 이 계약 시험의 체험/지원서 저장소는 메모리이며 SQL은 SQLite다. 실제 Redis/PostgreSQL 원자 경계는 별도 백엔드944건 기록을 따른다.

실제 Ollama 품질·기기 Clipboard/스크린리더·EC2/운영 HTTPS·회원 저장 #76·음성 읽기와 전체 여정은 남아 있다. #70/#71/#86 전체 통과로 기록하지 않는다. 단순 본문 복사를 외부 신청이나 영구 회원 저장으로 표시하지 않는다.
