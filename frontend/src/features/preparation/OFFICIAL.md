# 공식 준비 안내 — #71 / #86 부분 구현

기준일: 2026-10-17. `/opportunities/:id/preparation`에서 기존 OpenAPI의 공개 GET `/opportunities/{opportunity_id}/preparation`을 명시적 버튼으로 요청한다. 공고 상세에서 진입한다. 로그인·AI 동의·개인 자료를 요구하지 않는 공개 정보 범위다.

## 표시와 수명

- 응답의 요청 공고 ID·양의 버전·상태/방법 enum·날짜·문서 배열을 검증한 뒤 공고 버전, 접수 절차/방법, 마감, 공식 서류만 출력한다. React 텍스트 출력으로 외부 문자열을 HTML로 해석하지 않는다.
- `required_documents: null`은 미명시, `[]`는 서버의 빈 목록으로 구분한다. 어느 경우도 서류가 불필요하다고 단정하거나 임의 서류를 채우지 않는다.
- 임시 체크는 화면 메모리에서만 관리하며 서버/브라우저 저장소에 저장하지 않는다. 이탈·재조회·새로고침·pagehide에서 초기화하고 늦게 도착한 취소 응답은 표시하지 않는다. 제출·자격 충족·신청 완료로 기록하지 않는다.
- 모집 마감·미확인·변경 검토 중이면 체크와 신청 링크를 차단한다. 출처 링크는 기존 Work24/1365 공식 상세 URL 허용 목록을 재사용한다. 새 창은 noopener/noreferrer·no-referrer를 적용한다.
- 본문 2,000자·서류 이름 200자는 계약에 맞추고, 문서 최대 100개·URL 2,048자는 화면의 방어 한도로 정했다. 후자의 수치와 메모리 정책은 프로젝트 판단이며 공식 가이드의 수치 요구사항이 아니다.

## 검증과 남은 조건

`npm test`의 전용 19건으로 ID/버전/날짜/목록 오류, 텍스트/주소 처리, null/빈 목록, 체크 초기화, 상태별 차단, 취소·오류·재시도·포커스를 확인했다. 초기 잘못된 공고 주소 화면은 기존 axe 검사에 포함했다.

2026-10-18 로컬 통합에서 #66 준비 API를 연결했다. `npm run test:backend-contract`는 실제 FastAPI·SQLite 공개 포인터·HTTP·Vite 프록시·기존 API 클라이언트·프론트 파서·OpenAPI 검증을 함께 실행한다. 온라인/전화/복합 접수와 `null`/빈/명시 서류를 포함한 계약 시험 11개가 통과했다. 시험 서버의 가상 공고는 임시 SQLite에만 넣으며 실행 제품에 대체 성공 응답을 넣지 않는다. 이 결과는 Node HTTP 계약 시험이며 Chromium 성공 화면·실제 기관·배포 PostgreSQL·기기·스크린리더 사용성 검증은 아니다.

2026-10-24 로컬 구현에서 확정 프로필 추천의 공고별 `/journeys/:journeyId/opportunities/:opportunityId/preparation` 진입을 추가했다. 확정 프로필·모집 상태를 조회한 뒤 AI 생성 또는 빈 초안 작성을 명시적으로 요청한다. 현재 AI 처리 동의는 AI 생성에만 요구하며 수동 작성은 동의 없이 허용한다. 생성 응답 유실은 같은 키·본문으로 재확인하며 자동 재생성하지 않는다. 입력 변경, 서버 임시 반영, 다시 읽기 확인, 서버 승인, 회원 저장 선택은 별개다. 충돌 시 입력을 유지하고, 화면의 수정 내용을 서버 편집본으로 교체하려면 확인을 받는다. 승인된 현재 본문만 별도 저장 선택 화면으로 연결한다.

전용 UI/파서 시험 14개로 수동 작성→수정→재확인→승인, 생성 멱등 키, 버전 충돌, AI 실패 후 명시적 수동 전환, AI 동의 누락 시 생성 차단과 수동 허용, pagehide 후 늦은 본문 파싱 폐기, 복사 실패의 직접 선택, 변조된 참조 차단을 확인했다. 서버가 모델 실패·AI 시간 초과·기존 요청 처리 완료를 확인한 경우에만 별도 버튼으로 새 AI 요청을 선택할 수 있다. 이때 현재 프로필·공고·동의를 다시 조회한다. 네트워크 단절처럼 결과가 불확실하면 새 키 버튼을 제공하지 않고 기존 키·본문으로 재확인한다.

승인 응답 유실 뒤에는 승인 요청을 자동 반복하지 않고 서버 현재본을 조회해 실제 승인 상태를 복원한다. 프로필 변경·공고 변경·모집 마감의 재검토 응답을 받으면 본문을 유지하면서 승인·회원 저장 진입을 차단한다. 승인 화면의 자동 axe 검사도 포함한다.

UI 시험은 가상 응답을 사용하는 로컬 회귀 검사다. 별도 `test:draft-contract`는 실제 Redis·SQLite·FastAPI ASGI 응답의 생성·수정·승인 및 공고 마감/프로필 재확정 뒤 재검토 투영을 OpenAPI와 화면 파서에 대조한다. 기존 본문·근거 버전·승인 시각·revision이 재검토 조회에서 바뀌지 않음을 확인했다. 실제 체험 API부터 회원 저장까지의 브라우저 통합, 실제 기기·스크린리더, 실제 운영 동의·카카오 로그인 검증은 남아 있다. 기존 `/preparation`의 문장 미리보기를 이 공고의 지원서로 취급하지 않는다. #71/#86 전체 완료나 이슈 종료를 뜻하지 않는다. 최신 사용자 지시에 따라 이 변경은 로컬에만 보관하고 PR·원격 push를 하지 않는다.

`backend/tests/test_saved_drafts.py`의 전체 여정 회귀는 익명 체험 생성→프로필 편집·확정→수동 초안 생성·수정→미승인 저장 차단→승인→저장 대기→가상 제공자 OAuth→별도 저장 동의→프로필 우선 저장→지원서 저장·조회까지 실제 Redis/SQLite/ASGI 서비스로 연결한다. 생성 및 각 저장 요청의 같은 키 재전송도 단일 저장으로 처리하고 SQL에는 암호문을 보관함을 확인한다. 해당 파일 15개 통과, PostgreSQL 환경이 필요한 5개는 이번 실행에서 건너뛰었다. 기존 Redis/SQL 통합 CI가 이미 실행하는 시험 파일에 추가했지만 새 커밋의 원격 CI는 실행하지 않았다. 실제 브라우저나 실제 카카오 성공을 이 결과로 주장하지 않는다.
