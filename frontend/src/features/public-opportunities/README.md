# 미동의 공개 탐색 — W11-02.a / #81

역할 A의 #81 중 UX01의 **로그인·AI 동의 없이 공개 공고 탐색**이다. #120 위에 쌓는 별도 초안 PR #121이다. #80·#36·#9·#50이 미완료여서 #81 전체를 닫지 않는다. 이후 공개 상세 구현은 [DETAIL.md](DETAIL.md)에 기록한다. 맞춤 추천·자격·신고는 #85 등의 후속 범위다.

## 사용과 요청 경계

`/opportunities` 진입만으로 요청하지 않는다. 검색 버튼을 눌렀을 때 현재 origin의 `GET /api/v1/opportunities`를 호출한다. `/me`, 동의·체험·로그인·AI API는 호출하지 않는다. HTTP 메서드·경로·쿼리는 #117의 생성 타입을 사용한다.

- 검색어(최대 100자), 시·도(서울/경기/인천), 취업·공공일자리/봉사 유형을 지원한다. 시·군·구 선택은 서버 지역 목록 연결 후 남겨 둔다.
- 앞뒤 공백을 제외한 빈 검색어·미선택 필터는 쿼리에 넣지 않는다. 검색 조건을 자동으로 넓히지 않는다.
- 페이지는 1부터, 페이지 크기는 계약대로 20이다. 화면에 적용한 조건을 별도로 표시하며, 수정 중인 폼과 마지막 조회 조건을 구분한다. 페이지 이동·오류 재조회는 마지막 조회 조건을 사용하고 새 검색은 1페이지부터 시작한다.
- 조회 중 중복 제출을 차단하고 취소를 제공한다. 취소·화면 이탈·bfcache 복귀 후 이전 응답이 새 결과를 덮어쓰지 못한다. 검색 폼과 결과 모두 `useMemoryScope`에만 보유하며 주소 표시줄·영구 저장소에 넣지 않는다.
- 0건과 현재 페이지가 비었지만 total이 남아 있는 경우를 구분한다. 장애 때 검색어와 필터를 유지하고 고정 오류·명시적 재시도를 제공한다. 자동 재시도하지 않으며 일일 한도에는 즉시 재조회 버튼을 제공하지 않는다.

Vite 개발 서버에는 임의의 백엔드 주소나 프록시를 새로 정하지 않았다. 실제 연동은 C 담당의 같은 origin Nginx `/api/v1` 구성이 필요하다. 현재 Vite의 HTML fallback이나 서버 부재는 성공으로 처리하지 않는다. `npm run dev`는 화면 확인용이며 실제 서버·공고 연결 완료를 뜻하지 않는다.

## 응답과 표시

실제 API 응답이 없으면 가상 공고를 표시하지 않는다. `test-fixtures.ts`는 단위 시험에서만 import한다. 목록 카드의 상세 링크는 검증한 UUID로 만든 내부 경로이며 상세에서 최신 모집 상태와 원문 조건을 확인하도록 안내한다. 목록에는 공식 원문·신청 링크를 만들어 넣지 않는다.

`catalog.ts`는 응답을 unknown으로 받아 표시할 공개 필드만 검증·투영한다. UUID·문자열 길이·enum·명시적 null·불리언·페이지/total·20개 한도·중복 ID와 날짜 형식을 확인한다. 응답이 요청 페이지와 다르거나 페이지 크기가 다르면 거절한다. 공개 목록 계약을 어긴 모집 종료 항목은 조용히 숨겨 건수와 불일치시키지 않고 응답 전체를 거절한다. 미검수 여부는 Summary에 필드가 없어 브라우저가 증명할 수 없으므로 서버의 검수·공개 정책 검증은 #50에서 필요하다.

이 검사는 이 공개 화면의 표시 경계다. 모든 API에 적용되는 JSON Schema 검증이나 백엔드 공통 모델(#15)의 대체가 아니다. 표시할 수 없는 빈 제목·비정상 날짜도 거절하며 정의되지 않은 추가 필드는 보관하지 않는다.

- `unknown` 모집 상태, `change_pending`, 미확인 보수·지역을 각각 문구로 표시한다. 성공 확률·지원 가능 판정을 만들지 않는다.
- 정확한 시각이 있으면 Asia/Seoul로 표시한다. 날짜만 있으면 임의의 자정·종료 시각을 만들지 않고 시각 확인 필요로 안내한다. 날짜와 시각의 한국 날짜가 충돌하면 거절한다.
- 실제 시·군·구 명칭 목록을 아직 받지 않았으므로 내부 식별값으로 명칭을 추정하지 않는다. 지역은 시·도까지만 표시하고 시·군·구는 상세에서 확인할 항목으로 안내한다.
- 제목·기관·검색어는 React 텍스트로 출력한다. HTML·마크다운을 실행하지 않는다. 오류 본문의 내부 메시지는 기존 ApiError/RequestError 경계에서 제거한다.

조회한 필터와 결과는 공개 데이터지만 개인정보가 섞인 검색어를 별도 로그·스토리지에 기록하지 않는다. GET 검색어는 HTTP 요청 URL에는 포함되므로 서버 접근 로그·출처 데이터 정제 정책은 백엔드·운영에서 별도로 확인해야 한다.

## 검증·남은 작업

기존 78건에 공개 목록 30건을 더해 총 **108건**을 검증한다. 명시적 GET·쿼리 인코딩·필터·페이지/조회 조건 분리·빈 결과/빈 페이지·장애 재시도·중복 제출·취소·늦은 응답·언마운트/페이지 이탈·XSS·안전한 내부 링크·날짜/응답 경계를 포함한다. 계약 생성 검사·엄격한 타입 검사·빌드·린트도 수행한다. 시험용 응답을 실제 API 연결 증거로 사용하지 않는다.

2026-10-15 로컬 검사에서 108건·계약 생성 일치·엄격한 타입 검사·빌드·린트를 통과했다. 인앱 Chromium에서 실제 검색 버튼을 눌러 Vite HTML fallback을 성공으로 처리하지 않고 고정 오류를 표시하며 검색어·선택 지역을 유지하는 것을 수동 확인했다. 이 확인은 정상 공개 API 연결 증거가 아니다.

실제 공개 API·검수한 공고·기기 접근성·키보드/200% 확대·실제 bfcache·API 장애 중 다른 기능 유지 검증은 남아 있다. 공개 릴리스 전 개발 안내 문구와 실제 연결 상태를 함께 점검해야 한다.

AI 처리 동의는 기존 가상 미리보기 선택으로 유지한다. 운영 주체·문의처·리전·정책이 미확정인 상태에서 운영 동의를 기록하거나 체험 생성 성공으로 표시하지 않는다. 다음 기능 연결은 #9/#36/#50 등의 계약과 구현을 확인한 뒤 진행한다.
