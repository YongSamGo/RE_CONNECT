# 공개 공고 시·군·구 검색

PR #137 다음 단계다. 공개 `/regions` 목록으로 검색 세부 지역을 선택하고 `/opportunities`에 `province`와 `district`를 함께 전송한다. 프로필과 검색이 같은 검증기를 사용하도록 기존 지역 목록 투영 함수를 `frontend/src/features/regions/catalog.ts`로 이동했다. 생성 API 타입·고정 계약·의존성은 변경하지 않았다.

- 지역 목록과 공고 검색은 버튼으로 시작하는 독립된 공개 GET이다. 로그인·AI 처리 동의·프로필 확정 요청을 추가하지 않는다. 실제 백엔드가 없으면 오류를 표시하고 예제 목록을 앱에 주입하지 않는다.
- 시·도를 직접 바꾸면 이전 시·군·구를 해제한다고 안내한다. 세부 지역을 고르지 않으면 해당 시도 전체를 검색한다. 지역 목록 조회 실패/취소/삭제된 식별값 때문에 세부 지역을 자동으로 해제하지 않는다.
- 새로운 세부 지역 검색은 현재 조회한 목록과 일치해야 한다. 일치하지 않으면 검색 요청 없이 폼 오류와 포커스 링크를 제공하고, 목록을 다시 조회하거나 사용자가 활동 범위를 직접 바꾸도록 한다. 조회 중 새 검색은 잠근다.
- 제출 당시 검색어·시도·세부 코드·표시명·지역 목록 버전을 메모리에 복사한다. 페이지 이동/같은 조건 재시도에는 이 적용본을 사용한다. 사용자가 폼 또는 목록을 바꿔도 기존 검색의 의미와 설명을 바꾸지 않는다. 새 검색은 1페이지부터 시작한다.
- 이미 적용한 검색의 페이지 이동/재시도는 같은 코드를 그대로 서버에 전달한다. 목록 재조회가 옛 검색을 자동 변경하지 않는다. 서버의 현행 지역 검증이 실패하면 오류로 처리하며 검색 범위를 넓혀 재요청하지 않는다.
- 표시명/목록 버전은 화면의 적용 조건 설명에만 쓴다. API에는 계약에 있는 검색 필드만 보낸다. 목록 버전을 서버가 요청 인자로 검증했다고 주장하지 않는다. 검색 조건을 주소 기록·영구 저장소·로그에 추가하지 않는다.
- 검색/지역 목록/입력/폼 오류는 기존 메모리 수명을 사용한다. 취소·페이지 이탈·언마운트 뒤 늦은 성공/실패는 폐기한다. 실제 목록/검색 서버와 모바일/스크린리더 검증은 남아 있다.
