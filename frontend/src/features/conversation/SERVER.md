# 서버 체험 대화 화면 (#82)

`/journeys/:journeyId/conversation`에서 실제 GET /me와 소유 프로필의 revision을 읽고, POST /journeys/{id}/messages에 사용자가 확인한 직접 입력·transcription_id:null·base_revision·UUID 멱등 키를 보낸다. 서버 쿠키 세션·동의·소유권을 우회하지 않으며 체험 ID를 생성하지 않는다. 운영 정보가 미정이므로 #9/#81의 실제 동의·체험 시작은 활성화하지 않는다. 기존 `/conversation`은 가상 정보의 메모리 미리보기로 유지한다.

현재 질문 하나만 표시하고 성공하면 다음 질문으로 교체해 포커스를 옮긴다. 프로필 확인 링크는 요청 중에도 사용할 수 있고 완료를 강제하지 않는다. 프로필에서 직접 편집·확정하며 이 화면에서는 자동 확정하지 않는다. 현재 메시지 API의 AI 추출 범위는 경험이므로 지역·활동 유형·다른 조건은 프로필에서 직접 선택한다고 안내한다. 질문이 없는 응답은 프로필 검토로 안내한다.

화면이 아는 리비전보다 낮거나 요청의 base_revision+1과 다른 응답은 적용하지 않는다. 메시지 응답과 포함 프로필의 revision, UUID, 질문/next_step/누락 항목, 텍스트/주의사항 길이를 런타임 검사한다. 대화 복원 GET·localStorage·sessionStorage는 추가하지 않는다. 준비/재조회는 서버 프로필 상태와 고정 질문을 읽으며 과거 대화가 복원되었다고 표현하지 않는다.

동일 렌더 안의 연속 submit도 잠금으로 막는다. 통신 단절·시간 초과·미확인 응답·처리 중 응답에는 입력과 원래 요청 번호/본문을 메모리에 보존하고 편집을 잠근다. 결과 재확인은 같은 요청을 보내며, 서버의 멱등 재생이 중복 추론을 방지한다. 확정된 AI 실패에는 입력을 다시 편집하고 새 키로 재시도할 수 있다. 리비전 충돌은 입력을 유지하고 명시적으로 최신 프로필 상태를 읽기 전까지 전송을 막는다. 응답 기다리기 중지는 클라이언트 요청을 무효화하며 서버 처리가 끝났을 수도 있다고 설명한다.

프로필 이동/언마운트/pagehide는 화면 입력·요청·결과를 폐기하고 늦은 응답을 적용하지 않는다. 프로필 이동 후 미전송 입력을 복원하지 않는다. 세션/동의/소유권 접근 상실 시 본문을 지운다. 공통 JourneyRoute는 체험 URL 자체의 reload/back_forward 재진입을 API 요청 전에 시작으로 돌리고 BFCache 복원도 시작으로 이동한다. 프로필 화면도 같은 경계를 사용한다.

종료는 별도 삭제 확인 뒤 실제 DELETE를 호출한다. 204가 확인된 뒤 입력을 비우고 시작으로 이동하며 실패하면 입력을 남긴다. 화면 이탈을 서버 삭제 완료로 표시하지 않는다.

화면 대역 시험은 정상 전송/한 질문·포커스, 요청/CSRF/리비전, 응답 유실과 같은 키 재확인, 중복 submit, 확정 실패의 새 키, 충돌과 구 응답 거절, 요청 중 프로필 이동, 늦은 응답 폐기, 기다리기 중지, 명시 삭제, 접근 상실, reload 차단, 런타임 파서와 axe 구조를 검사한다. 실제 Redis/PostgreSQL 메시지 API의 검증은 백엔드 #37 시험의 별도 증거다. 화면 대역을 실제 모델/브라우저 전체 여정 검증으로 계산하지 않는다. 실제 Ollama 품질·#81 시작 연결·음성 #83·배포/대상 기기/스크린리더 전체 여정은 남아 있으며 #82 전체 통과로 기록하지 않는다.
