# 로그인·내 정보 연결 범위 (#87)

`/auth/result`는 서버 OAuth 왕복의 고정 복귀 주소다. `purpose=login|save|reauth`, `status=success|cancelled|failed|expired`를 각 하나씩만 받는다. 추가·중복·알 수 없는 값은 표시하지 않고 내 정보로 안내한다. 쿼리의 성공 표시는 인증·재인증·자료 저장 증거가 아니다.

사용자가 상태 확인을 누르면 same-origin `/api/v1/me`를 조회하고 기존 런타임 파서로 검증한다. 회원 상태, 유효한 저장 대기 자료의 프로필/지원서 대상, 기존 프로필 교체 필요성, 서버 재인증 기한만 안내한다. 사용자·자료 식별자는 화면이나 URL에 출력하지 않는다. 새 대화는 이전 대화를 복원하지 않는다. 성공/실패 원문을 반영하거나 임의의 반환 URL로 이동하지 않는다.

결과는 컴포넌트 메모리에만 둔다. 화면 변경·pagehide·bfcache 복귀 때 지우며, 대기 요청/재인증 기한 또는 확인 후 1분 중 먼저 도래한 시점에도 지운다. 이는 화면 안내의 유효 시간이며 실제 작업의 인가는 항상 서버에서 다시 검사한다.

## 운영 안내 확정 전

운영 주체·문의처·AWS 리전·보관 정책이 미정이다. 이 화면은 로그인 시작·동의 수락·저장 API를 자동으로 호출하지 않는다. 프로필+지원서 요청은 두 자료 모두 저장 대상임을 명시한다. 안내문이 준비되기 전에 임의의 안내문 버전이나 테스트 안내문으로 실제 동의를 받지 않는다.

## 저장 준비·확인과 취소

`/journeys/:journeyId/save`는 확정 프로필을, `/journeys/:journeyId/drafts/:draftId/save`는 승인 지원서와 프로필 묶음을 준비한다. 서버의 현재 확정/승인 참조를 읽고, 미확정 변경·미승인·재검토 상태면 진행하지 않는다. 현재 회원은 체험 참조로 직접 저장하고, 익명은 명시적 확인 뒤 저장 대기 참조를 만들고 고정 카카오 시작 주소로 이동한다. 실제 지원서 작성/승인 화면의 진입 연결은 #86과 함께 검증한다.

`/me/save`는 서버 `/me`에 결합된 자기 저장 대기만 읽는다. 프로필/지원서 전체 대상과 기존 프로필 기준 버전을 별도로 확인하고, 프로필 먼저·지원서 다음 버튼을 누른다. 기존 저장본과 내용이 같으면 서버가 같은 버전을 연결한다. 프로필만 성공한 경우 지원서 전체 성공을 표시하지 않는다. 응답 유실 때는 단계별 같은 멱등 키·같은 본문으로 재확인한다. 실제 쓰기 전후 현재 회원과 유효한 저장 동의를 다시 검사하며, 다른 세션·철회 후 선택을 재사용하지 않는다.

`DELETE /auth/save-intents/{id}`는 현재 세션에 결합된 일치 대기만 취소한다. 익명·회원 모두 Origin/CSRF 보호를 받고, 회원은 저장과 같은 소유자 잠금 안에서 폐기한다. 다른 세션/만료/기취소 ID는 내용 유무를 노출하지 않는 204다. 프로필을 이미 저장한 뒤 남은 지원서 대기를 취소해도 저장 프로필·동의·로그인은 유지한다. 체험에서 직접 저장하는 회원의 취소는 화면의 진행만 종료한다.

## 확정 안내문의 게시 설정

`GET /consents/notices`는 공개 텍스트만 제공한다. 런타임의 `CONSENT_NOTICES_JSON`이 없으면 목적별 안내문은 null이고 새 로그인 진입은 비활성이다. 버전 환경변수만 설정해도 안내문이 생기지 않는다. 실제 운영 값은 저장소에 넣지 않는다.

공급 형식은 `{state: "approved", ai_processing: 안내문 또는 null, storage: 안내문 또는 null}`이다. 각 안내문은 `version`, `title`, `controller`, `contact`, `aws_region`, `body`, `retention`, `deletion`을 모두 가진다. 목적별 `version`은 서버의 `AI_NOTICE_VERSION`/`STORAGE_NOTICE_VERSION`과 같아야 한다. 초안·누락·숨은 제어 문자·불일치는 시작 때 거절하며 원문을 오류에 넣지 않는다. 게시 여부는 문구의 법적·운영적 정확성을 자동 인증하는 값이 아니다. 운영 담당자가 확정하고, 내용을 바꿀 때 버전도 함께 바꿔 배포해야 한다.

화면은 안내문을 HTML/마크다운/외부 링크로 실행하지 않고 일반 텍스트로 표시한다. 현재 안내문을 읽고 별도 체크한 뒤에만 저장 동의를 요청하며, 서버의 현재 버전 검사와 `/me` 재확인을 통과한 경우에만 저장 선택을 활성화한다. 새 로그인은 게시된 저장/계정 안내와 제공자 구성이 모두 준비돼야 진입할 수 있다. 계정 삭제용 현재 회원 재인증은 별도다.

현재 운영 주체·문의처·리전·정책은 미정으로, 실제 게시 설정과 실동의는 계속 비활성이다. 시험은 가상 주체·안내문·제공자를 사용한다.

## 남은 실증

- 실제 운영 정보 확정과 게시 설정, 실제 카카오 정상 로그인, #86 승인 화면의 저장 진입 연결.
- 지원서 재편집·목적별 철회를 포함한 배포 환경 전체 왕복 시험. 기존 서버 시험과 화면 대역 시험을 실제 운영 증거로 계산하지 않는다.
- 실제 제공자·배포·모바일/PC 접근성 검증. 가상 제공자 시험은 이 증거를 대신하지 않는다.

로컬 Chromium 브라우저에서는 가상 제공자·안내문·체험 자료로 저장 준비→OAuth 왕복→현재 회원 확인→명시 동의→프로필 먼저/지원서 다음 저장→자기 자료 목록/상세→프로필 및 연결 지원서 삭제→재인증→별도 탈퇴 확인을 실행했다. 실제 API·PostgreSQL·Redis를 사용했고 마지막 SQL 사용자/프로필/지원서/동의는 0건, 최소 삭제 이력만 2건이었다. 시험 서버·SQL 스키마·세션은 시험에서 만든 것만 정리했다. 이 기록은 로컬 연결 증거이며 이슈 전체 운영 통과를 뜻하지 않는다.
