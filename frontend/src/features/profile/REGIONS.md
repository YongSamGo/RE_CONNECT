# 희망 활동 지역의 시·군·구 선택

PR #136 다음 단계다. 기존 시·도 선택을 `Region { province, district }[]`로 유지하고 공개 `/regions` 목록에서 서버 식별값·표시명·버전을 받아 세부 지역을 고른다. API 생성 타입·계약·의존성은 바꾸지 않았다.

- 버튼을 누른 경우에만 공개 GET을 수행한다. 로그인·운영 동의문·AI 처리·프로필 저장 요청 없이 동작한다. 실제 백엔드가 없으면 오류를 표시한다. 앱에 예제 지역 목록을 주입하지 않는다.
- 시·도 전체는 `district=null`, 세부 지역은 서버 목록의 식별값으로 구분한다. 전체와 같은 시·도의 세부 지역을 중복 선택하지 않는다. 합계 최대 10곳은 고정 프로필 API 계약의 `preferred_regions` 상한을 따른다.
- 모든 지역 선택 변경과 목록 재조회는 미리보기 확인을 해제한다. 조회 중에는 지역 수정/항목 확인을 잠근다. 다른 화면으로 이동하거나 요청을 취소한 뒤 늦은 응답은 폐기한다.
- 조회 실패·변경된 목록·화면 왕복 후 목록 미조회 상태에도 기존 식별값을 보존한다. 목록에 없는 세부 지역은 대조 필요 표시와 제거 버튼을 제공한다. 전체 지역으로 자동 확장하지 않으며, 사용자가 목록을 다시 조회하거나 선택을 직접 변경/제거해야 항목 확인을 통과한다.
- 시·도 전체 선택은 계약의 고정 Province enum에 근거한다. 세부 지역은 현재 조회 목록에서 대조한다. 이름을 추정해 코드를 만들거나 거주 자격·추천 가능 여부를 판정하지 않는다.
- 목록 응답은 버전/표시명 길이·식별값 패턴·허용 시도·중복 ID를 검사한 뒤 필요한 필드만 투영한다. 시·도당 100개 목록 상한은 UI 처리량을 위한 기술 판단이며 계약 원문의 상한이 아니다. 식별값 중복은 같은 시·도 안에서 검사한다.
- 선택은 기존 App 메모리 수명으로 관리한다. 경험/희망 조건의 확인은 미리보기 표시이며 서버 프로필 확정·동의·저장으로 기록하지 않는다. 실제 목록·모바일·스크린리더·서버 확정 연동 검증은 남아 있다.
