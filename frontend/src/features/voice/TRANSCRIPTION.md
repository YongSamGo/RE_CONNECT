# 체험 녹음·전사 수정 (#83)

실제 `/journeys/:id/conversation` 안의 별도 음성 패널에서 동작한다. 텍스트/전사/Blob을 URL·React Router state·브라우저 저장소로 전달하지 않는다. 패널 취소는 원래 대화 입력을 남기고, 전사 성공은 확인 문장에만 표시한다. 사용자가 수정 문장을 입력칸에 사용하고 다시 보내기를 눌러야 messages에 text와 소유 transcription_id를 보낸다. 원문을 자동 추출하거나 전사 성공을 사실 확정으로 표시하지 않는다.

기존 VoicePreview 녹음 수명을 useAudioRecorder/AudioRecorderControls로 공유했다. 가상 미리보기는 여전히 서버로 보내지 않는다. 실제 패널은 명시적 전송 버튼에서만 타입이 있는 Blob/단일 audio FormData·CSRF·UUID 멱등 키로 전사 API를 호출한다. getUserMedia는 녹음 시작 때만 요청하며 WebM/Opus 또는 MP4/AAC 지원을 검사한다.90초 타이머/6MiB 상한, 마이크 이탈/권한 거절·미지원 형식·빈 녹음/오류를 안내하고 직접 글쓰기를 유지한다. 실제 길이·압축 디코드는 서버의 판정이 우선이며 기기 인코더/타이머 지연 경계는 실기기 시험이 필요하다.

전송 중 중복 요청/녹음/확인 문장 편집을 막는다. 성공·실패·취소·이탈 뒤 track·recorder handler·timer·chunks·Blob·플레이어·object URL을 정리한다. 실패하면 기존 수정 문장은 남기고, 원본은 재전송하지 않으며 다시 녹음하거나 직접 작성한다. 늦은 업로드의 finally가 다음 새 녹음을 정리하지 않도록 녹음 generation에 묶은 cleanup을 사용한다. 서버가 처리를 끝냈을 수 있으므로 클라이언트 취소를 모델 실행 종료로 표시하지 않는다. 접근 상실은 부모 대화의 사적 입력/응답 캐시까지 지운다.

새11건 포함 프론트419건·lint·타입/빌드 통과. 명시 마이크/전송·multipart/CSRF/키·성공 정리/수정 확인, 실패 입력 유지, 중복/취소/늦은 응답, 이전 요청 정리가 새 녹음을 멈추지 않음, permission 이탈, 형식/권한 실패, 세션 상실, 부모 원래 입력 보존/수정 전사만 messages 전달, 파서/axe 구조를 검증했다. 미리보기의 기존5개 녹음 정리 시험도 유지했다. 첫 새 시험의 Node/jsdom File 클래스 불일치는 시험의 native Blob/File/FormData로 맞춰 통과했으며 제품 우회 코드를 추가하지 않았다.

계약16건 중 새 검사는 실제 API 클라이언트가 직렬화한 FormData를 실제 Python 제한 multipart 파서로 전달해 바이트 크기·SHA-256·MIME 보존을 대조한다. 이 검사는 모델이나 실제 마이크를 실행하지 않는다. 실제 Redis/HTTP 전사 완료 경계는 별도 백엔드1008건 증거다.

실제 STT 모델 서버·압축 codec/무음·한국어 정확도·PC/Android/iOS 세 기기·운영 HTTPS·스크린리더 전체 여정은 미검증이다. 운영 정보 미정으로 실제 동의/체험 시작 #81은 계속 비활성이다. #83 전체 통과나 실제 기기 녹음 성공을 주장하지 않는다.
