## 최종 화면 원칙

사용자의 추가 요청에 따라 한 화면에서 판단할 항목을 줄였다. 기능을 가리는 대신 다음 단계와 펼침 영역으로 나눴다.

- 홈: 서비스 목적과 두 진입 행동을 먼저 보여준다. 가상 입력과 정리 예시는 기본적으로 접혀 있다. 반복 설명 3개를 제거했다.
- 동의: 현재 미리보기의 입력 제한과 메모리 보관, 새로고침 및 종료 시 삭제를 먼저 안내한다. 향후 AI 처리 위치와 회원 저장 조건, 운영 안내문 미확정 사실은 펼쳐서 읽는다. 운영 동의로 기록하지 않는다.
- 경험 입력: 가상의 경험 한 가지를 적는 작업에 집중한다. 개인정보 입력 금지와 AI 미연결 상태를 유지한다.
- 작성 내용 확인: 입력한 경험만 보여준 뒤 사용자가 활동 조건 선택으로 넘어간다. 빈 경험이면 진행을 막고 수정 경로를 제공한다. 단계 변경 시 제목으로 초점을 이동한다.
- 활동 조건: 지역과 활동 유형을 선택한다. 선택과 검증의 기존 API 구조를 유지한다. 세부 정책과 지역 목록 버전은 펼쳐서 읽는다.
- 공고 탐색: 검색어와 활동 지역, 활동 유형이 기본이다. 시군구는 별도로 펼친다. 선택된 세부 지역은 접힌 제목에도 표시하며 지역 오류 시 펼침 영역을 연다. 검색 결과는 구분선이 있는 목록이다.
- 신청 작성 연습: 긴 사전 안내는 펼쳐서 읽는다. 내용 확인 후에만 복사 영역이 나타난다. 입력 유지와 삭제 및 클립보드 보관 조건은 유지한다.
- 실제 여정, 로그인, 저장: 문구와 공통 UI 스타일을 정리했다. 로그인 확인과 저장 성공을 구분하고 서버 응답 검증 및 멱등 재확인 구조를 유지했다. 서버 안내문 원문과 외부 공고 원문은 편집하지 않는다.

## 시각 기준

바탕 #F5F8F4, 표면 #FFFFFF, 본문 #182820, 주요색 #25634B, 작은 강조 #DDEBA7, 경계선 #D6DFD7. 기존 Noto Sans KR / Malgun Gothic 체계를 유지하며 새 폰트나 UI 패키지는 추가하지 않았다. 본문 18px, 주요 버튼 최소 높이 56px다. 모서리는 입력 및 행동에 8px, 내용 영역에 10px를 기본으로 두고 불필요한 아이콘과 장식용 화살표를 제거했다. 기본 키보드 초점과 reduced-motion 대응을 유지했다.

대표 색 조합의 계산 대비는 본문/바탕 14.39:1, 보조 글자/바탕 5.97:1, 보조 글자/연한 표면 5.68:1, 흰 글자/주요 버튼 7.08:1이다. 이 값은 대표 토큰 조합의 계산이며 WCAG 전체 적합성 판정이 아니다.

- 자동 접근성 검사는 jsdom에서 레이블과 구조 및 ARIA를 확인하며 실제 색 대비나 기하를 측정하지 않는다. 일부 axe 테스트는 jsdom의 canvas 미지원 알림이 있으나 검사 결과를 숨기거나 조작하지 않았다.

실제 200% 브라우저 확대와 스크린리더, Android/iPhone, 실사용자 검증, 카카오 인증 왕복, 서버 AI 및 DB 저장, AWS 운영 상태는 미검증이다. 전체 테스트와 E2E, 백엔드 테스트는 실행하지 않았다.

## 2026-10-27 전 화면 공통 UI 개선 후속

첫 화면 이후 공통 제목·폼·버튼·안내·패널과 반응형 간격을 정리했다. 공고 검색·상세, 경험 확인, 대화, 음성, 지원 내용 작성, 추천, 계정 관리, 저장 자료, 운영 화면의 관련 표면을 공통 체계에 맞췄다. 회원 동의 철회와 탈퇴는 각 결과를 구분하는 영역으로 나누되 요청·확인 조건은 바꾸지 않았다. 소개 영상은 여전히 준비 상태이며 재생 기능을 표시하지 않는다.

첫 화면·공통 UI·계정·공고 관련 테스트 95건, 대화·프로필·작성·저장 관련 테스트 31건, 운영·음성·추천·공식 준비 관련 테스트 88건이 통과했다. 후속 음성·추천 변경 뒤 관련 테스트 43건을 다시 실행했다(앞선 테스트와 중복). 린트와 API 타입 확인을 포함한 빌드가 통과했다. 데스크톱 브라우저에서 공고 검색, 경험 입력 및 확인, 활동 조건 선택, 작성 연습 화면을 확인했다.

모바일 실기기·200% 확대·실제 대비·스크린리더 및 시니어 사용자 검증은 수행하지 않았다. 서버 인증이 필요한 계정·운영·실제 체험의 성공 상태와 API 연동은 브라우저에서 확인하지 못했다. 자동 테스트와 공통 스타일 적용만으로 모든 상태의 실제 사용성을 확정하지 않는다.

## 전 화면 세부 정리 및 좁은 화면 확인

체험 프로필·추천·신청 준비의 관련 화면 이동 링크와 조작 묶음을 분리하고, 추천 필터가 좁은 화면에서 세로로 배치되도록 했다. 프로필 편집 입력 간격, 역할 목록과 지원서 복사 영역을 정리했다. 접힌 경험 예시의 키보드 포커스 표시가 경계에서 잘리지 않도록 조정했다.

관련 추천·프로필·신청 준비·접근성 테스트 71건이 통과했고, 후속 프로필·작성 화면 수정 후 관련 25건을 재실행했다(중복 포함). jsdom의 canvas 미구현 알림은 있었지만 테스트는 통과했다. 린트, API 타입 확인과 빌드도 통과했다.

인앱 브라우저에서 320 CSS px의 첫 화면·공고 검색, 390 CSS px의 내 정보·경험 확인을 확인했다. 320px에서 세로 스크롤바와 body 최소 폭이 겹쳐 생긴 가로 넘침을 수정했고 해당 화면의 문서 폭과 스크롤 폭이 일치했다. 실제 모바일 기기, 브라우저 200% 확대, 모든 서버 성공 화면과 스크린리더 검증을 대신하지 않는다.

## 저장·신고·운영 화면 후속 정리

회원 저장의 확인·취소 조작, 공고 오류 신고, 음성 전사 확인, 운영자의 공고 원문 비교와 조건 편집을 각각 읽기와 조작 단위로 정리했다. 서버가 제공한 안내문의 내용과 버전, 데이터 전송 및 저장 조건은 유지했다. 운영 화면 코드를 별도로 불러오도록 해 초기 번들을 줄였으며 운영 화면에 진입하는 동안 로딩 상태를 표시한다.

저장·안내·신고·전사 관련 테스트 39건과 운영·공고 관련 테스트 35건, 코드 분리 후 앱·접근성·운영 관련 테스트 47건이 통과했다(각 실행은 일부 중복). 린트와 빌드도 통과했으며 초기 JavaScript 번들은 약 500.13kB에서 446.98kB로 줄었다(압축 전 빌드 출력 기준). 운영 진입 화면은 인앱 브라우저의 320 CSS px에서 가로 넘침 없이 표시됐다. 서버 인증 후의 운영 성공 상태는 실제 브라우저에서 확인하지 않았다.

대표 텍스트 색상 조합은 계산상 6.54:1 이상이지만 모든 화면과 상태의 실제 대비를 측정한 결과는 아니다. 인앱 브라우저에서 확대 단축키는 뷰포트나 배율을 바꾸지 않아 실제 200% 확대 확인은 여전히 남아 있다.

## 좁은 화면 여백과 상태 안내 확인

320 CSS px에서 음성 입력 안내, 작성 연습, 공고 주소 오류 및 첫 화면 전환 영역을 확인했다. 작은 화면의 본문·패널·안내문 좌우 여백을 줄여 읽을 폭을 확보하고, 미리보기 배너와 도구막의 정렬을 맞췄다. 위 화면의 문서 스크롤 폭은 표시 폭과 같았다. 이는 실제 기기나 200% 브라우저 확대 검증이 아니다.

로그인 확인 상태를 알리는 영역에서 이동 링크를 분리하고 오류 입력과 요약의 시각적 표시를 보완했다. 관련 계정·공통 UI·접근성·지역 및 운영 테스트 66건과 화면 여백 변경 후 앱·접근성·음성·작성·공고 상세 테스트 64건이 통과했다(중복 포함). 린트와 빌드도 통과했다.

## 오류 복귀와 정상 응답 접근성 확인

잘못된 체험·신청 준비·저장 주소에서 제목과 시작 화면/공개 공고 복귀 경로를 제공하도록 정리했다. 유효하지 않은 주소에서는 기존처럼 서버 요청을 시작하지 않는다. 공개 공고 상세의 안내는 공개 탐색에서 할 수 있는 일과 체험 화면에 구현된 일을 구분하고 실제 체험 시작은 준비 중이라고 표시한다.

잘못된 주소 복귀, 저장·신청 준비 및 접근성 관련 테스트 80건이 통과했다. 공고 상세의 정상 응답 및 펼친 신고 양식과 로그인 확인 후 저장 대기 링크를 axe 검사에 추가했고, 공고 상세·접근성 테스트 39건과 린트·빌드가 통과했다. 응답은 테스트용 대역이며 실제 서버 연동 검증이나 화면 색·기기 접근성 검증은 아니다. 관련 시험에서 jsdom canvas 미구현 알림은 있었으나 테스트는 통과했다.

## 사용자 문구와 저장본 편집 정리

지원서 승인 상태와 임시 초안의 유지 범위, 음성 요청 재확인 안내를 쉬운 문장으로 다듬었다. 사용자가 승인한 본문과 회원 저장을 구분하고, 같은 녹음과 요청 번호를 사용하는 조건 및 새 녹음 시 대기 참조를 지우는 사실은 유지했다. 저장본 편집 화면은 반영·재승인·저장·복사 조작을 한 묶음으로 정리했다.

관련 지원서·음성·대화 테스트 21건, 후속 저장본 편집·지원서·음성·앱 테스트 48건과 린트·빌드가 통과했다(일부 중복). jsdom의 canvas 미구현 알림은 있었으나 테스트는 통과했다. 실제 회원 서버와 기기에서의 저장·복사·음성 이용 검증은 별도다.
