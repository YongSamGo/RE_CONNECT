# 공통 접근성 자동 검증 — #80 / W11-01.c

기준일: 2026-10-17. 기존 공통 UI·메모리 구현 위에 자동 회귀 검사만 보강했다. 제품 화면이나 데이터 처리·동의·인증 동작은 바꾸지 않았다. 선행 #13/#19와 실제 기기 검증이 남아 있어 #80 전체 완료가 아니다.

## 재현

`frontend/`에서 `npm test` 또는 `npx vitest run src/accessibility.test.tsx`를 실행한다. 기존 CI의 `npm test`에 자동 포함된다. `axe-core@4.14.0`은 개발 의존성에 고정했으며 제품 엔트리에서 import하지 않는다. 브라우저 번들에는 포함하지 않는다.

## 범위

- 초기 화면 8개: 시작, 안내, 공개 검색, 유효하지 않은 공고 상세, 내 정보, 회원 저장 자료, 미인증 운영자, 404.
- 체험 내 동적 상태: 경험 입력, 빈 프로필 오류 요약·포커스, 자기소개/지원동기 입력 후 문장 확인 상태.
- 비동기 실패: 공개 검색 요청 오류·결과 영역 포커스·재시도 버튼 유지.

WCAG 2.0/2.1 A·AA 태그의 axe 규칙 중 DOM에서 판단 가능한 레이블·ARIA·의미 구조 등을 실행한다. 적용되는 통과 규칙이 실제 존재하는지도 확인한다. 테스트는 검사 대상 앱 전체를 스캔하며 실패 시 규칙 ID와 DOM 대상을 보고한다. 테스트용 네트워크 실패는 시험 코드에서만 주입하고 실행 앱은 바꾸지 않는다.

## 자동 검사로 판단하지 않는 항목

- jsdom에는 실제 렌더러가 없으므로 색 대비 규칙을 비활성화한다. Canvas context는 지원하지 않는 것으로 명시해 axe의 기능 감지 오류 메시지를 방지하며 검사 결과는 대체하지 않는다.
- 앱 하위 DOM만 검사한다. 호스트 문서의 lang/title·실제 문서 전체의 landmark 구성은 별도 확인한다.
- 결과의 위반 0건은 WCAG 적합성·스크린리더 사용성 통과를 뜻하지 않는다. 자동 판정 불가능/incomplete 항목, 실제 탭 순서·음성 출력·확대·200%·대비·레이아웃·44px 표적은 별도 확인한다.
- 로그인/MFA 성공·실제 API 결과·장치 권한/녹음 중·실제 TTS·운영 권한별 화면은 전체 통합 후 추가한다. 미인증 화면 검사로 이 상태들을 검증한 것으로 처리하지 않는다.
