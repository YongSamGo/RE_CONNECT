# 프론트 실행 준비서

2026-10-29. [완성 계획](08_Frontend_Completion_Plan.md)의 실행에 필요한 파일과 확인 순서를 정리한다. 스타일 판단은 [보존 기준](../frontend/DESIGN_BASELINE.md)을 따른다.

## 1. 지금 준비한 것

- 루트와 프론트 작업 지침에서 계획과 스타일 기준을 읽도록 연결한다.
- 기존 토큰과 컴포넌트의 재사용 위치를 정했다.
- 현재 브라우저 화면과 수정 전 소스 사본을 로컬에 기록한다. 승인된 디자인과 현재 결함을 구분한다.
- 제품 코드의 가운데 점 사용을 찾는 정적 검사 명령을 준비한다.
- 실제 서버가 필요한 작업과 브라우저에서 먼저 할 수 있는 작업을 구분했다.

이 단계에서는 제품 화면이나 AI 기능을 새로 구현하지 않는다. 각 단계에 필요한 관련 검사와 브라우저 확인은 실제 구현할 때 수행한다.

## 4. 의존성 때문에 멈추지 않도록 진행할 순서

1. 공통 치수와 이동을 정리하며 서버와 게시 안내, 로컬 모델 상태를 확인한다.
2. 프로필 편집과 공고 목록을 실제 라우트에 연결한다. 실제 서버가 없으면 화면 배치를 개발 자료로 확인하고 성공 왕복은 미확인으로 남긴다.
3. 지원서 생성 계약과 서버 문장 생성 기능을 구현한 뒤 작성 UI에 연결한다. 고정 문구를 AI 결과로 표시하지 않는다.
4. 인증과 저장을 연결하면서 내 자료와 계정 화면을 실제 자료로 전환한다.
5. 외부 조건이 막힌 경우 독립적인 화면 정리는 계속한다. 같은 실패를 반복하거나 가짜 완료로 우회하지 않는다.
6. 마지막에 현재 구현과 맞지 않는 기존 검사 기대값을 검토하고, 직접 관련 검사와 실제 브라우저 흐름을 확인한다.

운영 안내의 실제 내용과 인증 제공자 설정처럼 코드로 결정할 수 없는 조건만 별도로 기록한다. 새로운 환경을 무리하게 재구축하거나 기존 서비스를 임의로 종료하지 않는다.

## 5. 화면 비교 환경

| 범위 | 필수 확인 |
| --- | --- |
| 기본 데스크톱 | 1280×650 CSS px. 현재 제목과 핵심 작업, 주 행동이 첫 화면에 보이는지 확인 |
| 넓은 화면 | 1440×800, 1920×1080. 박스를 과도하게 늘리지 않는지 확인 |
| 모바일 | 320px과 390px 폭. 자연스러운 세로 배치와 가로 넘침 확인 |
| 글씨 확대 | 큰 글씨 보기와 브라우저 200% 확대를 각각 확인 |
| 내용 상태 | 정상, 빈 자료, 처리 중, 오류, 긴 내용 |
| 입력 방식 | 키보드, 음성 실패 후 글 입력, 확인 창 열기와 닫기 |

준비 때 얻은 1280×720 캡처만으로 위 검수를 완료 처리하지 않는다. 도구가 목표 뷰포트를 설정할 수 없으면 실제 측정 크기를 기록하고 지원하는 방법으로 보완한다.

## 6. 검사 명령과 실행 범위

프론트 폴더에서 실행한다.

- npm run ui:copy: 가운데 점을 포함한 소스 문자열을 찾는다. 오류 위치를 검토하고 자체 문구만 수정한다.
- npm run ui:copy -- --report: 현재 위반 후보만 보고한다. 준비 단계에서 기존 상태를 기록할 때 사용한다.
- npm run typecheck: 타입을 확인한다.
- npm run lint -- <변경 파일>: 변경한 코드에 관련된 정적 검사를 우선한다. 실제 CLI 인자 지원을 확인한다.
- npm test -- <관련 테스트 파일>: 해당 기능의 정상과 오류 동작을 확인한다.
- npm run api:check: API 계약을 다룬 경우에 확인한다.
- npm run build: 배포 번들 확인이 필요한 시점에 실행한다.

문서만 바꿀 때 제품 테스트를 실행하지 않는다. 가운데 점 정적 검사는 스타일 감사이며 동작 시험이나 시각 검수를 대신하지 않는다. 전체 테스트와 브라우저 E2E는 명시적 요청 또는 릴리스 검증 단계에서 수행한다. 기존 browser-tests를 새 기대값 검토 없이 반복 실행하지 않는다.

## 7. 실행 때 확인할 기존 문제

| 항목 | 준비 중 관찰 또는 코드 근거 | 처리 시점 |
| --- | --- | --- |
| 홈 높이 | 1280×720에서 패널 하단 약 749px. 개발 메뉴에 버튼 일부가 가려짐 | 1단계 |
| 이전 화면 | 상단 뒤로가기가 첫 화면으로 연결됨 | 1단계 |
| 프로필 편집 | 프로필 주소가 추천으로 리다이렉트됨 | 2단계 |
| 추천 목록 | 예시 목록에서 안쪽과 바깥쪽 스크롤이 함께 보임 | 3단계 |
| 공고 검색 결과 | 전체 보기 외 조건 검색은 여전히 아래 결과 추가 방식이 남아 있음 | 3단계 |
| 지원서 진입 | 예시 흐름에서 이전 스크롤 위치가 남아 지원서 하단부터 보임 | 4단계 |
| 지원서 정보량 | 신청자 정보와 참고 프로필, 반복 안내가 초안보다 먼저 넓게 표시됨 | 4단계 |
| AI 문장 | 사실 ID 선택 후 서버 조합만 제공하고 지원동기는 빈 값 | 4단계 |
| 저장과 계정 | 실제 관리 코드와 현재 예시 화면이 분리되어 있음 | 5~6단계 |
| 과거 브라우저 검사 | 현재 없는 제목과 이동 링크를 기대함 | 해당 구현 단계 |

이 표는 작업 준비 중 확인한 기능과 배치 항목이다. 보안 취약점 판정이나 전체 감사 결과를 뜻하지 않는다.

## 8. 실행 시작과 인계

다음 실행은 이 문서를 읽은 뒤 1단계부터 시작한다. 먼저 중복된 CSS 선언과 공통 크기를 정리하고 실제 화면 비교를 수행한다. 사용자에게 기존 취향이나 이미 정한 범위를 다시 묻지 않는다.

단계가 끝날 때마다 완성 계획의 실행 현황에 변경 내용과 검사 증거를 기록한다. 한 단계가 덜 끝났으면 다음 단계에서 완료로 가정하지 않는다. 외부 조건 때문에 확인하지 못한 부분은 별도 조건으로 유지한다.
