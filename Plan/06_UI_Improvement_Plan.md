# 다시잇다 UI 개선 계획

작성일: 2026-10-27
상태: 조사 기반 제안. 디자인 시안과 사용자 검증 전이다.

## 1. 목적과 범위

시니어와 노인을 포함한 다양한 이용자가 서비스의 목적을 이해하고, 다음 행동을 예측하며, 자신의 속도로 경험을 정리하거나 공고를 찾을 수 있도록 UI를 개선한다. 첫 화면에 서비스 소개와 짧은 소개 영상을 배치하고, 두 영역을 Apple 사이트에서 영감을 받은 부드러운 블러로 연결한다.

이번 계획은 첫 화면을 우선 대상으로 하되, 용어와 조작 방식의 일관성은 이후 대화·공고·신청 준비 화면까지 이어간다. UI 개편은 기존 동의·개인정보 처리·저장·공식 신청 경계를 변경하는 작업이 아니다.

## 2. 현재 상태와 개선 과제

- 현재 [시작 화면](../frontend/src/App.tsx)은 서비스 목적, `내 경험 이야기하기`와 `공고부터 살펴보기`, 접힌 경험 정리 예시를 제공한다. 공식 신청처에서 직접 신청한다는 안내도 있다.
- 시작 화면에는 서비스 소개 영상이 없고, 처음 접한 이용자에게 전체 이용 순서를 설명하는 정보가 부족하다.
- 현재 경험 입력은 가상 정보를 사용하는 미리보기이며, 실제 AI 처리·서버 보관·회원 저장이 연결되지 않았다는 안내가 있다. 소개 문구와 영상에는 실제 제공 상태를 반영한다.
- [기존 화면 개선 기록](../frontend/UI_QUALITY.md)은 본문 18px, 주요 버튼 최소 높이 56px, 초록 계열의 색상과 절제된 정보량을 기준으로 삼는다. 새 디자인은 이 기준을 출발점으로 삼고 실제 화면에서 다시 검증한다.
- [접근성 검증 기록](../frontend/ACCESSIBILITY.md)에 따르면 자동 검사만으로 실제 대비, 확대, 스크린리더 또는 사용자 경험을 판정할 수 없다.

## 3. 디자인 원칙

1. **목적을 먼저 설명한다.** 서비스가 무엇을 돕는지 한 문장으로 말하고, 사용자가 할 수 있는 행동을 이어서 보여 준다.
2. **다음 행동을 예측할 수 있게 한다.** 버튼에 결과를 나타내는 이름을 쓰고 화면이 바뀌어도 같은 용어를 유지한다.
3. **한 번에 판단할 내용을 줄인다.** 주 행동은 `내 경험 이야기하기`, 보조 행동은 `공고부터 살펴보기`로 구분하고 나머지 설명은 아래에 둔다.
4. **영상은 선택 사항이다.** 영상을 보지 않아도 서비스 목적과 시작 방법을 알 수 있게 한다.
5. **시니어를 하나의 집단으로 가정하지 않는다.** 시력, 조작 능력, 디지털 경험이 다른 이용자와 함께 확인한다.
6. **장식보다 읽기와 조작을 우선한다.** 블러와 움직임은 배경에 한정하고 글자·버튼·영상 조작부는 선명하게 유지한다.

## 4. 첫 화면 구성안

### 권장안: 차분한 소개형 + 단계 안내

```text
[다시잇다]                          [공고 살펴보기] [내 정보]

지금까지의 경험이
새로운 기회로 이어지도록

다시잇다는 해온 일을 정리하고
일자리와 봉사 기회를 찾도록 돕습니다.

[내 경험 이야기하기]    공고부터 살펴보기
미리보기에서는 가상의 경험을 입력해 주세요.

             배경이 부드럽게 이어지는 전환

다시잇다, 이렇게 이용해요
[              소개 영상 썸네일              ]
[▶ 소개 영상 보기]               영상 내용 글로 보기

1. 경험을 이야기해요
2. 정리한 내용을 확인해요
3. 기회를 살펴보고 신청을 준비해요

실제 신청은 공고의 공식 신청처에서 직접 진행해요.
```

문구와 단계는 시안용이다. 실제 서비스가 지원하는 상태를 확인한 뒤 확정하며, 미구현 기능을 현재 제공 중인 것처럼 표현하지 않는다. 기존 경험 정리 예시는 이용 흐름을 방해하지 않는 위치에서 접힌 상태로 제공할지 시안 평가에서 결정한다. 영상 유무와 관계없이 두 진입 경로가 찾기 쉬워야 한다.

### 비교할 대안

| 안 | 구성 | 장점 | 확인할 점 |
| --- | --- | --- | --- |
| 차분한 소개형 | 간단한 소개와 두 행동, 아래에 영상 | 기존 흐름을 유지하면서 목적을 빠르게 전달 | 서비스 전체 과정에 대한 이해가 충분한지 |
| 이야기 중심형 | 사람의 경험을 보여 주는 사진 또는 일러스트와 영상 | 브랜드 인상과 정서적 공감 | 이미지가 읽기를 방해하거나 이용자를 정형화하지 않는지 |
| 단계 안내형 | 이용 순서 3단계와 행동, 아래에 영상 | 다음 단계와 전체 흐름 예측이 쉬움 | 첫 화면의 정보량과 미구현 기능 표현 |

우선 권장안으로 시안을 만들고, 필요하면 다른 안과 비교한다. 사진 또는 영상 소재가 미정인 경우 임시 이미지를 실제 이용자나 실제 서비스 화면으로 오인하게 표현하지 않는다.

## 5. 영상과 블러 연출

### 소개 영상

- 목표 길이는 30~60초로 두고 사용자 검증 후 조정한다.
- 내용은 서비스 목적, 경험 이야기와 내용 확인, 공고 탐색, 공식 신청처 이동 순으로 구성한다. 실제 기능 상태에 따라 대본을 수정한다.
- 자동 재생하지 않고 사용자가 재생한다. 재생·일시정지·음량 등 기본 조작을 제공한다.
- 한국어 자막과 `영상 내용 글로 보기`를 제공한다. 영상의 중요한 시각 정보도 글 대안에 포함한다.
- 영상이 아직 없을 때는 완성된 것처럼 보이는 재생 버튼을 노출하지 않는다. 영상 준비와 게시 시점은 별도로 정한다.
- 영상 소재의 제작·사용 권한, 게시 위치, 외부 플레이어 사용 시 개인정보 처리 여부를 제작 전에 확인한다.

### 영역 연결

- 소개와 영상 사이에 별도의 장식용 배경 레이어를 두고, 배경색·이미지와 부드러운 그라데이션 또는 블러를 연결한다.
- 제목, 본문, 버튼, 포커스 표시와 영상 콘텐츠에는 블러를 적용하지 않는다. 텍스트 배경이 변해도 대비가 유지되도록 표면색을 확보한다.
- 스크롤 위치를 강제로 고정하거나 가로채지 않는다. 화면이 움직여야 내용이 나타나는 구조를 피한다.
- `prefers-reduced-motion` 설정을 존중해 움직임을 제거하거나 줄인다. 저사양 기기와 블러 미지원 환경에서는 정적 그라데이션으로 대체한다.
- 모바일에서 성능과 배터리 사용을 고려해 효과 범위를 제한하고, 실제 기기에서 끊김과 가독성을 확인한다.

## 6. 접근성 및 사용성 기준

| 항목 | 계획 기준 및 확인 방법 |
| --- | --- |
| 글자 | 기존 본문 18px을 출발점으로 삼고 200% 확대 시 내용과 조작이 유지되는지 확인한다. 글자 크기는 이용자 관찰을 통해 조정한다. |
| 대비 | 일반 텍스트 4.5:1 이상, 큰 텍스트 3:1 이상을 기준으로 실제 배경과 모든 상태를 측정한다. 장식 효과가 대비를 떨어뜨리지 않게 한다. |
| 조작 영역 | 주요 버튼은 기존 최소 높이 56px을 유지하고 주요 조작 영역은 44×44 CSS px 이상을 목표로 한다. 인접 조작 간격도 확보한다. |
| 키보드 | 모든 링크·버튼·영상 조작에 접근하고 순서와 포커스가 명확한지 확인한다. |
| 구조 | 페이지에 적절한 제목 순서와 랜드마크를 사용하고, 영상과 조작부에 이해할 수 있는 이름을 제공한다. |
| 예측 가능성 | 같은 작업에 같은 용어를 사용하고, 버튼을 누른 후 열리는 화면과 처리 결과를 명확히 안내한다. |
| 상태 안내 | 미리보기의 가상 입력, 저장 여부, 실제 신청처 이동을 해당 행동 전에 알린다. |
| 움직임 | 이용자의 움직임 축소 설정을 따르고 정적 상태에서도 모든 정보와 기능을 제공한다. |

기준 근거는 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)와 [W3C 고령 이용자 접근성 자료](https://www.w3.org/WAI/older-users/)를 따른다. 44px은 이 계획의 목표이며 WCAG 2.2 AA의 일반적인 최소 타깃 기준은 예외 조건을 포함해 24×24 CSS px이다. 위 수치만 충족해도 접근성 전체가 보장되는 것은 아니다.

## 7. 참고 자료

- [Apple 한국 사이트](https://www.apple.com/kr/): 넓은 여백, 짧은 메시지와 섹션의 시각적 연결. 서비스에 맞게 절제해 적용한다.
- [서울시50플러스 일자리몽땅](https://www.50plus.or.kr/): 국내 중장년 대상 일자리·교육 정보의 용어와 분류.
- [NHS](https://www.nhs.uk/): 주제별 제목과 짧은 설명으로 목적지를 선택하는 방식.
- [GOV.UK Design System](https://design-system.service.gov.uk/): 일관된 컴포넌트, 폼, 오류와 단계 안내.
- [W3C 미디어 접근성](https://www.w3.org/WAI/media/av/): 영상 자막과 텍스트 대안.
- 로컬 `frontend-design` 스킬: 서비스의 실제 내용에 맞는 색·서체·레이아웃을 선택하고 불필요한 움직임을 줄이는 디자인 절차.

## 8. 실행 순서와 완료 기준

1. **콘텐츠 확정:** 현재 동작과 운영 예정 기능을 대조해 소개 문구, 두 행동의 이름, 영상 대본과 안내를 정한다.
2. **시안 제작:** 권장안의 데스크톱·모바일 화면과 정적 블러 대체안을 만든다. 기존 색·본문·버튼 기준을 확인하고 변경 이유를 기록한다.
3. **영상 제작:** 실제 제공 범위에 맞는 영상, 한국어 자막, 글 대안을 준비한다. 게시·권한과 개인정보 처리 여부를 확인한다.
4. **구현:** 첫 화면의 의미 구조와 반응형 배치, 선택 재생, 장식 배경, 움직임 축소 및 대체 표현을 적용한다. 기존 경로와 미리보기 안내를 유지한다.
5. **직접 관련 검증:** 변경된 첫 화면의 링크·안내·영상 조작과 접근성에 관련된 테스트를 실행한다. 실제 브라우저에서 확대, 키보드, 대비, 모바일 화면과 움직임 축소를 확인한다. 실행 범위와 확인하지 못한 부분을 기록한다.
6. **사용자 검증:** 시니어 이용자에게 서비스 목적 설명, 두 진입 경로 찾기, 영상 재생·정지, 미리보기와 공식 신청 경계 이해를 요청하고 어려움을 관찰한다. 연령만이 아니라 기기·디지털 경험·접근성 요구가 다른 참여자를 포함한다.
7. **개선 및 인계:** 관찰 결과를 반영하고 미해결 사항과 기능별 실제 연결 상태를 기록한다. 자동 검사 통과와 실제 이용 가능성을 구분해 보고한다.

완료는 시안이나 자동 테스트의 통과만으로 판단하지 않는다. 실제 서비스 상태와 안내가 일치하고, 위 핵심 과업을 대상 이용자와 보조 기술 환경에서 확인했는지 함께 판단한다.
