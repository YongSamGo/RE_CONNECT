# 다시잇다 프론트 전면 개편 계획\n\n작성일: 2026-10-28\n상태: 다음 프론트 작업 세션의 실행 기준\n\n## 목표\n\n주 이용자인 시니어·고령자가 필요한 내용을 쉽게 읽고 다음 행동을 고를 수 있도록 프론트 화면을 재구성한다. 노트북·데스크톱의 기본 화면에서는 그 화면의 핵심 정보와 주요 행동이 첫 뷰포트 안에 들어오게 한다. 반복 설명과 불필요한 페이지 이동을 줄여 전체 화면 수도 관리한다.\n\n사용자가 직접 끝까지 검수한 UX01 시작, UX02 AI 처리 안내, UX07 공고 상세의 현재 구성은 디자인 기준으로 보존한다. 화면 전체를 전면 개편하더라도 이 세 화면의 정보 구조와 검수된 표현은 별도 동의 없이 바꾸지 않는다. 공통 컴포넌트·전역 스타일 변경이 세 화면에 영향을 주면 시각 차이를 비교하고 기존 상태를 유지한다.\n\n## 범위와 기준\n\n- 데스크톱·랩탑 우선 기준 뷰포트: 1280×650 CSS px. 보조 확인 크기: 1440×800 및 1920×1080 CSS px.\n- 본문은 기존 18px 기준을 출발점으로 하고, 주요 조작은 기존 56px 높이와 44px 이상의 조작 영역을 유지한다. 화면 맞춤을 이유로 읽기와 조작 크기를 낮추지 않는다.\n- 첫 뷰포트에는 해당 과업의 제목, 판단에 필요한 핵심 정보, 주요 행동을 둔다. 긴 원문·긴 작성 내용과 확대 상태는 모든 내용을 읽고 조작할 수 있도록 세로 스크롤을 허용한다.\n- 카드 내부 스크롤이나 잘라낸 내용으로 바깥 스크롤이 없는 것처럼 만들지 않는다. 공간이 모자라면 반복 문구, 장식, 중복 패널, 한 번 더 확인하는 이동부터 줄인다.\n- 현재 모바일 지원과 접근성 동작을 깨뜨리지 않는다. 320 CSS px 재배치와 확대 시 내용·기능 유지도 계속 확인한다.\n- 서비스의 동의, 개인정보 처리, AI 처리, 저장·삭제, 프로필 확정, 공고 자격 판정, 공식 신청 경계는 UX/API 명세를 따른다. 화면 통합은 별도 확인이나 동의를 생략하는 근거가 아니다.\n\n## 화면 통합 방향\n\n목록 번호보다 실제 이용 경로와 현재 구현을 기준으로 화면을 정리한다. 기존 URL이나 진입 경로는 동작 호환이 필요할 수 있으므로 라우트 삭제보다 같은 목적 화면으로 연결하는 방안을 먼저 검토한다.\n\n| 현재 화면·기능 | 목표 구성 |\n|---|---|\n| UX01 시작, UX02 처리 안내, UX07 공고 상세 | 사용자 검수 상태를 보존한다. 공통 스타일 변경 영향도 확인한다. |\n| 대화·음성 입력·전사 확인 | 대화 화면에서 입력 방식을 전환하고 전사 확인을 같은 과업 흐름 안에 둔다. 질문 하나, 답변 입력, 보내기가 중심이다. |\n| 대화 결과·프로필 확인·수정 | **내 경험 확인** 화면으로 묶는다. 경험 요약, 필요한 수정, 희망 활동 조건, 확정 행동을 한 과업에 연결한다. |\n| 추천 공고·공개 공고 탐색 | 공고 목록의 탐색·필터·항목 구조를 공유한다. 추천 근거는 필요한 만큼만 표시하고 공개 목록과 추천의 출처·조건을 혼동하지 않게 한다. |\n| 공고 상세·지원 조건 대조 | 공고 상세에서 주요 조건과 사용자 프로필 대조 결과를 함께 확인한다. 원문과 자격 근거를 보존한다. |\n| 참여 준비·지원서 작성·공식 서류 안내 | **신청 준비** 화면 안에서 준비 항목과 지원서 내용을 다룬다. 공식 신청처 이동과 접수 완료를 구분한다. |\n| 자료 선택·저장 대기·저장 결과 | 저장을 시작한 화면에서 선택·동의·진행·성공/실패 상태를 처리한다. 인증 복귀 등 필요한 기술 경로는 유지한다. |\n| 내 정보·내 프로필·저장 자료 | **내 자료**를 주 메뉴로 묶고, 프로필·지원서·계정 관리를 찾기 쉬운 하위 화면으로 둔다. 동의 철회·삭제·탈퇴의 구분과 확인을 유지한다. |\n\n목표는 경로별로 별도 페이지를 반복 방문하는 일을 줄이는 것이다. 통합 후의 정확한 사용자 화면 수는 현재 구현과 중복 진입점을 조사한 다음 확정하고, 숨은 화면이나 새 단계를 만들지 않는다.\n\n## 화면별 정보 예산\n\n- **대화:** 현재 질문 하나, 답변 입력, 음성 전환, 보내기. 이전 응답은 현재 질문을 방해하지 않도록 접근 가능하게 둔다.\n- **내 경험 확인:** 경험 요약, 희망 활동 조건, 수정 진입, 확정. 추천에 필요한 필수 입력과 선택 입력을 분명히 구분한다.\n- **공고 목록:** 핵심 필터와 간결한 공고 항목. 첫 화면에 적은 수의 결과를 읽기 좋게 배치하고 나머지는 명확한 페이지 이동으로 제공한다.\n- **공고 상세:** 모집 상태, 기관·장소, 활동, 일정, 필수 조건, 신청 방법과 다음 행동. 판단에 필요한 사실은 접거나 삭제하지 않는다.\n- **신청 준비:** 현재 준비 상태, 공식 서류·절차, 지원서 작성과 검토 행동. 서로 다른 상태와 일부 완료 여부를 혼동하지 않게 한다.\n- **내 자료:** 프로필 상태와 저장 자료 목록. 계정의 민감한 변경은 명확히 분리한다.\n\n## 문구 원칙\n\n각 문구는 사용자의 이해, 판단, 오류 복구 또는 동의에 필요할 때만 남긴다.\n\n- 제목만으로 뜻이 분명한 화면에서는 상단 설명을 반복하지 않는다.\n- 도움말은 기능 설명을 되풀이하지 않는다. 사용자가 막힐 지점과 해결 방법만 짧게 쓴다.\n- 상태 문구는 그 시점의 사실을 말한다. 예: `이 내용으로 확정`, `계정에 저장하지 않았습니다`.\n- 오류에는 무엇이 안 됐는지와 다시 할 방법을 함께 표시한다.\n- 동의·개인정보·AI 처리·공식 신청·저장·삭제 관련 안내는 필요한 행동 직전에 정확히 제공한다. 짧게 만들더라도 의미와 법적·보안상 조건을 약화하지 않는다.\n- 개발자 용어, 내부 상태 설명, 기능을 과장하는 소개 문구, 장식용 라벨, 모든 화면에서 반복되는 이용 순서 안내를 제거한다.\n\n## 시각 체계\n\n기존 S-Core Dream과 청색 중심 팔레트를 출발점으로 한다. 화면마다 패널을 중첩하는 대신 하나의 주 작업 영역과 명확한 제목·본문·보조 정보 위계를 사용한다. 관련 정보는 간격과 구분선으로 묶고, 같은 모양의 카드가 연속되는 구성을 줄인다. 화면마다 주 행동은 하나를 우선 강조하며, 보조 행동은 눈에 띄되 시각적으로 경쟁하지 않게 한다. 뒤로가기와 다음 행동의 위치, 버튼 이름, 상태 표현은 화면 전반에서 일관되게 한다.\n\n새 장식 효과나 시각 테마를 더하기보다 읽기 폭, 정렬, 간격, 대비, 조작 상태를 다듬는다. 색상만으로 상태를 전달하지 않고 키보드 초점과 확대 동작을 유지한다.\n\n## 실행 순서\n\n1. 저장소 지침, UX 흐름, 서비스 화면 목록, 현재 프론트 코드와 기존 작업 내용을 살펴본다. 작업 전 변경 파일을 구분하고 사용자의 미커밋 변경을 보존한다.\n2. UX01·UX02·UX07을 변경 금지 기준 화면으로 기록하고, 개발용 화면 번호와 UX 화면 ID의 대응을 확인한다.\n3. 현재 라우트와 실제 사용자 과업을 표로 대조한다. 합칠 화면, 보존할 진입 URL, 상태·권한·동의 경계를 먼저 결정한다.\n4. 대화, 내 경험 확인, 공고 상세, 신청 준비의 대표 데스크톱 시안을 만든다. 1280×650에서 읽기 크기를 유지한 채 첫 뷰포트에 핵심 정보와 행동이 들어가는지 확인한다.\n5. 공통 틀·타이포그래피·간격·행동 배치를 정리하고 화면 통합을 적용한다. 검수된 세 화면의 변경을 막는 회귀 비교도 수행한다.\n6. 코드 수정 뒤 변경 범위에 직접 관련된 검사만 실행한다. 별도 요청 없이 전체 테스트나 E2E를 돌리지 않는다.\n7. 데스크톱·노트북 실제 뷰포트에서 빈 상태, 정상 상태, 긴 콘텐츠, 오류 상태를 확인하고, 모바일 폭과 확대·키보드 사용도 확인한다. 실사용자 검증은 수행 여부와 결과를 코드 검사와 구분해 기록한다.\n8. 문서와 화면 목록을 구현 결과에 맞게 갱신하고, 바뀐 화면·보존한 보안 경계·검사 범위·미검증 환경을 다음 인계에 남긴다.\n\n## 완료 기준\n\n- UX01·UX02·UX07의 검수된 정보 구조와 표현이 보존되고, 의도치 않은 시각 회귀가 없다.\n- 1280×650 CSS px에서 대표 과업 화면의 제목, 핵심 판단 정보, 주 행동을 읽고 사용할 수 있다. 긴 자료와 확대 상태는 내용 손실 없이 탐색할 수 있다.\n- 반복 화면 이동과 중복 설명이 실제로 줄고 사용자 화면 목록 및 링크가 그 결과와 일치한다.\n- 주요 글자·조작 영역의 크기, 대비, 초점 표시, 좁은 화면 재배치가 유지된다.\n- 동의·개인정보·AI 처리·저장·삭제·확정·신청 상태가 화면 통합으로 약화되지 않는다.\n- 직접 관련 검사 결과와 실제 브라우저·기기·이용자 검증의 범위를 구분해 보고한다.\n\n## 근거 문서\n\n- [UX 흐름·화면 명세](01_UX_Flow.md)\n- [기존 UI 개선 계획](06_UI_Improvement_Plan.md)\n- [프론트 서비스 화면 목록](../frontend/SERVICE_SCREENS.md)\n- [프론트 개발 지침](../frontend/README.md)\n- [W3C 고령 이용자 접근성](https://www.w3.org/WAI/older-users/)\n- [WCAG 2.2 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)\n
